## 실행

Node 24를 사용합니다. Windows PowerShell에서는 `npm.cmd`를 사용하면 실행 정책의 영향을 피할 수 있습니다.

```sh
npm ci
npm run data:init
npm run dev
```

`data:init`은 최초 설치 전용입니다. 기존 업무·조직 파일을 덮어쓰지 않습니다. 이후에는 `npm run dev`만 실행합니다. 기존 업무 스키마 8·7·조직 스키마 2 및 업무6·조직1은 아래 해당 보존 이관이 필요하며 서버 시작 시 자동 변환하지 않습니다.

- 앱: http://127.0.0.1:5186
- API: http://127.0.0.1:5187/api
- 정적 실행: `npm run build` 후 `npm start` → http://127.0.0.1:5187
- 업무 JSON: `data/runtime/state.json` (스키마 10)
- 조직 JSON: `data/master/organizations.json` (스키마 2)
- 별도 시험 파일: `EKS_DATA_FILE` 환경변수. 실제 운영 파일로 시험하지 않습니다.

계정 전환은 MVP 검증용이며 사내 로그인 인증이 아닙니다. 탭별 세션 쿠키·sessionStorage 식별자를 사용하고 8시간 뒤 만료됩니다. 서버 재시작 후 계정을 다시 선택합니다. API·앱은 기본적으로 127.0.0.1에 바인딩하며 JSON·백업·서버 소스는 정적 경로로 제공하지 않습니다.

## 운영 규칙

| 역할 | 범위 |
| --- | --- |
| 학습자 | 본인 계획·학습·두 평가·수료증·인증서 |
| 팀 조직 관리자 | 자기 Lv1의 기준·계획 요청·결과·팀 공지·조직 필수 자격·세부 관리자 지정 |
| 세부 조직 관리자 | 실제 소속 조직 한 곳의 설명·담당 업무·필수 자격 설정, 직접 소속 인원의 대상자 Hold |
| 시스템 운영자 | 조직·사용자·역할·시스템 공지·진행 초기화, 명시적으로 선택한 Lv1의 관리자 기능 |

FT 역할과 주관식은 폐지했습니다. 박준호·오지훈은 학습자이며 복수 역할 계정에서는 FT만 제거했습니다. 시스템 운영자의 소속과 관리 대상 Lv1은 별개입니다. 조직·사용자의 같은 Lv1 내 이동만 지원하며 조직은 물리 삭제 대신 사용 중지합니다. 조직 파일 누락·손상은 시작을 중단하며 기본 조직으로 대체하지 않습니다.

- `객관식 · 지식 평가`: 개념·기준·원리의 이해를 단일 정답 객관식으로 확인합니다.
- `실기 · 상황 대응 평가`: 가상 상황과 대응 질문을 읽고 적절한 선택지를 고릅니다. 실제 작업을 관찰한 증거로 사용하지 않습니다.
- 각 유형의 합격 기준을 독립 적용합니다. 통과한 유형은 유지하고 미통과 유형만 새 회차로 응시합니다.
- 인증Set에 설정된 필수 평가 유형을 모두 통과하면 인증Set 수료, 모든 필수 인증Set 수료 시 자격 인증을 자동 발급합니다.
- 학습자료는 직접 작성·EDM Link·Confluence·일반 URL을 여러 개 등록합니다. URL은 HTTP(S)만 허용하며 외부 접근 권한 확인·본문 수집·파일 업로드는 하지 않습니다. 자료 열람은 학습 완료가 아닙니다.
- 새 계획 요청의 작성 기한은 실제 서버 요청일(KST)+28일입니다. 직접 수정한 날짜는 유지하고 빈 날짜는 거부합니다. 개인 계획의 목표 인증일·인증Set 일정과 구분합니다.
- 사용 중 기준의 수정은 새 버전입니다. 미참조 초안만 삭제하고 게시 버전은 운영 종료합니다. 기존 배정과 인증 근거는 유지합니다.
- 실제 수행 비교는 두 평가의 확정 회차와 별도 현장 근거를 비교하는 관리자 기능입니다. 관찰자는 역할이 아닌 기록 정보입니다.
- 인증기간은 발급 시 고정합니다. 기간제는 월말 보정 후 만료일 KST 하루 끝까지 유효합니다. 재인증 사전 알림은 시작일 기본7일 전에 유효기간별 한 번 생성하며 재시작 시 필요한 누락 알림만 보충합니다. 재인증은 별도 종합평가 완료 버튼으로 갱신합니다. PDF와 실제 종합평가 문항은 후속 범위입니다.

Photo팀 시험 기준은 15자격·75인증Set·지식 225문항·상황 대응 225문항입니다. 유형별 100%, 취득 후 36개월·재인증 시작 기본7일 전 1회 알림, 문항 끝 정답 공개는 **프로세스 검증용 데이터에만** 적용합니다. 실제 회사의 장비값·승인 기준을 대신하지 않습니다.

## 조직별 필수 자격 운영

1. 시스템 운영자가 조직을 만들고 사용자를 실제 소속에 지정합니다. Lv5 이후도 추가할 수 있으며 어느 노드에나 직속 소속을 지정할 수 있습니다. 이동은 같은 Lv1·같은 레벨로 제한합니다.
2. `인증 업무 관리 → 조직별 자격 설정`에서 자기 Lv1의 게시 자격과 **적용할 버전**을 선정합니다. 시스템 운영자는 관리할 Lv1을 먼저 선택합니다.
3. 조직을 선택해 설명·담당 업무·필수 자격을 저장합니다. 상위 조직 설정은 상속하지 않습니다. 미설정과 명시적 ‘필수 자격 없음’을 구분합니다.
4. `대상자·계획`에서 계획 요청을 보냅니다. 실제 소속과 당시 대상 자격을 보관하며 새로 추가한 필수 자격은 별도 요청합니다. 대상/계획 확정/유효 인증/현재 기준 제외 건수를 구분합니다.
5. 학습자는 요청받은 현재 필수 자격만 계획합니다. 현재 팀 적용 버전을 사용하며, 소속·자격·버전 변경으로 대상이 달라진 초안은 입력을 보존하고 재작성·삭제를 안내합니다.
6. 홈의 `이어서 진행` → `자격 상세`에서 자격 요약·인증Set별 목표와 일정·학습 범위·자료를 확인한 뒤 `평가하기`로 이동합니다. 여러 학습자료를 함께 펼칠 수 있고 인증Set별 펼침 상태를 화면 안에서 유지합니다. 자료 열람이나 학습 완료 입력을 평가 조건으로 사용하지 않습니다. 기존 답안·확정 배정은 계속 진행합니다.

같은 자격 계보의 **현재 유효한 인증**은 구버전도 충족으로 인정합니다. 개인 Hold·Revoke·기간 미정은 충족으로 세지 않습니다. 재인증은 현재 팀 적용 기준으로 진행하며 만료 폐기 후에는 새 요청부터 재취득합니다. 팀 목록의 자격을 필수 지정한 조직이 있으면 목록 제거를 차단합니다. 초안/타 Lv1 자격은 선정할 수 없습니다. 종료 인증Set은 신규 계획을 막지만 기존 설정·진행·인증 근거를 삭제하지 않습니다.

최초 이관에서는 팀 목록·필수 자격을 자동 선정하지 않습니다. Photo 시험 15종도 관리자가 검색·선정해야 합니다. 조직 정책과 변경 이력은 조직 JSON에 저장하므로 진행 초기화로 삭제되지 않습니다.

모든 페이지의 본문 마지막에 기본 접힘 상태의 `MVP 프로세스 검토`를 제공합니다. 펼치면 현재 단계·담당자·저장/확정의 의미·이후 경로와 **정적 AI 검수 항목(v10)**을 확인할 수 있습니다. 실시간 AI 호출, 실제 데이터 검수, 판단 저장 기능은 없습니다.

## 단일 재인증 알림·평가 순서와 업무 9 → 10 보존 이관

- `재인증 시작 N일 전 알림`은 기본7일, 0~365일이며 0은 당일입니다. 알림일은 KST의 `재인증 시작일 - N일`이고 유효기간 시작일보다 앞서지 않습니다. 기존 시작일 당일/만료 임박의 추가 알림은 중단합니다. 이미 해당 회차에 알렸으면 다시 보내지 않으며, 상태 변경·만료 폐기 사실 알림은 유지합니다.
- 인원/개인 Hold 동안 사전 알림을 중단합니다. 해제·서버 재시작 후에도 유효하고 미발송인 회차만 보충합니다. 발급 당시 만료일/재인증 시작일·최초 근거는 그대로입니다. 종전 `reminderDays`는 과거 정책으로 보존합니다.
- 같은 수강/인증Set 버전의 지식 통과가 실기 시작·저장·제출의 선행 조건입니다. 실기를 사용 등록하려면 지식 평가도 필요합니다. 기존 실기 초안과 확정 근거는 보존합니다.
- 응시는 `제출 → 답안 확인 → 최종 제출`이며 미응답은 팝업과 문항 이동으로 안내합니다. 답안 검토는20개씩, 최종 제출 뒤 수정 불가 안내는 실행 버튼 바로 위입니다. 마지막 문항의 다음 버튼은 안내만 하고 자동 제출하지 않습니다.
- 결과 배경은 로컬 Topography SVG(Hero Patterns, Steve Schoger, CC BY4.0)의 낮은 불투명도 패턴과 녹색/코랄색을 사용합니다. 결과 문구·아이콘·점수·다음 행동을 함께 제공합니다.
- 기본 Excel은v5이며 v3/v4 읽기를 유지합니다. 기존 기준의 누락 알림 설정은 원본, 신규는7일입니다. 기존 복수 알림을 새 정책으로 재해석하지 않습니다.

서버를 중지한 뒤 미리보기의 revision과 두 해시를 사용합니다. 최초 적용은 영구 백업 쌍을 만들고 업무만 원자적으로 교체하며 반복 적용은 무변경입니다.

```sh
npm run data:migrate-assessment-flow -- --dry-run
npm run data:migrate-assessment-flow -- --apply --expected-revision=N --expected-sha256=STATE_HASH --organization-sha256=ORG_HASH
npm run dev
```

백업은 `data/backups/state/before-assessment-flow-*.json`과 `data/backups/organizations/before-assessment-flow-*.json`입니다. 되돌릴 때는 서버를 중지하고 현재 파일을 별도 보관한 뒤 동일 접미사의 원본 백업 쌍과 스키마9 호환 코드를 복원합니다. 현행 코드에는 명시적 이관이 다시 필요합니다. 조직만 임의로 교체하지 않습니다. 실제 적용/검증 결과는 [handover.md](handover.md)를 따릅니다.

2026-10-22 적용 결과: 업무9 revision216→업무10 revision217, 조직2 revision3과 기존 응시10·수료5·인증1을 보존했습니다. 영구 백업·반복 이관 무변경·재시작 후15개 화면 조회에서 두 파일 해시 불변을 확인했습니다. 최종 서버110건·브라우저67건·빌드 통과, 실제 백업 경로와 검증 범위는 [handover.md](handover.md)에 기록했습니다.

## 이전 자격 상태·재인증과 업무 8 → 9 보존 이관 이력

자격의 구성요소 이름은 **인증Set**입니다. 기존 ID·`courseIds`·`/courses` URL은 유지하며 사용자 작성 내용과 과거 감사 원문은 치환하지 않습니다.

| 상태 영역 | Active/대상 | Hold | Revoke |
| --- | --- | --- | --- |
| 자격 기준 버전 | 신규 계획·재인증 가능 | 신규 계획 생성·확정/재인증 중단 | 동일 버전 재개 금지, 새 버전 필요 |
| 개인 보유 자격 | 유효한 자격으로 인정 | 효력 정지·필수 자격 미충족 | 복구 없이 새 취득 필요 |
| 인원 취득 대상 | 취득·평가·재인증 가능 | 모든 취득/재인증 중단, 대상자 통계 제외 | 인원에는 이 상태를 사용하지 않음 |

기준 Hold/Revoke는 이미 확정한 배정의 평가·자동 취득과 보유 자격을 바꾸지 않습니다. 인원 Hold는 보유 자격 효력을 정지시키지 않습니다. **어느 Hold도 만료일을 늦추지 않습니다.** 자료와 과거 기록은 계속 조회합니다.

- `자격 관리`에서 기준 상태·영향 건수·사유를 확인하고 변경합니다. `인증 대상자 관리`는 검색·체크·선택 인원·일괄 Hold/해제를 제공합니다. 세부 관리자는 정확히 같은 조직의 직접 소속 인원만 처리합니다.
- `개인 자격 관리`에서 보유 자격을 검색하고 상태·이력 관리로 이동합니다. 개인 효력 변경은 팀 관리자/선택 Lv1 운영자만 가능합니다.
- 기간제 자격은 **만료 3개월 전**부터 재인증을 기본 허용합니다. 관리자가 개월 수를 수정하며 재인증 사전 알림 일수와 별개입니다. KST 달력 개월·월말 보정을 사용하고 짧은 기간은 현재 기간 시작일보다 앞서 열지 않습니다.
- 학습자는 `보유 자격 → 상태·재인증 확인 → 재인증 시작 → 종합평가 완료`로 처리합니다. 현재 팀 목록의 같은 계보 Active 게시 버전을 사용하며 새 계획이나 인증Set 평가를 만들지 않습니다. **MVP 완료 버튼으로 처리**한 사실을 남기고 실제 평가 점수를 만들지 않습니다.

## 백업·복구·일반 초기화

일반 업무 저장은 기존 자동 백업·쓰기 대기열·revision 검사·중복 요청 방지를 유지합니다. 삭제·가져오기·등록·진행 초기화에는 영구 사전 백업을 사용합니다. 시스템 운영의 일반 진행 초기화는 계획·일정·목표·배정을 보존하며 기존 학습 기록은 과거 진행으로만 취급합니다. 조직 정책·세부 관리자 지정·시스템 및 팀 공지는 보존합니다.

서버를 중지하고 실행합니다.

```sh
npm run data:backup
npm run data:restore -- <업무-백업-경로>
npm run data:organizations:restore -- <조직-백업-경로>
npm run data:unlock
```

일반 업무 복구는 현행 스키마와 참조를 검증하며 조직을 덮어쓰지 않습니다. 조직 복구는 현재 사용자 소속과 팀 선정 자격의 게시 버전 참조를 함께 검증하는 별도 절차입니다. 존재하지 않는 자격을 가리키는 복구는 거부합니다. `data:unlock`은 종료된 프로세스의 잠금만 해제합니다. 이관 중단 표시가 남았다면 서버를 중지한 채 표시 파일에 기록된 **동일 접미사의 업무·조직 백업 두 개**를 별도 경로에 복사하고 `EKS_DATA_FILE`·`EKS_ORGANIZATIONS_FILE`을 지정해 `data:migrate-policies -- --dry-run`으로 쌍을 검증합니다. 검증한 두 파일을 원래 경로에 함께 복원한 뒤에만 중단 표시를 제거하고 새 미리보기·이관을 실행합니다. 한 파일만 복구한 채 서버를 켜지 않습니다. 복원 전에 현존 파일과 중단 표시도 별도 보관합니다. 오래된 스키마 5 백업은 현재 코드의 일반 복구 대상이 아닙니다.

## 설정·기준만 남기기와 다른 서버에서 불러오기
