# EKS 직무자격인증

개인 인증 계획·학습 완료 기록·객관식/주관식/FT 실기 평가부터 과정 수료·검증용 인증서·유효기간 안내까지 연결한 로컬 MVP입니다. 기존 실제 수행 비교도 세 평가 유형의 확정 회차를 지원합니다. Vue 3·Fastify·JSON 구조를 사용하며 **Lv1 조직별로 인증 업무를 분리**합니다. 조직 마스터 JSON은 업무·진행 JSON과 별도로 보존합니다.

## 시작

Node 24가 필요합니다. 최근 검증 환경은 Windows Node 24.14.0 / npm 11.9.0입니다. 저장소 루트에서 실행합니다.

```sh
npm ci
npm run data:init
npm run dev
```

`data:init`은 최초 설치에만 사용하며 기존 업무 파일을 덮어쓰지 않습니다. 조직 파일이 이미 있으면 검증하여 그대로 사용합니다. 이후에는 `npm run dev`로 시작합니다. 기존 `schemaVersion: 1`, `2` 또는 `3` 데이터가 있으면 아래 **기존 데이터 이관** 절차를 사용합니다. Node 버전 관리 도구를 사용한다면 `.nvmrc`의 24를 선택합니다.

- 프런트엔드: [http://127.0.0.1:5186](http://127.0.0.1:5186)
- API: `http://127.0.0.1:5187/api` — 개발 중 `/api`는 Vite가 전달합니다.
- 정적 빌드 실행: `npm run build` 후 `npm start`. 이 경우 [http://127.0.0.1:5187](http://127.0.0.1:5187)에서 앱과 API를 함께 제공합니다.

상단에서 가상 계정을 선택합니다. 각 탭은 sessionStorage의 식별자와 탭별 HttpOnly·SameSite 쿠키로 세션을 구분하므로 다른 탭에서 계정을 바꿔도 현재 탭의 계정은 유지됩니다. 새로고침 후에도 같은 탭의 세션을 사용합니다. 서버는 역할·본인·담당 관계를 검사합니다. 계정 선택은 검증 환경의 전환 기능이며 비밀번호 인증은 포함하지 않습니다. 서버는 `127.0.0.1`에만 바인딩됩니다. 세션은 8시간이며 서버를 다시 시작하면 계정을 다시 선택합니다.

## 조직과 역할

| 역할 | 범위와 메뉴 |
| --- | --- |
| 학습자 | 본인 계획·학습·평가·보유 자격, `자격 취득` |
| FT | 같은 Lv1에서 지정된 학습자의 주관식 채점·실기 평가, `FT 평가` |
| 조직 관리자 (`admin`) | 자신의 Lv1 전체 기준·대상자/계획 요청·FT 배정·결과·비교·공지, `인증 업무 관리` |
| 시스템 운영자 (`system_operator`) | 선택 Lv1의 인증 업무 관리 + 전체 조직·사용자·역할·진행 초기화, `인증 업무 관리` / `시스템 운영` |

각 사용자는 Lv1~Lv4 중 한 조직에 소속됩니다. 하위 조직의 관리자도 자신의 Lv1 전체를 관리하며 같은 Lv1 관리자끼리 공동 처리합니다. 배정을 만든 관리자는 이력으로 남습니다. 시스템 운영자는 실제 소속을 유지하면서 **인증 업무 관리**에서 관리할 Lv1을 선택하여 해당 조직의 기준·배정·FT 변경·검증 제외·결과·비교 작성/확정/정정·공지를 관리합니다. 주관식 채점과 실기 판정은 해당 학습자에게 지정된 FT만 확정할 수 있으며 본인 평가는 금지합니다. 신규 배정은 학습자의 계획 완료에서 생성하고 관리자의 직접 배정 API는 차단합니다. 이력에는 실제 실행자와 관리 대상 Lv1이 남습니다.

시스템 운영자 계정에서 다음 화면을 사용합니다.

- **인증 업무 관리:** 최초 진입 시 Lv1을 선택합니다. 선택은 탭별 sessionStorage와 URL의 `lv1OrganizationId`에 유지합니다. 저장 중에는 전환을 막고 미저장 편집이 있으면 확인합니다. 조직 관리자는 자기 Lv1로 고정됩니다.
- **조직 관리:** 트리 검색·펼치기, 추가·이름 수정·이동·표시 순서·사용 중지·재활성화, 전체 경로·소속 인원·변경 이력. 이름과 위치가 바뀌어도 ID는 유지됩니다. 동일 Lv1·동일 레벨 이동만 허용합니다. 제목 옆 `Lv1 조직 추가`로 최상위 조직을 생성하며, 상세에서 해당 조직의 인증 업무 관리·사용자 등록으로 이어집니다.
- **사용자 관리:** 사용자 생성, 이름·소속·복수 역할 수정, Lv1 또는 하위 조직 검색. 소속은 연동 선택기에서 어느 단계에서든 완료할 수 있습니다. 기존 사용자의 Lv1 변경은 지원하지 않습니다.
- **전체 업무 조회:** Lv1을 선택해 자격·과정·기준·배정·평가 결과·인증·비교·공지를 읽습니다.
- **테스트 관리:** 선택한 Lv1 또는 전체 조직의 진행 내역을 초기화합니다.

사용 중지된 조직과 그 하위에는 신규 사용자 소속·배정을 할 수 없습니다. 기존 소속·진행·과거 기록은 유지합니다. 진행 중 배정에 필요한 학습자·FT 역할 제거와 마지막 시스템 운영자 역할 제거를 차단합니다. 조직·사용자 수정은 revision과 중복 요청 ID를 검사하며 충돌 시 `다시 불러오기`로 확인합니다. 다른 탭의 역할 변경은 다음 조회·쓰기에서 반영되고, 탭으로 돌아올 때 화면 권한도 갱신합니다.

## 기존 데이터 이관

실행 중인 개발 서버를 종료한 뒤 실행합니다.

```sh
npm run data:migrate
npm run dev
```

기존 업무 원본을 `data/backups/state/before-migration-*.json`에 보관한 뒤 스키마 5로 전환합니다. 검증에 실패하면 업무 파일을 교체하지 않습니다. 스키마 1의 조직 최초 이관에서만 누락된 조직 파일을 배포용 조직표로 생성하며, 기존 조직 파일은 검증하고 그대로 사용합니다.

- Photo 20개, Etch 11개, FAB운영혁신그룹 4개, 총 35개 조직을 제공합니다. 동명 조직도 각각 다른 ID를 가집니다.
- 기존 김민서·박준호·이서연·정하린·오지훈과 자격·과정·배정·공지는 Photo팀 Lv1 직속에 배치합니다. 기존 ID·평가·수료·인증·비교는 유지합니다. 과거 배정에는 `이관 시 소속`을 표시합니다.
- 이서연은 조직 관리자로 유지하며 별도 `시스템 운영자`(`operator-1`) 계정을 Photo팀 직속으로 추가합니다. Etch·FAB에는 기존 업무를 복제하지 않습니다.
- 위 조직·계정 배치는 스키마 1에서만 적용합니다. 스키마 2→3은 기존 과정에 `operationalStatus: active`를 추가하고 조직·소속·역할·기준 내용·진행·인증을 유지합니다.
- 스키마 3→4는 과정의 기존 `objective/practical/both`를 필수 평가 유형 목록으로 바꾸고, 기존 평가 확정 상태를 `graded`로 구분합니다. 기존 ID·점수·판정·회차·시각·수료/인증 근거를 유지합니다. 계획·학습 기록·알림 컬렉션을 추가하되 기존 배정에 새 선행 조건을 소급 요구하지 않습니다.
- 기존 자격의 설명·영문명·인증기간은 미정으로 유지합니다. 기존 인증에는 `유효기간 미설정 · 기존 기록`과 이관 시 확보한 표기 정보가 붙으며 무기한으로 바꾸지 않습니다. 신규 계획 대상으로 공개하려면 자격의 새 버전에서 설명·기간 정책·필수 과정을 준비합니다. 과거 과정의 필수 학습 항목이 비어 있으면 새 과정 버전에서 준비한 뒤 연결합니다.
- 스키마 4→5는 선택적 기준코드와 가져오기 배치를 추가합니다. 기존 사용자·기준·개인 진행·인증의 ID·내용은 그대로 유지하며 조직 JSON을 쓰지 않습니다.
- 스키마 5에서 다시 실행하면 검증만 하고 파일을 다시 쓰지 않습니다. 정상 서버 시작은 자동 이관하지 않습니다. 스키마 2/3/4/5에서 조직 파일이 없거나 손상되면 자동 재생성하지 않습니다.

## Excel·웹 표 기준 일괄 관리

`인증 업무 관리 → 기준 일괄 관리`에서 **자격 → 과정 → 학습·평가 내용** 순서로 편집합니다. 자격 검색·준비 상태에서 작업할 자격만 열고, 새 내용은 `새 자격 만들기` 또는 `Excel 가져오기`로 시작합니다. 대량 작업은 `전체 과정 표 보기`에서 범위 붙여넣기·행 추가/복제/제외를 사용합니다. 이름과 한글 선택값으로 작성하며 코드·원본 연결은 자동 처리합니다.

- `.xlsx` 10MB·100자격·평가 10,000행까지 지원합니다. 자격별 메타정보와 이름 있는 5개 데이터 표를 사용합니다.
- 게시된 기준은 새 초안 버전으로 개정하고, 동일 내용 재가져오기는 새 버전을 만들지 않습니다. 다른 자격에서 사용할 과정은 독립 사본입니다.
- 구조 오류는 저장을 차단하고 미완성 기준은 초안 저장 후 보완합니다. 사용 등록은 관련 과정과 자격을 함께 검증해 원자적으로 처리합니다.
- 입력 후 500ms에 사용자·Lv1·작업별 IndexedDB에 자동 보관합니다. **브라우저 보관은 서버 저장이 아닙니다.** 다시 방문하면 이어쓰기/폐기를 선택하고, 보관 실패·서버 충돌에서도 작업 파일 다운로드로 내용을 보존할 수 있습니다.
- 변경 전후 검토에서 적용 대상을 선택하고 `초안 저장 → 사용 등록`을 같은 화면에서 진행합니다. 일부만 저장·등록해도 나머지 입력을 유지합니다. 행 선택 없이는 복제·제외할 수 없고 과정 제외는 연결 학습·문항까지 확인 후 처리합니다.
- 기본 Excel은 한글 드롭다운과 과정 이름 선택을 갖춘 v2이며 v1도 읽습니다. 원본 연결 정보는 접힌 관리 영역에 보존하고 신규 코드는 자동 생성합니다. 파일에 포함되지 않은 자격과 과거 학습·인증은 유지합니다.
- 초안 저장/등록 전에 영구 백업을 만들며, 최신 역할·Lv1·원본 revision·요청 ID를 쓰기 대기열에서 재검사합니다.
- 자세한 양식·보존·API·QA 절차: [CATALOG_WORKBOOK.md](docs/CATALOG_WORKBOOK.md). 공통 스타일·작업 폭·표 40/48px 밀도는 최신 [DESIGN.md](docs/DESIGN.md)의 EKS 업무 화면 적용 규칙을 따릅니다.

스키마 4 백업을 현재 코드로 복구할 때에는 복사본을 `EKS_DATA_FILE`로 지정하고 정상 조직 파일을 `EKS_ORGANIZATIONS_FILE`로 지정하여 먼저 `data:migrate`로 스키마 5로 검증·이관합니다. 서버를 중지한 뒤 이관된 백업을 `data:restore`에 전달합니다. 기존 조직 마스터를 복구/초기화할 필요는 없습니다. 이번 배포 자체를 스키마 4 코드로 되돌릴 때만 배포 전 코드와 원본 백업을 함께 사용합니다.

## 개인 계획·학습·평가 운영

1. 운영자는 사용자 등록에서 조직과 학습자 역할을 지정합니다. 조직 관리자는 자기 Lv1, 시스템 운영자는 선택 Lv1에서 기준을 준비합니다.
2. **자격 관리 → 기본 자격 가져오기**에서 15종 중 필요한 항목만 독립 초안으로 가져옵니다. 같은 Lv1의 같은 템플릿을 재가져와도 중복 생성하지 않습니다. **새 자격**도 계속 만들 수 있습니다. 제공된 한·영 명칭과 순서를 유지하고 설명·기간·과정·평가 기준은 임의로 채우지 않습니다.
3. 자격 설명·인증기간(기간제 또는 무기한)·같은 Lv1의 게시된 필수 과정을 준비한 뒤 사용 등록합니다. 과정에는 필요한 MTC교육/팀 특화 교육/현업 OJT 중 하나 이상의 필수 학습 항목, 필수 평가 유형과 유형별 기준을 설정합니다. 미정 기준은 초안으로 보존합니다.
4. **대상자·계획 → 계획 수립 요청**에서 학습자, 작성 기한, 안내문, 선택적인 FT를 지정합니다. 다시 요청하면 새 기한·안내를 별도 이력으로 남기며 기존 계획을 덮어쓰지 않습니다. 학습자는 개인 알림에서 **내 계획**으로 이동해 취득할 자격을 선택하고 과정별 일정·목표를 작성합니다. 계획 작성 기한과 목표 인증일은 별개입니다.
5. **계획 완료**는 결재 생략 정책과 절차 버전을 기록하고 계획 확정·배정·필수 수강을 한 번에 저장합니다. 일정의 선후 관계를 검사하지만 예정일 이전 시작이나 지연을 차단하지 않습니다. 완료 후 일정·목표 수정에는 사유가 필요하며 기준 버전은 바뀌지 않습니다.
6. 필수 학습 항목별 실시일·완료 내용과 선택적인 근거 URL을 학습자가 기록합니다. `학습자 기록`이며 외부 기관 공식 확인이 아닙니다. 필수 학습 기록을 갖추면 과정별 평가를 진행합니다.
7. 객관식·주관식·실기는 각각 통과해야 합니다. 통과한 유형을 유지하고 미통과 유형만 다시 응시합니다. FT가 없어도 계획·학습·객관식·주관식 초안 작성은 가능하며 주관식 제출/실기 요청은 배정 후 열립니다. 다른 과정의 채점 대기는 현재 과정의 진행을 막지 않습니다.
8. 주관식은 답안 제출 후 고정됩니다. 지정 FT가 배점 내 점수·비공개 채점 근거·공개 피드백을 기록하고 확정하면 서버가 합격 여부를 계산합니다. 미통과에는 공개 피드백이 필요합니다. FT 변경은 제출 답안과 과거 확정을 보존하고 이전 FT의 미확정 초안을 이력으로 남긴 뒤 새 FT에게 빈 채점을 제공합니다.
9. 과정의 필수 평가를 모두 통과하면 수료증, 자격의 필수 과정을 모두 수료하면 인증서를 조회할 수 있습니다. 발급번호·취득일·발급 당시 표기·평가 근거를 저장하므로 재조회가 재발급을 만들지 않습니다.

학습자 홈은 계획 요청·작성 중 계획·다음 학습/평가·만료 안내를 보여줍니다. **FT 평가**는 주관식 채점과 실기 평가를 나누고 학습 목표를 함께 표시합니다. **대상자·계획**은 미발송·미착수·작성 중·계획 완료·학습 진행·FT 미배정·평가 대기·기한 경과를 구분합니다. 결과 조회와 보유 자격에서 유효·만료 예정·만료·기간 미설정 상태를 필터링할 수 있습니다.

계획/답안/채점은 500ms 자동 저장, revision 충돌 확인, 응답 유실 재시도를 사용합니다. 최종 제출 전 저장을 완료하며 화면·계정·Lv1 전환 시 입력을 보호합니다. 학습자용 계획 목록에 정답·모범답안·채점 기준은 포함하지 않습니다. 절차 정의는 `personal-certification-v1`과 안정적인 12개 단계 ID로 관리합니다. 절차 추가·변경은 코드와 버전으로 확장하며 동적 절차 편집기는 없습니다.

## 일정 기본값·미확정 계획 삭제·단일 디자인

계획을 시작하면 서버의 Asia/Seoul 오늘을 기준으로 시작일은 7일 후, 완료는 시작일부터 21일 후, 평가는 시작일부터 28일 후로 저장합니다. 기존 초안은 일정 화면 첫 진입에서 빈 날짜만 보완하며 기존 시작일이 있으면 그 날짜를 기준으로 계산합니다. 이후 날짜를 지우거나 시작일을 바꾸어도 다른 날짜를 자동 변경하지 않습니다. 목표 인증일·학습 목표는 직접 입력합니다. 과정명과 세 날짜를 한 행으로 표시하고 모바일에서는 세로로 바뀝니다.

`내 계획`의 **계획 삭제**는 본인 미확정 계획만 처리합니다. 일정·목표는 업무 목록에서 제외하고 삭제자·시각·감사 기록을 보존합니다. 원래 계획 요청·알림 읽음 상태는 유지되어 같은 자격을 다시 작성할 수 있습니다. 확정·배정된 계획은 삭제할 수 없습니다. 다른 탭의 삭제된 계획은 `PLAN_DELETED` 안내와 함께 자동 저장을 중단합니다.

모든 화면은 새 [DESIGN.md](docs/DESIGN.md)의 단일 밝은 스타일을 따릅니다. 테마 선택기·계정별 테마 동기화는 제거했으며 예전 설정값은 읽거나 삭제하지 않습니다. 일반 화면·개별 편집은 최대 1280px, 관리 목록·Excel 표는 1760px입니다. 날짜·표·대화상자도 같은 스타일을 사용합니다. 일정/삭제의 스키마 5 선택 필드와 기존 데이터는 유지합니다.

## 인증 유효기간과 개인 알림

- 기간제는 개월 수와 하나 이상의 만료 전 알림 일수를 관리자가 확정합니다. `90·30·7일 전`은 선택 예시이며 기본 정책으로 저장되지 않습니다. 무기한은 명시적으로 선택해야 합니다.
- 취득일의 대한민국 날짜에 개월 수를 더하고 해당 날짜가 없으면 월말로 맞춥니다. 만료일의 Asia/Seoul 하루가 끝날 때까지 유효합니다. 발급 시 복사한 정책은 이후 기준 개정의 영향을 받지 않습니다.
- **취득 사실**과 **현재 유효 여부**를 분리합니다. 만료 인증은 현재 유효 집계에서 제외하지만 인증서·평가 근거·실제 수행 비교 기록을 보존합니다. 과정 운영 종료도 기존 취득/진행 근거를 삭제하지 않습니다.
- 개인 알림은 계획 요청, FT 요청, 평가 결과, 수료/인증, 만료 예정/만료를 안내합니다. 읽음은 업무 완료를 뜻하지 않습니다. 생성된 기록을 수신자·관련 기록·발생 시점으로 중복 방지합니다.
- 만료 알림은 서버 시작 시와 실행 중 1분마다 공통 쓰기 대기열에서 확인합니다. 중지 기간에는 알림이 생성되지 않으며 재시작 시 현재 가장 가까운 경고 시점 또는 만료 알림만 보충합니다. 지난 경고를 한꺼번에 만들지 않습니다. 서버 내부 시계 주입과 순수 날짜 계산 함수를 시험에 사용합니다.
- 알림은 시스템 내 조회만 지원합니다. 이번 범위에 재인증 신청·재응시·재발급이나 외부 전송 버튼을 추가하지 않습니다.

주요 추가 API는 `/api/qualification-templates`, `/api/qualification-templates/import`, `/api/planning-requests`, `/api/plans`, `/api/plans/:id`(저장), `/api/plans/:id/complete`, `/api/enrollments/:id/learning`, `/api/attempts/:id/grading`, `/api/attempts/:id/grading/finalize`, `/api/completions/:id`, `/api/notifications/:id/read`입니다. 주관식 답안은 기존 응시의 `/draft`·`/submit`을 사용합니다. 계획 가능 자격·개인 계획·알림·보유 인증은 권한에 맞는 `/api/workspace`에서 조회합니다. 모든 쓰기는 기존 revision·중복 요청 방지·Lv1/본인/지정 FT 검사·공통 저장 절차를 유지합니다.

## Photo팀 프로세스 검증 데이터

현재 개발 JSON에는 Photo팀의 **게시 자격 15종·고유 과정 75개**가 있습니다. 과정마다 필수 학습 항목 1개와 객관식·주관식·실기 3항목씩 총 675개 평가 항목을 넣었습니다. 모든 시험 문항 끝의 정답·예시·통과 기준은 프로세스 시험을 위한 의도적인 공개 정보입니다. 자격 설명·관리/학습자 목록·인증서에서 시험 데이터임을 표시합니다. 36개월 유효기간과 90·30·7일 전 알림도 **Photo팀 시험 기준**이며 실제 사내 자격 정책으로 사용하지 않습니다. 다른 Lv1에 이 기준을 자동 복제하지 않습니다.

2026-10-19 11:42 KST의 최종 일회성 적용에서 Photo팀의 `평가 흐름 체험`, `Recipe Management`, 후속 시험 v2와 `자료 확인`, `기록 작성`, `Recipe 생성`, `Recipe 편집`을 ID 계보로 제거했습니다. 잘못 Recipe 과정을 참조하던 설비 Backup 시험 버전도 제거하고 새 5과정으로 재구성했습니다. **전 Lv1의 계획 요청·계획·배정·학습·평가·수료·인증·비교·진행 알림과 관련 이력**을 정리했습니다. 무관한 초안·다른 조직 기준, 사용자·역할·조직 JSON은 보존했습니다. 일반 `테스트 관리 → 초기화`는 계획·배정을 보존하므로 이 작업과 범위가 다릅니다.

이전 체험 데이터가 있는 개발 저장소에서만 `npm run data:setup-photo -- --dry-run`으로 revision·업무 해시·삭제 ID·보존/생성 건수를 확인한 뒤 서버를 중지하고 아래처럼 적용합니다. **현재 파일에는 이미 적용돼 재실행하면 무변경**입니다. 예상 밖 참조나 revision·해시 변경이 있으면 적용을 중단합니다. 새 설치는 체험 데이터 없이 시작하므로 이 일회성 정리 명령을 사용하지 않습니다. 회귀 시험용 체험 데이터는 `server/tests/fixtures/seed-source.json`에만 보관합니다.

```sh
npm run data:setup-photo -- --dry-run
npm run data:setup-photo -- --apply --expected-revision=<미리보기 revision> --expected-sha256=<미리보기 stateSha256> --confirm=DELETE_ALL_PROGRESS
```

최종 적용 전 원본 영구 백업은 `data/backups/state/manual-1792377775491.json`, 조직 사본은 `data/backups/organizations/manual-1792377775496.json`입니다. 업무 원본 SHA-256은 `3de1af9f3ba536db4b69fb4a834c5da3c187b09f781ebd27c45b8f2b2c5d5932`, 조직 원본·적용 후 SHA-256은 `b7978595eccd107c98ed4e1eaff27527e90a4500c4945f5030c01a7700fa093c`입니다. 복구가 필요하면 서버를 중지하고 이 백업 쌍을 **별도 임시 저장소에서 먼저 검증**한 뒤 `npm run data:restore -- "data/backups/state/manual-1792377775491.json"`을 실행합니다. 업무 전체를 되돌리므로 백업 이후에 새로 쌓인 진행도 함께 사라집니다. 조직 파일은 이 적용에서 변경되지 않았고 일반 업무 복구도 조직 JSON을 수정하지 않습니다.

## 과정 삭제·운영 종료

`인증 업무 관리 → 과정 관리`의 과정 상세에서 처리합니다. 게시 상태(초안/사용 등록)와 운영 상태(운영 중/운영 종료)를 분리합니다.

| 동작 | 조건과 영향 |
| --- | --- |
| 초안 삭제 | 자격 초안의 필수 과정·수강·평가·수료·비교·후속 버전 참조가 없는 초안만 삭제합니다. 생성 감사·요청 기록은 삭제를 막지 않습니다. 사유와 삭제 전 원본 이력을 보존합니다. |
| 운영 종료 | 사용 등록된 **선택 버전**의 신규 사용만 중단합니다. 배정 이력이 없어도 게시한 버전은 물리적으로 삭제하지 않습니다. |
| 기존 배정 | 미시작자를 포함하여 기존 필수 과정·버전 그대로 학습·평가·재응시·수료·자동 인증을 계속합니다. |
| 기존 인증 | 인증 ID·취득일·자격 버전·수료·평가 근거를 그대로 유지하고 현재 과정의 운영 종료 상태를 표시합니다. |
| 신규 사용 | 종료 과정을 포함한 자격의 신규 배정과 자격 초안의 사용 등록을 막습니다. 초안 저장은 허용합니다. 새 자격 버전에서 제거·대체해야 합니다. |
| 운영 재개 / 새 버전 | 사유를 입력하여 같은 내용·버전을 재개하거나, 종료 정보를 승계하지 않는 새 과정 초안을 만듭니다. v1 종료는 v2에 영향을 주지 않습니다. |

필수 과정을 자동으로 제거하거나 교체하지 않습니다. 운영 종료는 인증 취소가 아니며 취득한 인증의 취소·재평가는 이번 범위에 포함하지 않습니다.

실행 전에 조직·과정·버전, 연결 자격과 배정·수료·인증 건수를 확인합니다. 과정 revision과 업무 revision을 함께 검사하고 확인 이후 변경되면 다시 조회하도록 합니다. 초안 삭제 전 영구 백업은 `data/backups/state/before-course-delete-<revision>-<UUID>.json`입니다. 백업 실패 시 삭제하지 않으며 같은 요청의 재시도는 삭제 후에도 원래 성공 응답을 반환합니다.

API는 `GET /api/courses/:id/usage`, `DELETE /api/courses/:id`, `POST /api/courses/:id/retirement`, `POST /api/courses/:id/reactivation`입니다. 쓰기 본문에는 `courseRevision`, `stateRevision`, `reason`을 전달합니다. 운영자의 모든 조직 업무 쓰기는 `?lv1OrganizationId=<선택 Lv1>`과 `Idempotency-Key`가 필수입니다. 조직 관리자는 생략 시 자기 Lv1을 사용하며 다른 Lv1을 지정하면 거부합니다. 같은 요청 키로 조직을 바꾸면 충돌합니다. Workspace는 실제 `actor`와 별도 `management` 정보를 제공합니다.

삭제 후 되돌림이 필요하면 서버를 중지하고 사전 백업을 **별도 임시 저장소에서 먼저 검증**한 뒤 일반 복구 절차를 사용합니다. 업무 파일 전체를 되돌리므로 백업 이후의 진행·변경도 되돌아갑니다. 단순 운영 종료를 취소할 때는 백업 복구 대신 `운영 재개`를 사용합니다. 일반 복구는 조직 마스터를 변경하지 않습니다.

## 저장·백업·복구

- 업무: `data/runtime/state.json` (`schemaVersion: 4`). 사용자 소속·역할·revision, Lv1 소유 기준·배정·공지, 응시·수료·인증·비교·변경 이력·중복 요청 정보를 저장합니다. 새 배정은 당시 학습자의 전체 조직 경로를 보관합니다.

- **진행 초기화, 일반 데이터 복구, 재시작은 조직 파일을 수정하지 않습니다.** 시작 시 파일 누락·손상은 오류로 중단합니다. 조직·업무·백업 파일은 웹 정적 경로에 노출하지 않습니다.

**서버를 종료한 뒤** 수동 백업·복구를 실행합니다.

```sh
npm run data:backup
npm run data:restore -- "data/backups/state/manual-<생성시각>.json"
npm run data:organizations:restore -- "data/backups/organizations/manual-<생성시각>.json"
```

`data:backup`은 업무·조직 백업 경로 두 개를 출력합니다. 필요한 파일의 실제 경로를 해당 복구 명령에 넣습니다. 일반 복구는 현재 조직과 업무 백업의 참조·채점·근거를 검증하고 업무 파일만 교체합니다. 조직 복구는 현재 업무 파일을 잠근 상태에서 모든 사용자와 업무의 조직 참조를 검증한 뒤 조직 파일만 교체합니다. 조직 파일이 없거나 손상된 경우에도 이 별도 복구를 사용할 수 있습니다. 참조가 맞지 않는 백업은 거부하며 현재 파일을 `before-restore-*.json`으로 보관한 뒤 교체합니다.

두 파일이 모두 손상됐다면 원본을 보관한 뒤 호환되는 업무·조직 백업 쌍을 별도 임시 디렉터리에 복사하고, 그 두 경로를 환경 변수로 지정해 `data:backup`이 검증을 통과하는지 확인합니다. 검증된 쌍을 서버가 중지된 운영 경로에 복사하여 복구합니다. 스키마 1/2/3/4 업무 백업도 별도 디렉터리에서 `data:migrate`로 먼저 검증·변환합니다. 조직 마스터는 기본 조직표로 대체하지 않습니다.

비정상 종료로 잠금만 남았다면 `npm run data:unlock`을 실행합니다. 두 저장소 각각 잠금에 기록된 프로세스가 종료된 경우에만 해제합니다. 실행 중인 서버를 강제로 해제하는 명령은 없습니다. 운영 조직·업무·백업·잠금 파일은 Git에 포함하지 않습니다.
