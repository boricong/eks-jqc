# EKS 직무자격인증

관리자 요청 → 학습자 자격 선택·개인 계획 → 자격 상세·학습자료 확인 → 지식·상황 대응 평가 → 인증Set 수료 → 자격 인증·유효기간 조회를 연결하는 로컬 MVP입니다. 지식 평가를 통과한 뒤 상황 대응 평가에 응시하며, 두 평가는 학습자가 직접 응시하고 서버가 자동 채점합니다. 실제 장비 작업의 관찰·시연을 자동 확인하는 기능은 아닙니다. Vue 3·Fastify·JSON으로 구현하며 Lv1별 기준과 진행을 분리합니다.

Auditor는 별도의 **평가자** 역할로 계획 없이 자율 학습합니다. 필수 학습항목을 본인이 확인해 수료하며 일반·메인 선행 조건과 갱신은 Auditor 풀 계약을 따릅니다. 타인 평가/승인은 제공하지 않습니다.

## 조직 필요자격과 계획 요청

Auditor는 시스템 기본자격 풀에서 팀에 등록합니다. 일반·메인 등급과 선행 일반 자격은 시스템에서 지정하며, 새 팀 자격은 v1·Hold입니다. 팀별 Active 일반·메인은 각각 하나입니다. Auditor 운영에는 지정 안내문 설정만 남습니다. [Auditor 풀·API·이관 계약](docs/AUDITOR_POOL.md)을 확인하세요.

업무27은 서버 종료·세 파일 및 소스 백업 후 `data:migrate-objective-renewals`로 명시 이관합니다. [객관식 재인증 계약](docs/OBJECTIVE_RENEWALS.md)을 따르세요.

현행 형식은 **업무28·조직4** (설정 파일 이전 종료)입니다. 자격·인증Set은 불변 메이저·마이너 버전을 사용합니다. [버전 운영·API·이관 계약](docs/RELEASE_VERSIONS.md)을 따르세요. 팀 자격의 운영 준비를 완료한 뒤 `조직 필요자격` 또는 자격 상세의 `필요 조직 설정`에서 Auditee 필요자격을 지정합니다. 상위 지정은 하위 조직으로 상속됩니다. 사유를 입력해 상속을 제외하면 하위 조직에도 이어지고, 더 아래에서 직접 지정하면 다시 적용됩니다. 새 계획 요청은 당시 적용 목록과 규칙을 고정합니다. 업무26은 백업 후 `data:migrate-requirement-exceptions`로 명시 이관합니다. 기존 선택형 요청·확정 계획·학습 기록은 보존하고, 관리자가 선택한 이전 요청만 교체 종료합니다. [운영·API·이관·복구 계약](docs/ORGANIZATION_REQUIREMENTS.md)을 따르세요.

## 자격 단위 계획

Auditee는 조직 필요자격마다 시작일·종료일과 선택 학습 목표 하나를 작성합니다. 인증Set별 일정·평가 예정일은 사용하지 않으며 종료일이 취득 목표입니다. 업무24는 서버 종료·백업 후 `data:migrate-qualification-plans`로 명시 이관합니다. [API·보존·운영 계약](docs/QUALIFICATION_PLANS.md)을 확인하세요.

## 주관식 평가 — 답변 수집 (2026-10-26)

Auditee 공통·특화인증Set에 선택형 주관식 문항을 제공합니다. 학습자는 자동 임시 저장 후 모든 문항에 답변하면 한 번 제출하며, 제출하거나 인증Set을 수료하면 수정할 수 없습니다. 관리자는 제출 답변만 조회합니다. 준비 상태·필수 평가 순서·점수·수료·인증에는 영향을 주지 않으며 Auditor는 기존 학습 확인을 유지합니다. 이 기능 도입 시 형식은 **업무22·조직4·기본정보 JSON12**였습니다. 업무21은 서버를 중지하고 세 파일·호환 소스를 백업한 뒤 `npm run data:migrate-subjective -- --dry-run`과 명시 적용을 수행합니다. [상세 계약·이관 절차](docs/SUBJECTIVE_RESPONSES.md)를 따르세요.

## 조직별 필수자격 종료 (2026-10-26)

조직 필수 설정·판정·화면·현황 지표를 제거했습니다. `/admin/organization-settings`에서 조직 정보·세부 관리자를 관리하며 예전 `/admin/policies`는 새 화면으로 이동합니다. 이전 필수 API는 권한 확인 후410 `FEATURE_REMOVED`로 종료합니다. 기존 요청의 필수 대상은 선택 항목으로 전환하고 원문은 감사·백업에 보존합니다. 업무21·조직4·기본정보 JSON11의 명시 이관이 필요하며 일반 시작은 자동 이관하지 않습니다.

## 엑셀·기준 일괄 편집 종료 (2026-10-26)

해당 메뉴·화면·파일 처리와 전용 의존성을 제거했습니다. 예전 `/admin/catalog` 주소는 관리 조직·유형을 유지해 팀 자격 설정으로 이동합니다. `/api/catalog/*`는 인증·관리 권한 확인 후 본문을 해석하기 전에 410 `FEATURE_REMOVED`를 반환합니다. 기존 업무20·조직3·JSON10 및 과거 일괄 이력·감사·영수증은 보존합니다. 브라우저에 남은 과거 초안은 자동 삭제하지 않지만 현재 편집/복구 기능은 제공하지 않습니다.

## 인증 업무 관리 메뉴

관리 메뉴는 **현황 조회 / 인증 운영 / 자격 기준 설정 / 팀 소통**으로 구분합니다. 그룹은 접지 않으며 기존 주소와 권한을 유지합니다.

- 현황 조회: 인증 현황
- 인증 운영: 취득 대상자 상태 → 팀 사용자 관리 → 조직 정보·관리자 → 조직 필요자격 → Auditor 운영 → 계획 요청·진행 → 평가·수료 결과 → 보유 자격 관리
- 자격 기준 설정: 팀 자격 설정 → 인증Set 설정
- 팀 소통: 팀 공지 관리

세부 조직 관리자는 인증 현황·취득 대상자 상태·조직 정보·관리자·조직 필요자격만 사용합니다. 조직 설명·담당 업무를 저장하고, 관리자 지정은 팀 관리자와 시스템 운영자가 별도로 저장합니다. 계획 요청 현황과 자격별 취득 진행의 필터는 각각 해당 구역에만 적용합니다.

## 실행

Node 24를 사용합니다. Windows PowerShell에서는 `npm.cmd`를 사용하면 실행 정책의 영향을 피할 수 있습니다.

```sh
npm ci
npm run data:init
npm run dev
```

`data:init`은 최초 설치 전용입니다. 기존 업무·조직 파일을 덮어쓰지 않습니다. 이후에는 `npm run dev`만 실행합니다. 기존 업무 스키마 8·7·조직 스키마 2 및 업무6·조직1은 아래 해당 보존 이관이 필요하며 서버 시작 시 자동 변환하지 않습니다.

- 앱: http://127.0.0.1:5186 또는 `http://서버IP:5186` (LAN 기본 수신)
- API: http://127.0.0.1:5187/api
- 정적 실행: `npm run build` 후 `npm start` → `http://서버IP:5187` (웹앱·API 단일 포트)
- [LAN 환경변수·요청 검증·WSL 포트포워딩 안내](docs/NETWORK.md)
- 업무 JSON: `data/runtime/state.json` (스키마 27)
- 조직 JSON: `data/master/organizations.json` (스키마 4)
- 별도 시험 파일: `EKS_DATA_FILE` 환경변수. 실제 운영 파일로 시험하지 않습니다.

계정 전환은 MVP 검증용이며 사내 로그인 인증이 아닙니다. 탭별 세션 쿠키·sessionStorage 식별자를 사용하고 8시간 뒤 만료됩니다. 서버 재시작 후 계정을 다시 선택합니다. 개발 웹앱과 빌드 실행은 기본적으로 0.0.0.0에서 수신하며 개발 API만 127.0.0.1을 유지합니다. 사설 IP·로컬 접속 주소와 요청 출처를 검증하고, 접속자 범위는 별도 방화벽으로 제한합니다. JSON·백업·서버 소스는 정적 경로로 제공하지 않습니다.

## 운영 규칙

| 역할             | 범위                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| 학습자           | 본인 계획·학습·두 평가·수료증·인증서                                     |
| 팀 조직 관리자   | 자기 Lv1의 기준·계획 요청·결과·팀 공지·조직 정보·세부 관리자 지정        |
| 세부 조직 관리자 | 실제 소속 조직 한 곳의 설명·담당 업무 설정, 직접 소속 인원의 대상자 Hold |
| 시스템 운영자    | 조직·사용자·역할·시스템 공지, 명시적으로 선택한 Lv1의 관리자 기능        |

FT 역할과 주관식은 폐지했습니다. 박준호·오지훈은 학습자이며 복수 역할 계정에서는 FT만 제거했습니다. 시스템 운영자의 소속과 관리 대상 Lv1은 별개입니다. 조직·사용자의 같은 Lv1 내 이동만 지원하며 조직은 물리 삭제 대신 사용 중지합니다. 조직 파일 누락·손상은 시작을 중단하며 기본 조직으로 대체하지 않습니다.

- `객관식 · 지식 평가`: 개념·기준·원리의 이해를 단일 정답 객관식으로 확인합니다.
- `실기 · 상황 대응 평가`: 가상 상황과 대응 질문을 읽고 적절한 선택지를 고릅니다. 실제 작업을 관찰한 증거로 사용하지 않습니다.
- 각 유형의 합격 기준을 독립 적용합니다. 통과한 유형은 유지하고 미통과 유형만 새 회차로 응시합니다.
- 인증Set에 설정된 필수 평가 유형을 모두 통과하면 인증Set 수료, 모든 필수 인증Set 수료 시 자격 인증을 자동 발급합니다.
- 학습자료는 직접 작성·EDM Link·Confluence·일반 URL을 여러 개 등록합니다. URL은 HTTP(S)만 허용하며 외부 접근 권한 확인·본문 수집·파일 업로드는 하지 않습니다. 자료 열람은 학습 완료가 아닙니다.
- 인증Set 생성·관리의 **학습 정보**에서 교육(MTC교육·팀 특화 교육·현업 OJT)과 자료를 세로 탭으로 함께 편집합니다. 교육 우선·구분 내 순서를 저장합니다. Auditee는 학습 정보 없이도 평가 기준을 갖추면 운영할 수 있으며 Auditor만 운영 전 필수 교육을 하나 이상 요구합니다. 두 유형 모두 빈 상태 저장은 가능합니다.
- 개인 계획은 필수 날짜를 확인해 바로 최종 확인·완료할 수 있습니다. `학습 목표(선택)` 단계는 방문과 입력 모두 선택이며, 확정 후에도 사유를 남겨 목표를 추가하거나 비울 수 있습니다. 날짜 순서와 목표2,000자 제한은 유지합니다.
- 새 계획 요청의 작성 기한은 실제 서버 요청일(KST)+28일입니다. 직접 수정한 날짜는 유지하고 빈 날짜는 거부합니다. 개인 계획의 목표 인증일·인증Set 일정과 구분합니다.
- 자격·인증Set은 상세에서 바로 편집·저장합니다. 참조된 내용은 자동 새 버전, 미참조 내용은 같은 ID에서 수정합니다. 미완성도 저장하며 새 운영에는 완성된 기준만 사용합니다. 팀 적용 버전은 자동 변경하지 않습니다.
- 인증기간은 발급 시 고정합니다. 기간제는 월말 보정 후 만료일 KST 하루 끝까지 유효합니다. 재인증 사전 알림은 시작일 기본7일 전에 유효기간별 한 번 생성하며 재시작 시 필요한 누락 알림만 보충합니다. Auditee 재인증은 객관식 전용 팀 자격의 평가 합격으로 선택한 기존 인증을 갱신합니다. [운영·API·이관 계약](docs/OBJECTIVE_RENEWALS.md)을 따릅니다.

Photo팀 시험 기준은 15자격·75인증Set·지식 225문항·상황 대응 225문항입니다. 유형별 100%, 취득 후 36개월·재인증 시작 기본7일 전 1회 알림, 문항 끝 정답 공개는 **프로세스 검증용 데이터에만** 적용합니다. 실제 회사의 장비값·승인 기준을 대신하지 않습니다.

### 평가 기준 검증 기능 종료 (2026-10-24)

실제 수행과 평가 회차를 비교하던 `평가 기준 검증`의 메뉴·작성/조회 화면·시스템 조회 탭을 제거했습니다. 인증 업무 관리는 네 그룹·10개 메뉴이며, 기존 `/admin/comparisons`와 상세 주소는 관리 조직을 유지한 채 인증 현황으로 이동합니다. 기존 접근 권한은 그대로 적용됩니다.

`GET /api/comparisons`, `GET /api/comparisons/:id`, `POST /api/enrollments/:id/comparisons`, `PUT /api/comparisons/:id`, `POST /api/comparisons/:id/finalize`, `POST /api/comparisons/:id/corrections`는 모두 종료하여 404를 반환합니다. `/api/workspace` 응답에서도 `comparisons`를 제외했습니다.

업무 스키마 13의 과거 비교 자료와 감사 이력은 파일·백업의 호환성을 위해 보존합니다. 새 비교 기록을 만들거나 수정하는 기능은 없으며 데이터 이관·삭제가 필요하지 않습니다. 과거 자료가 있는 저장소는 참조 무결성과 기존 초기화 영향 검사를 유지합니다. 지식·상황 대응 평가, 수료·인증·대시보드의 업무 흐름은 유지합니다.

## 공통 기본자격·팀 자격과 업무 11 → 12 보존 이관

- 시스템 운영 → **기본자격 관리**: Lv1 선택 없이 공통 자격명·영문명·설명을 생성·수정하고 이력을 확인합니다. 인증Set과 유효기간은 포함하지 않습니다.
- 인증 업무 관리 → **팀 자격 설정**: **기본자격에서 등록** 후 팀의 인증Set·평가·유효기간·재인증을 설정합니다. 공통 필드는 읽기 전용입니다. 같은 팀·기본자격에는 하나의 계보만 존재합니다.
- **팀 적용**에서 사용할 완성 버전을 선택합니다. 새 버전 저장은 적용 버전을 자동 교체하지 않습니다. 필수 지정 조직이 있으면 적용 해제를 차단합니다.
- 세부 조직 관리자는 **실제 소속 조직 한 곳**의 설명과 담당 업무를 설정합니다. 기존 계획 요청·취득 절차를 유지합니다.
- 현재 목록은 최신 공통 정보를 사용합니다. 확정 계획·배정·평가·인증은 당시 이름·설명을 보존합니다. 저장 검토 중 공통 정보가 바뀌면 `공통 정보 다시 확인`으로 팀 입력을 유지하며 재검토합니다.
- 엑셀 파일 처리와 기준 일괄 편집은 종료했습니다. 팀 자격·인증Set의 개별 편집과 기본정보 JSON10 백업·복원을 사용합니다.

정상 시작에서 업무11을 자동 이관하지 않습니다. 실행 서버를 중지하고 같은 `EKS_DATA_FILE`·`EKS_ORGANIZATIONS_FILE`을 지정한 뒤 다음 순서로 적용합니다. **초기화 명령은 사용하지 않습니다.**

```sh
npm run data:migrate-templates -- --dry-run
npm run data:migrate-templates -- --apply --expected-revision=미리보기값 --expected-sha256=업무해시 --organization-sha256=조직해시
npm run dev
```

미리보기의 건수·설명 보완 수·revision과 SHA256을 확인합니다. 적용 명령은 영구 업무/조직/기존 관리 정보 백업을 먼저 만들고 동일 데이터인지 재검사합니다. 실패 시 파일 쌍·관리 정보를 되돌리며 반복 이관은 무변경입니다. 성공 후 데이터 세대가 바뀌므로 계정을 다시 선택합니다.

15개 기본자격의 ID는 보존하며 공통 설명은 비워 둡니다. 기존 팀 설명은 원래 기준과 이관 감사의 `previousMetadata`에 남고 공통 설명으로 승격하지 않습니다. 시스템 운영자가 공통 설명을 보완한 뒤 팀을 적용하세요. 미연결/충돌 시 이관이 중단됩니다. 명시적으로 확인한 JSON 연결 파일을 두 명령에 같은 `--mapping=/절대경로/mapping.json`으로 지정할 수 있습니다. `entities`는 기존 자격 `entityId`→기본자격 ID이고, 기존 15종에 없는 공통 자격은 `templates`에 `id/revision/title/englishName/description/updatedAt/updatedBy`를 명시합니다. 이름으로 자동 병합하지 않습니다.

업무11 백업으로 복구할 때는 현행 일반 `data:restore`를 사용하지 않습니다. 서버를 멈춘 상태에서 같은 접미사의 업무·조직·관리 정보 백업을 별도 경로에 보관·검증한 뒤 함께 복원하고, 업무11을 지원하는 이전 코드 또는 `data:migrate-templates`로 재이관합니다. 중단 표시가 남으면 [백업·복구 안내](#백업복구일반-초기화)를 따릅니다.

## 조직 정보·관리자와 필요자격 매핑

1. 팀 관리자가 기본자격을 팀에 등록하고 공통·특화인증Set과 기간 기준을 완성합니다.
2. `조직 정보·관리자`에서 조직 설명·담당 업무와 세부 관리자를 관리합니다.
3. `조직 필요자격`에서 조직 트리를 선택해 Active Auditee 자격을 지정합니다. 상속과 직접 지정 결과를 확인하고 여러 조직의 변경을 한 번에 검토·저장합니다. 자격별 보기에서는 하나의 자격을 여러 조직에 매핑할 수 있습니다. 세부 관리자는 실제 소속 조직만 편집합니다.
4. 관리자는 소속별 필요 목록을 검토하고 계획 수립 요청을 보냅니다. 학습자는 요청에 고정된 각 자격의 시작일·종료일과 선택형 목표를 작성합니다. 기존 요청에는 설정 변경이 소급되지 않습니다.
5. 과거 선택형 요청과 확정 계획·학습·인증 근거는 보존합니다. 새 요청의 필요 목록과 이전 선택형 요청은 각각 당시 정책을 따릅니다.

현행 화면·권한·공개 API는 [조직 필요자격 계약](docs/ORGANIZATION_REQUIREMENTS.md), 백업·이관은 [데이터 운영](docs/MASTER_DATA.md)을 따릅니다. 과거 필수 충족률·통계는 다시 제공하지 않습니다.

## 이전 기준 직접 편집 정책과 업무 10 → 11 → 12 보존 이관

- 자격·인증Set의 초안/사용 등록 속성과 편집 잠금을 제거했습니다. `저장 → 변경 확인 → 저장 확인`으로 처리합니다. 구조 오류는 거부하지만 미정 설명·기간·문항·정답은 저장하고 보완 위치를 안내합니다.
- 참조된 기준은 자동 새 버전으로 저장하고 기존 확정 계획·평가·수료·인증과 팀 적용 버전을 유지합니다. 인증Set 새 버전은 자격 구성에서 따로 선택합니다. 새 자격 버전은 팀 자격 설정의 팀 적용에서 선택해야 신규 계획·재인증에 적용됩니다.
- 팀 관리자와 선택 Lv1 운영자만 자격의 선택 버전을 삭제합니다. 팀 적용 중이면 차단하고, 팀 자격은 참조 여부와 관계없이 삭제 표시로 계보를 보존합니다. 같은 기본자격 재등록은 동일 계보의 다음 버전입니다. 다른 버전·인증Set·개인 보유 자격을 함께 삭제하거나 Revoke하지 않습니다.
- 삭제된 기준은 상태 필터의 `삭제된 항목`에서 조회만 가능하며 복구 기능은 없습니다. 인증Set 삭제도 실제 참조 여부를 검사합니다. 내용 저장만으로 Hold/Revoke/운영 종료를 해제하지 않습니다.
- 인증Set은 상단 가로 구역 탭과 내부 세로 번호 탐색을 사용합니다. 개별 편집에서 참조된 버전과 기존 업무 근거를 보존합니다. 기본정보 이전은 JSON10/업무20/조직3이며 구형 JSON 읽기와 보존 이관을 유지합니다.

서버를 중지한 뒤 실행합니다. 일반 시작에서는 자동 이관하지 않습니다.

```powershell
npm run data:migrate-catalog-editing -- --dry-run
npm run data:migrate-catalog-editing -- --apply --expected-revision=미리보기값 --expected-sha256=업무해시 --organization-sha256=조직해시
npm run dev
```

업무·조직 원본은 같은 접미사의 `before-catalog-editing-*.json` 영구 백업 쌍으로 저장하며 기존 관리 정보도 백업합니다. 기존 ID·버전·내용·정답·조직 정책·진행은 보존하고 자격/인증Set의 `status/publishedAt`만 제거합니다. 조직 JSON은 바이트 그대로 유지합니다. 이관 후 데이터 세대를 바꿔 이전 탭과 복구 입력의 저장을 차단합니다. 반복 이관은 파일·세대를 바꾸지 않습니다.

실패 시 원본 쌍과 관리 정보를 복구합니다. 중단 표식이 남으면 서버를 시작하지 말고 표식의 업무/조직/관리 백업을 함께 확인하세요. 이전 코드로 되돌릴 때도 서버를 중지한 상태에서 스키마10 호환 코드와 동일 접미사의 백업 쌍·관리 정보를 복원해야 합니다. 실제 적용 건수와 백업 경로는 handover 최신 이력을 따릅니다. 이번 이관은 기준 삭제·진행 초기화를 실행하지 않습니다.

## 단일 재인증 알림·평가 순서와 업무 9 → 10 보존 이관

- `재인증 시작 N일 전 알림`은 기본7일, 0~365일이며 0은 당일입니다. 알림일은 KST의 `재인증 시작일 - N일`이고 유효기간 시작일보다 앞서지 않습니다. 기존 시작일 당일/만료 임박의 추가 알림은 중단합니다. 이미 해당 회차에 알렸으면 다시 보내지 않으며, 상태 변경·만료 폐기 사실 알림은 유지합니다.
- 인원/개인 Hold 동안 사전 알림을 중단합니다. 해제·서버 재시작 후에도 유효하고 미발송인 회차만 보충합니다. 발급 당시 만료일/재인증 시작일·최초 근거는 그대로입니다. 종전 `reminderDays`는 과거 정책으로 보존합니다.
- 같은 수강/인증Set 버전의 지식 통과가 실기 시작·저장·제출의 선행 조건입니다. 실기를 신규 운영하려면 지식 평가도 필요합니다. 기존 실기 초안과 확정 근거는 보존합니다.
- 응시는 `제출 → 답안 확인 → 최종 제출`이며 미응답은 팝업과 문항 이동으로 안내합니다. 답안 검토는20개씩, 최종 제출 뒤 수정 불가 안내는 실행 버튼 바로 위입니다. 마지막 문항의 다음 버튼은 안내만 하고 자동 제출하지 않습니다.
- 결과 배경은 로컬 Topography SVG(Hero Patterns, Steve Schoger, CC BY4.0)의 낮은 불투명도 패턴과 녹색/코랄색을 사용합니다. 결과 문구·아이콘·점수·다음 행동을 함께 제공합니다.
- 개별 기준의 누락 알림 설정은 원본, 신규는7일입니다. 기존 복수 알림을 새 정책으로 재해석하지 않습니다. 엑셀 입출력은 종료했습니다.

서버를 중지한 뒤 미리보기의 revision과 두 해시를 사용합니다. 최초 적용은 영구 백업 쌍을 만들고 업무만 원자적으로 교체하며 반복 적용은 무변경입니다.

```sh
npm run data:migrate-assessment-flow -- --dry-run
npm run data:migrate-assessment-flow -- --apply --expected-revision=N --expected-sha256=STATE_HASH --organization-sha256=ORG_HASH
npm run dev
```

백업은 `data/backups/state/before-assessment-flow-*.json`과 `data/backups/organizations/before-assessment-flow-*.json`입니다. 되돌릴 때는 서버를 중지하고 현재 파일을 별도 보관한 뒤 동일 접미사의 원본 백업 쌍과 스키마9 호환 코드를 복원합니다. 현행 코드에는 명시적 이관이 다시 필요합니다. 조직만 임의로 교체하지 않습니다. 실제 적용/검증 결과는 [handover.md](handover.md)를 따릅니다.

## 이전 자격 상태·재인증과 업무 8 → 9 보존 이관 이력

자격의 구성요소 이름은 **인증Set**입니다. 기존 ID·`courseIds`·`/courses` URL은 유지하며 사용자 작성 내용과 과거 감사 원문은 치환하지 않습니다.

| 상태 영역      | Active/대상           | Hold                                    | Revoke                            |
| -------------- | --------------------- | --------------------------------------- | --------------------------------- |
| 자격 기준 버전 | 신규 계획·재인증 가능 | 신규 계획 생성·확정/재인증 중단         | 동일 버전 재개 금지, 새 버전 필요 |
| 개인 보유 자격 | 유효한 자격으로 인정  | 효력 정지                               | 복구 없이 새 취득 필요            |
| 인원 취득 대상 | 취득·평가·재인증 가능 | 모든 취득/재인증 중단, 대상자 통계 제외 | 인원에는 이 상태를 사용하지 않음  |

기준 Hold/Revoke는 이미 확정한 배정의 평가·자동 취득과 보유 자격을 바꾸지 않습니다. 인원 Hold는 보유 자격 효력을 정지시키지 않습니다. **어느 Hold도 만료일을 늦추지 않습니다.** 자료와 과거 기록은 계속 조회합니다.

- `자격 관리`에서 기준 상태·영향 건수·사유를 확인하고 변경합니다. `취득 대상자 상태`는 검색·체크·선택 인원·일괄 Hold/해제를 제공합니다. 세부 관리자는 정확히 같은 조직의 직접 소속 인원만 처리합니다.
- `보유 자격 관리`에서 보유 자격을 검색하고 상태·이력 관리로 이동합니다. 개인 효력 변경은 팀 관리자/선택 Lv1 운영자만 가능합니다.
- 기간제 자격은 **만료 3개월 전**부터 재인증을 기본 허용합니다. 관리자가 개월 수를 수정하며 재인증 사전 알림 일수와 별개입니다. KST 달력 개월·월말 보정을 사용하고 짧은 기간은 현재 기간 시작일보다 앞서 열지 않습니다.
- 현행 Auditee 흐름은 `보유 자격 → 재인증 대상 선택 → 객관식 평가 → 갱신 결과`입니다. 새 계획이나 별도 재인증 자격 인증은 만들지 않습니다. 이전 MVP 갱신 기록은 과거 근거로 보존합니다. [객관식 재인증](docs/OBJECTIVE_RENEWALS.md)을 참고하세요.

## 백업·복구·일반 초기화

일반 업무 저장은 기존 자동 백업·쓰기 대기열·revision 검사·중복 요청 방지를 유지합니다. 삭제·가져오기·등록·진행 초기화에는 영구 사전 백업을 사용합니다. 시스템 운영의 일반 진행 초기화는 계획·일정·목표·배정을 보존하며 기존 학습 기록은 과거 진행으로만 취급합니다. 조직 정책·세부 관리자 지정·시스템 및 팀 공지는 보존합니다.

서버를 중지하고 실행합니다.

```sh
npm run data:backup
npm run data:restore -- <업무-백업-경로>
npm run data:organizations:restore -- <조직-백업-경로>
npm run data:unlock
```

일반 업무 복구는 현행 스키마와 참조를 검증하며 조직을 덮어쓰지 않습니다. 조직 복구는 현재 사용자 소속과 팀 선정 자격의 버전 참조를 함께 검증하는 별도 절차입니다. 존재하지 않는 자격을 가리키는 복구는 거부합니다. `data:unlock`은 종료된 프로세스의 잠금만 해제합니다. 이관 중단 표시가 남았다면 서버를 중지한 채 표시 파일에 기록된 **동일 접미사의 업무·조직 백업 두 개**를 별도 경로에 복사하고 `EKS_DATA_FILE`·`EKS_ORGANIZATIONS_FILE`을 지정해 `data:migrate-policies -- --dry-run`으로 쌍을 검증합니다. 검증한 두 파일을 원래 경로에 함께 복원한 뒤에만 중단 표시를 제거하고 새 미리보기·이관을 실행합니다. 한 파일만 복구한 채 서버를 켜지 않습니다. 복원 전에 현존 파일과 중단 표시도 별도 보관합니다. 오래된 스키마 5 백업은 현재 코드의 일반 복구 대상이 아닙니다.

## 선택형 계획 요청 · 업무13 보존 이관

현재 업무12 저장소는 서버를 중지한 뒤 같은 업무·조직 경로 환경변수로 명시적으로 이관합니다. 시작 시 자동 변환하거나 초기화하지 않습니다.

```sh
npm run data:migrate-planning -- --dry-run
npm run data:migrate-planning -- --apply --expected-revision=N --expected-sha256=STATE_HASH --organization-sha256=ORG_HASH
```

미리보기의 revision·해시를 사용합니다. 이관은 영구 업무/조직/관리 정보 백업 후 원자적으로 교체하며 실패 시 원본을 복구합니다. 기존 요청은 `fixed` 방식과 당시 대상, 기존 계획·평가·인증을 보존합니다. 완료 사실을 추정하지 않습니다. 조직 스키마2·설정 내용은 유지하며 일반 복구 절차는 위 안내를 따릅니다.

신규 요청은 `learner_choice` 방식입니다. `GET /api/planning-requests/:id/candidates`로 본인 후보·차단 사유·완료 가능 여부를 조회합니다. 화면은 `취득할 자격 → 계획 시작 → 일정·목표 작성`이며 별도 선택 저장은 없습니다. `POST /:id/complete`는 `revision` 및 대상 없음인 경우 `confirmNoAdditional: true`를 받습니다. 모든 변경은 Idempotency-Key·본인·소속·최신 역할·취득 상태를 검사합니다. 완료 근거는 계획/인증/이전 직접 배정 참조이며 과거 완료를 이후 정책·효력 변경으로 취소하지 않습니다.

### 계획 시작 API · 선택 단계 통합

`POST /api/plans`는 `{ requestId, requestRevision, qualificationId }`와 `Idempotency-Key`를 받습니다. `requestRevision`은 후보 조회의 `revision` 또는 요청의 현재 수정 번호이며 필수입니다(누락/형식 오류422, 수정 충돌409). 성공 응답은 `{ id }`입니다.

- 요청 소유자·현재 소속·팀 적용 버전·취득 가능 상태를 검증하고 요청 포함과 초안 생성/재사용을 한 쓰기 작업으로 저장합니다. 포함이 추가되면 요청 revision·감사 이력도 함께 갱신합니다. 저장 실패 시 모두 원복합니다.
- 같은 소속·취득 회차·현재 적용 버전의 초안은 다른 요청에서도 재사용합니다. 이전 버전 초안은 원문을 보존하고 현재 버전으로 새로 작성합니다. `fixed` 요청은 당시 대상에 한정하며 유효 인증/확정 진행을 새 계획으로 중복 생성하지 않습니다.
- 응답 유실·조회 실패 재시도는 최초 입력과 키를 그대로 사용합니다. 수정 충돌에서는 선택을 유지한 채 재조회 후 최신 revision으로 다시 시작합니다.
- `DELETE /api/plans/:id`는 기존 계획 revision을 받고, 비필수 초안 삭제와 그 초안을 공유하는 미완료 요청의 선택 제외·revision·감사를 함께 저장합니다. 필수 대상·확정 계획·완료 요청 근거는 변경하지 않습니다.
- `PUT /api/planning-requests/:id/selection`(`revision`, `entityIds`)은 이전 클라이언트 호환 및 계획 없이 선택만 남은 비필수 항목의 `요청에서 제외`에 사용합니다. 새 계획 시작 화면은 이 API를 호출하지 않습니다.

## 인증 현황 대시보드

`인증 업무 관리 → 인증 현황`(`/admin/dashboard`)에서 현재 현황을 요약·조직별·자격별·구성원별·만료/재인증으로 조회합니다. 팀 관리자는 자기 Lv1, 세부조직 관리자는 실제 소속 조직의 직접 소속 인원만 조회합니다. 운영자는 Lv1을 선택합니다. 읽기 전용이며 기존 결과·인증 관리 링크는 해당 권한이 있는 사용자에게만 제공합니다.

- 기본 대상은 활성 소속의 학습자 중 대상자 Hold를 제외한 인원입니다. 제외 인원도 별도 목록으로 조회할 수 있고 보유 인증의 효력·만료는 유지됩니다.
- 현재 팀 적용 자격과 조회 대상 구성원의 진행·보유 기록이 남은 자격을 포함합니다. 자격 계보별로 묶으며 적용 해제된 과거 기록도 보존합니다.
- 계획 확정·자격 취득·현재 효력·재인증 진행은 별개입니다. 여러 요청에서 공유하는 초안은 진행 한 건이며 인증 발급된 배정을 취득 진행으로 중복 집계하지 않습니다.
- 날짜는 Asia/Seoul 기준입니다. 만료일 당일은 유효하고 다음 날부터 만료입니다. 0~30/31~60/61~90일 조회는 기존 재인증 가능 기간을 바꾸지 않습니다.
- 만료 구간의 `기간 만료`(`expired`)와 `수동 폐기`(`revoked`)는 구분합니다. 개인 인증 Hold는 만료 예정에 포함하고 무기한·기간 미정·Revoke는 예정 구간에서 제외합니다.

조회 API는 기존 탭별 세션과 데이터 세대 검사를 사용하고 모든 응답을 `Cache-Control: no-store`로 제공합니다. 정답·답안·문항별 득점·개인 목표·상세 사유 원문은 전용 응답에 포함하지 않습니다.

| GET 경로                         | 응답                                                                                    |
| -------------------------------- | --------------------------------------------------------------------------------------- |
| `/api/dashboard/options`         | 허용 조직·자격 선택지                                                                   |
| `/api/dashboard`                 | `view=summary/organizations/qualifications/members/matrix/renewals`, 요약과 현재 페이지 |

공통 쿼리는 `lv1OrganizationId`, `organizationId`, `includeDescendants`, `population=eligible/excluded/all`이며 탭에 따라 `search`, `entityId`, `required`, `efficacy`, `progress`, `qualificationScope`, `expiryBucket`, `renewalState`, 정렬·페이지 조건을 사용합니다. 일반 목록은 `pageSize=25/50/100`, 매트릭스는 행 페이지와 `columnPage`(10열)를 사용합니다. 정확한 허용값과 반환 필드는 `shared/src/dashboard.ts`를 따릅니다.

`snapshot`에는 `asOf`, KST `date`, 업무·조직 revision, 실제 조회 범위와 제외 수가 포함됩니다. 상세 요청에 `expectedStateRevision`, `expectedOrganizationRevision`, `expectedDate`를 전달하고 기준이 바뀌었으면 `409 DASHBOARD_STALE`로 다시 조회합니다. 권한 검사는 기준 시점 검사보다 먼저 수행합니다. 한 조회의 업무·조직 데이터를 직렬 대기열에서 함께 읽으며 GET은 파일·감사·만료 상태를 변경하지 않습니다.

새 영속 데이터와 스키마 이관은 없습니다. 과거 충족률 추이·기간별 발급 실적·Excel 출력·예약 발송은 포함하지 않습니다. 실제 업무 데이터로 시험하지 말고 기존 임시 JSON 시험 구성을 사용합니다.

### 차트·확대·구간 명세

각 탭은 표와 차트를 함께 제공합니다. **크게 보기**에서 넓은 차트와 데이터 표를 전환하고 구간을 선택하면 그 수치에 포함된 명세, 구성원을 선택하면 개인 요약을 확인합니다. 뒤로/닫기는 선택·차트 페이지·원래 초점을 복원합니다.

GET /api/dashboard의 charts는 현재 뷰의 전체 조건 집계입니다. page, pageSize, columnPage는 차트의 모집단을 줄이지 않습니다. 비교 차트는 현재 정렬의 첫8개를 미리 표시하고 확대 시20개씩 표시합니다. 단일 분포는 항상 전체 조건을 집계하며 그래프와 표를 같은 snapshot으로 반환합니다.

- DashboardChart의 series는 범례와 상태, groups는 조직/자격 또는 전체 분포입니다. groups[].values[i]는 같은 위치의 series 수치이며 단위는 unit을 따릅니다. 비율의 분모0은—입니다.
- 취득 단계는 계획 미작성/작성/평가 대기/진행/일부 수료입니다. 미작성은 기존 ‘취득 진행’ 지표에 포함하지 않습니다. 비필수 미선택은 분포에서 제외합니다. 인증 효력과 재인증은 별도 차트로 표시합니다.
- 구성원 충족 분포는 전체 충족/일부/미충족/필수 없음의 고유 인원입니다. 현재 자격 필터가 있어도 개인의 전체 필수 판정은 유지합니다. 구성원/만료 탭의 차트는 선택한 population을 따릅니다.
- GET /api/dashboard/chart-details는 기존 조회 조건과 chartId, groupKey, seriesKey, expectedStateRevision, expectedOrganizationRevision, expectedDate, 명세 페이지를 받습니다. 응답은 snapshot, selection, title, unit, rows입니다. 기존 지표 명세의 필터 초기화와 달리 현재 탭 조건을 보존합니다.
- 서버는 실제 허용 차트·그룹·구간을 다시 검사하고 같은 단위의 명세를 계산합니다. 잘못된 구간/권한은403, 형식 누락은422, 오래된 기준은409 DASHBOARD_STALE입니다. 화면은 최신 집계를 한 번 갱신하고 재조회하며 실패하면 재시도를 제공합니다.
- 확대/복원 주소는 chart, chartPage, chartDisplay, chartGroup, chartSeries, chartDetailPage, chartMember, chartMemberEntity를 사용합니다. 필터·탭 변경은 차트 선택을 해제하며 개인 데이터는 브라우저에 영속 저장하지 않습니다.

차트에는 개인 답안·정답·목표·상세 사유를 포함하지 않습니다. 확정 기록을 변경하거나 과거 추이를 추정하지 않으며 인증 유형 도입 후 업무15/조직2 저장 형식을 사용합니다.

선택/완료 구조는 업무13에서 도입한 기존 구조를 유지합니다. 인증 유형 도입에는 아래의 업무14 보존 이관을 적용하며 초기화하지 않습니다.

## Auditee·Auditor 인증 유형 (2026-10-25)

유형은 역할이 아닌 기본자격 속성입니다. 시스템 운영자가 기본자격을 만들 때 `Auditee(피심사자)` 또는 `Auditor(심사자)`를 선택하며, 어느 팀에도 등록된 적이 없을 때만 바꿀 수 있습니다. 팀 등록/새 버전은 원본 유형을 상속하고 계획·배정·발급의 당시 메타데이터에 보존합니다.

Auditor는 **기본자격 생성 → 팀 등록 → 기준 편집/저장**까지만 제공합니다. 팀 적용·조직 필수 지정·계획 확정·평가·발급·재인증은 서버에서 제한합니다. 보유 자격은 Auditee/Auditor 탭으로 나뉘며, 현재 실행 데이터의 인증은 Auditee입니다. Auditor 절차·수동 발급·승인/현장 심사는 후속 범위입니다.

업무13 파일은 자동으로 고치지 않습니다. 서버 중지 후 `npm run data:migrate-qualification-types -- --dry-run`으로 검토하고 해시·revision을 지정하여 명시적으로 적용하세요. [유형 이관·복구 절차](docs/MASTER_DATA.md#auditee·auditor-유형-보존-이관-1314)를 따릅니다.

## 팀 자격·인증Set 유형별 작업 공간

팀 자격 설정과 인증Set 설정에서 **Auditee(피심사자) / Auditor(심사자)** 탭을 선택합니다. 기본은 Auditee이며 Auditor 주소에는 `type=auditor`를 사용합니다. 두 메뉴의 이동·상세·목록 복귀는 유형을 유지하며 각 계정/팀/메뉴/유형의 검색·상태·정렬·페이지 크기를 별도로 기억합니다.

- 팀 등록은 선택 유형의 기본자격만 보여줍니다. Auditor는 기준 준비만 가능하므로 팀 적용 행동과 열을 제공하지 않습니다.
- 인증Set 추가는 이름을 입력한 뒤 `생성 후 편집`을 누를 때만 저장합니다. 생성 유형은 탭을 따릅니다. 첫 버전이며 자격 연결·계획·학습·평가·과거 비교 이력이 없는 인증Set만 편집 화면에서 유형을 바꿀 수 있습니다. 저장 검토와 서버의 재검사를 거칩니다.
- 자격은 같은 유형의 인증Set만 연결합니다. 개별 저장에서 검사합니다. 자동 복제와 버전 생성도 유형을 유지합니다. 교차 유형 복제는 제공하지 않습니다.
- 기존 업무14는 자동 수정하지 않습니다. 서버 종료 후 `npm run data:migrate-course-types -- --dry-run`으로 계보 분류와 충돌을 검토하고 `--apply --expected-revision=N --expected-sha256=STATE_SHA256 --organization-sha256=ORG_SHA256`으로 명시적 적용합니다. [데이터 운영 절차](docs/MASTER_DATA.md#인증set-유형-보존-이관-1415)를 따릅니다. 현재 기본정보 JSON10이 유형을 보존합니다.

Auditor 최초 인증은 평가자 역할의 유형별 계획 요청과 필수 학습항목 본인 확인을 사용합니다. Auditee의 기존 평가 절차는 유지합니다. Auditor 재인증·타인 평가/승인은 제공하지 않습니다. 업무16 명시적 이관과 기본정보 JSON10 운영 절차는 [데이터 운영](docs/MASTER_DATA.md), [엑셀 기능 종료 기록](docs/CATALOG_WORKBOOK.md), [최신 인수인계](docs/HANDOVER.md)를 확인하세요.
