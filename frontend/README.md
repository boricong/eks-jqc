# EKS 직무자격인증 프런트엔드

1920×900을 기준으로 홈, 자격 취득, FT 평가, 인증 업무 관리, 시스템 운영 화면을 분리한 Vue 3 앱입니다. [UX 설계안](../docs/EKS_프런트엔드_UX_설계안.md)과 [DESIGN.md](../docs/DESIGN.md)의 배치·색상·글꼴 원칙을 적용합니다.

## 실행

설치·실행·시험은 저장소 루트에서 수행합니다. Node 24를 사용하며 잠금 파일은 루트 `package-lock.json` 하나로 관리합니다.

```sh
npm ci
npm run data:init
npm run dev
```

초기화는 최초 설치에만 필요합니다. 기존 스키마 1/2 데이터는 서버를 중지한 뒤 `npm run data:migrate`로 이관합니다. 앱 주소는 [http://127.0.0.1:5186](http://127.0.0.1:5186)이며 API는 5187을 사용합니다. 이관·저장·복구·정적 빌드·테스트 명령은 [루트 실행 안내](../README.md)를 참고합니다.

## 가상 계정과 동선

| 사용자 | 역할 | 시작 상태 |
| --- | --- | --- |
| 김민서 | 학습자 | 가상 자격 배정, 첫 과정 객관식 통과·실기 미통과 |
| 박준호 | FT | 김민서의 실기 평가 담당 |
| 오지훈 | FT | FT 변경 검증을 위한 추가 계정 |
| 이서연 | 조직 관리자 | Photo팀 전체 기준·배정·결과·기준 검증·공지 관리 |
| 정하린 | 학습자 | 미배정, 빈 상태 확인 |
| 시스템 운영자 | 시스템 운영자 | 선택 Lv1 인증 업무 관리, 전체 조직·사용자 관리, 진행 초기화 |

모든 초기 계정은 Photo팀 Lv1 직속입니다. 위 진행 상태는 새 설치의 샘플이며 기존 데이터 이관은 현재 진행을 유지합니다. 계정 선택에 Lv1을, 홈·사용자 상세에 전체 소속을 표시합니다. 조직 관리자·학습자·FT를 겸할 수 있으며 각 업무는 소속 Lv1 범위에서 처리합니다.

김민서의 `이어서 진행 → 다시 요청` 후 박준호의 `FT 평가`에서 판정합니다. 남은 과정의 객관식·실기까지 통과하면 검증용 인증이 생성됩니다. 과정의 `학습자료`는 본문과 선택적인 HTTP(S) 링크를 제공합니다.

조직 관리자의 `인증 업무 관리 → 기준 검증`에서 대상 과정을 선택하고 객관식·실기 회차, 관찰 정보, 독립된 근거와 실제 수행 판정을 기록합니다. 같은 Lv1 관리자끼리 공동 관리하며 확정 후에는 정정 사유를 입력해 새 기록을 만들 수 있습니다. 비교 기록은 평가·수료·인증 상태를 바꾸지 않습니다.

`시스템 운영자` 계정의 **시스템 운영** 메뉴에서 조직 트리와 사용자를 관리합니다. 조직은 왼쪽 트리에서 선택하고 오른쪽에서 이름·상위 조직·사용 여부·형제 순서를 수정합니다. 소속은 Lv1→Lv4 연동 선택기로 지정하며 어느 단계에서든 완료할 수 있습니다. 제목 옆 **Lv1 조직 추가**로 생성하고 상세의 **사용자 등록**, **이 조직의 인증 업무 관리**로 이어집니다. 운영자는 계정이나 소속을 바꾸지 않고 선택 Lv1의 기준·배정·비교·공지를 관리합니다. 전체 업무 조회 메뉴는 읽기 전용입니다.

**시스템 운영 → 테스트 관리**에서 특정 Lv1 또는 전체 조직을 선택해 진행 건수를 확인하고 `초기화`를 입력합니다. 조직·조직 이력·소속·역할·기준·과정 운영 상태와 변경 이력·배정·FT·제외·공지는 유지합니다. 조직 관리자 화면에는 초기화 메뉴가 없습니다.

## 관리 대상과 과정 운영

**인증 업무 관리** 상단에서 운영자는 `관리할 Lv1 조직`을 선택합니다. 첫 진입은 미선택이며 이후 같은 탭·계정의 선택과 URL을 유지합니다. 여러 탭은 서로 다른 Lv1을 선택할 수 있습니다. 조직 관리자는 자기 Lv1만 관리합니다. 저장 중 조직·계정 전환을 막으며 미저장 변경이 있으면 저장 후 이동하거나 변경을 버리도록 안내합니다.

과정 상세는 초안의 **초안 삭제**, 게시된 버전의 **운영 종료**, 종료 버전의 **운영 재개**를 제공합니다. 확인창에서 연결된 자격·배정·수료·인증 건수와 처리 사유를 확인합니다. 참조가 있는 초안은 연결을 먼저 정리해야 합니다. 기본 목록은 초안·운영 중이며 `운영 종료` 또는 `전체 상태` 필터로 지난 버전도 찾습니다.

운영 종료 후에도 기존 배정은 계속 진행하고 인증은 유지합니다. 신규 배정 불가 자격은 원인 과정을 표시하며 자격 상세의 **새 버전**에서 구성을 개정합니다. 종료 과정의 새 버전은 운영 종료 정보를 갖지 않는 초안입니다. 학습자·FT·인증·결과 화면에는 종료 상태를 표시하면서 원래 평가 근거를 보존합니다.

## 상태와 오류 복구

- 계정은 서버 세션과 연결됩니다. 새로고침해도 데이터와 세션을 유지하며 서버 재시작 후에는 계정을 다시 선택합니다.
- 답안과 FT 판정은 입력 후 500ms에 저장합니다. 저장 실패 시 입력을 유지하고 `저장 재시도`를 제공합니다. 다른 창과 충돌하면 `다시 불러오기`로 서버 내용을 확인합니다.
- 최종 제출은 저장을 마친 뒤 처리합니다. 응답이 유실되거나 화면 갱신이 실패해도 같은 요청을 다시 실행해 결과를 복구합니다.
- 정답·문항별 점수·타인 기록의 노출 범위는 서버가 결정합니다. 라우트 가드는 화면 이동을 보조합니다.
- FT 변경은 이전 초안을 이력에 보존하고 새 FT에게 빈 입력을 제공합니다. 검증 제외된 과제는 읽기 전용으로 남습니다.
- FT 결과는 `실기 평가를 확정했습니다.`, `김민서 님이 이 과정을 수료했습니다.`처럼 평가자 관점으로 표시합니다. 학습자의 수료 문구는 학습자 화면에서 유지합니다.
- 다른 탭에서 계정을 전환해도 현재 탭의 세션은 유지합니다. 운영자가 소속·역할을 수정한 경우 조회·쓰기 때 최신 권한을 적용하며 탭에 다시 초점을 맞추면 화면도 갱신됩니다.
- 조직·사용자 수정 충돌은 `다시 불러오기`로 확인합니다. 사용 중지 조직에는 신규 소속·배정을 할 수 없으며 기존 기록은 열람할 수 있습니다.

`src/stores/demo.ts`의 파일명은 기존 화면 호환성을 위해 유지했지만 내용은 API 어댑터입니다. 채점·수료·인증 계산은 서버에서 수행합니다. 입력 중인 답안은 `useAttemptDraft.ts`가 관리합니다.

Recipe Management는 사용자 제공 내용을 보존한 미완성 초안입니다. `재검토`는 문항의 정답 문자열이며 업무 승인 기능이 아닙니다. Inter와 Pretendard는 라이선스에 따라 번들하며 Arcadia는 사용하지 않습니다.

## 화면 검증

Playwright는 서버를 자동 기동하고 테스트마다 별도 임시 업무·조직 JSON을 만듭니다. 1920×900과 1440·768·390px 화면, 키보드 이동, 조직·사용자 등록부터 다른 Lv1의 기준·배정·평가·인증 조회, 역할 변경, 선택 조직 초기화, 여러 탭, 자동 저장·재시작·충돌·실패 복구를 확인합니다. 캡처는 `test-results/`에 저장하며 기존 `docs/preview/`는 시안 단계의 참고 자료입니다.
