# EKS 직무자격인증 프런트엔드

2026-10-19: 밝은 업무형 홈과 40/48px 관리 목록, 오른쪽 사용자 편집 패널을 적용했습니다. `인증 업무 관리 → 기준 일괄 관리`(`/admin/catalog`)에서 Excel 양식/내보내기/가져오기·셀 편집·범위 붙여넣기·변경 비교·초안 저장·일괄 사용 등록을 제공합니다. Tabulator는 해당 경로에서 지연 로딩합니다. 양식과 개정·보존 정책은 [기준 일괄 관리 안내](../docs/CATALOG_WORKBOOK.md), 공통 스타일은 [디자인 정책](../docs/DESIGN.md)를 확인하세요.

1920×900을 기준으로 홈, 자격 취득, FT 평가, 인증 업무 관리, 시스템 운영 화면을 분리한 Vue 3 앱입니다. [UX 설계안](../docs/EKS_프런트엔드_UX_설계안.md)과 [DESIGN.md](../docs/DESIGN.md)의 배치·색상·글꼴 원칙을 적용합니다.

## 실행

설치·실행·시험은 저장소 루트에서 수행합니다. Node 24를 사용하며 잠금 파일은 루트 `package-lock.json` 하나로 관리합니다.

```sh
npm ci
npm run data:init
npm run dev
```

초기화는 최초 설치에만 필요합니다. 기존 스키마 1/2/3 데이터는 서버를 중지한 뒤 `npm run data:migrate`로 이관합니다. 앱 주소는 [http://127.0.0.1:5186](http://127.0.0.1:5186)이며 API는 5187을 사용합니다. 이관·저장·복구·정적 빌드·테스트 명령은 [루트 실행 안내](../README.md)를 참고합니다.

## 가상 계정과 동선

| 사용자 | 역할 | 시작 상태 |
| --- | --- | --- |
| 김민서 | 학습자 | 진행 초기 상태, Photo팀 시험 자격별 계획 작성 가능 |
| 박준호 | FT | 계획 요청 시 지정받아 주관식 채점·실기 평가 |
| 오지훈 | FT | FT 변경 검증을 위한 추가 계정 |
| 이서연 | 조직 관리자 | Photo팀 전체 기준·배정·결과·기준 검증·공지 관리 |
| 정하린 | 학습자 | 미배정, 빈 상태 확인 |
| 시스템 운영자 | 시스템 운영자 | 선택 Lv1 인증 업무 관리, 전체 조직·사용자 관리, 진행 초기화 |

모든 초기 계정은 Photo팀 Lv1 직속입니다. 현재 개발 데이터는 전 조직의 과거 시험 진행을 정리해 계획·배정·학습·평가·인증이 0건입니다. 새 설치도 체험 진행 없이 시작합니다. 계정 선택에 Lv1을, 홈·사용자 상세에 전체 소속을 표시합니다. 조직 관리자·학습자·FT를 겸할 수 있으며 각 업무는 소속 Lv1 범위에서 처리합니다.

이서연이 김민서에게 **계획 수립 요청**을 보내고 박준호를 FT로 지정하면, 김민서는 Photo팀 15종 중 자격 하나를 선택해 5개 과정의 일정·목표를 작성합니다. 학습 완료 기록 후 객관식·주관식·실기를 각각 통과하면 과정 수료, 5개 과정 모두 수료하면 검증용 인증이 생성됩니다. 과정의 `학습자료`는 본문과 선택적인 HTTP(S) 링크를 제공합니다.

조직 관리자의 `인증 업무 관리 → 기준 검증`에서 대상 과정을 선택하고 객관식·주관식·실기 확정 회차, 관찰 정보, 독립된 근거와 실제 수행 판정을 기록합니다. 같은 Lv1 관리자끼리 공동 관리하며 확정 후에는 정정 사유를 입력해 새 기록을 만들 수 있습니다. 비교 기록은 평가·수료·인증 상태를 바꾸지 않습니다.

`시스템 운영자` 계정의 **시스템 운영** 메뉴에서 조직 트리와 사용자를 관리합니다. 조직은 왼쪽 트리에서 선택하고 오른쪽에서 이름·상위 조직·사용 여부·형제 순서를 수정합니다. 소속은 Lv1→Lv4 연동 선택기로 지정하며 어느 단계에서든 완료할 수 있습니다. 제목 옆 **Lv1 조직 추가**로 생성하고 상세의 **사용자 등록**, **이 조직의 인증 업무 관리**로 이어집니다. 운영자는 계정이나 소속을 바꾸지 않고 선택 Lv1의 기준·배정·비교·공지를 관리합니다. 전체 업무 조회 메뉴는 읽기 전용입니다.

**시스템 운영 → 테스트 관리**에서 특정 Lv1 또는 전체 조직을 선택해 진행 건수를 확인하고 `초기화`를 입력합니다. 조직·조직 이력·소속·역할·기준·과정 운영 상태와 변경 이력·계획 요청·개인 계획·일정·목표·배정·FT·제외·공지는 유지합니다. 학습 완료·세 평가 유형·수료/인증·관련 진행 알림은 초기화합니다. 조직 관리자 화면에는 초기화 메뉴가 없습니다.

## 새 개인 인증 흐름

- **관리자:** 자격 관리에서 기본 15종 중 필요한 자격을 가져오거나 새로 만듭니다. 설명·인증기간·필수 과정을 준비하고 사용 등록합니다. 과정은 필요한 학습 항목과 객관식/주관식/실기를 선택하며 문항·합격 기준·채점 근거를 직접 작성합니다. `설정 필요` 항목은 해당 상세에서 보완합니다.
- **Photo팀 시험 기준:** 현재 개발 데이터에 15종 게시 자격·각 5개 고유 과정·총 675개 평가 항목이 있습니다. `[테스트 정답]`, `[테스트 정답 예시]`, `[테스트 통과 기준]`은 프로세스 시험을 위해 문항 끝에 공개한 답입니다. 모든 자격은 취득 후 3년과 만료 90·30·7일 전 알림으로 설정됐습니다. 실제 직무 인증 기준으로 사용하지 않습니다.
- **기준 편집:** 과정의 필수 평가는 화면 폭에 맞춰 배열하고 학습 항목은 항목별 탭에서 편집합니다. 자격 편집에서는 필수 과정 검색과 선택한 과정 우선 표시, 인증기간의 `취득 후 3년` 선택을 제공합니다. 3년 선택만으로 알림 시점을 임의 저장하지 않습니다.
- **대상자·계획:** 계획 요청을 개인별로 보내고 미착수·작성 중·완료·FT 미배정·평가 대기·기한 경과를 찾습니다. 신규 직접 배정은 제공하지 않습니다. 기존 배정의 FT 변경·검증 제외는 유지합니다.
- **학습자 내 계획 (`/plans`):** 자격 선택 → 일정 → 학습 목표 → 최종 확인. `다음`과 상단 단계 탭의 앞으로 이동은 날짜·목표 필수 입력과 저장 성공을 확인하며, 오류 위치로 초점을 옮깁니다. 초안은 자동 저장하고 완료 시 결재 생략 안내와 함께 수강을 생성합니다. 완료된 계획의 일정·목표 변경에는 사유를 입력합니다.
- **학습·평가 (`/qualifications`):** 필수 학습 항목에 완료 내용을 기록하고 각 유형별 평가를 진행합니다. 자료 열람과 학습 완료, 평가 통과, 과정 수료를 구분합니다. FT가 없으면 주관식 제출·실기 요청의 대기 사유를 표시합니다.
- **주관식:** 본인 답안은 `/qualifications/:id/courses/:courseId/subjective`, 지정 FT 채점은 `/evaluations/:id/:courseId/subjective`에서 처리합니다. 제출 후 답안은 고정되고 FT가 점수·비공개 근거·공개 피드백을 확정합니다. 미통과 유형만 다시 응시합니다.
- **FT 평가 (`/evaluations`):** 주관식 채점/실기 평가 필터와 요청일·학습 목표를 확인합니다. 완료 메시지는 대상 학습자를 명시합니다. 다른 FT의 미확정 채점은 새 FT 입력에 합쳐지지 않습니다.
- **보유 자격 (`/qualifications?filter=certified`):** 취득 이력과 현재 유효 여부를 나눠 보여줍니다. 만료·기간 미설정도 인증서 조회가 가능하며 현재 유효 집계에서는 제외합니다.
- **증명서:** `/completions/:id`는 과정 수료증, `/certifications/:assignmentId`는 자격 인증서입니다. 발급번호와 당시 표기를 고정하고 기존 기록은 이관 시 확보한 정보임을 표시합니다. 모두 MVP 검증용 화면이며 PDF 발급은 제공하지 않습니다.
- **알림함 (`/notifications`):** 계획 요청·평가·수료/인증·만료 안내를 열고 읽음 처리합니다. 읽음은 계획·평가 상태를 바꾸지 않습니다.

새 기능 시험은 Photo팀 15종의 공개 기준을 김민서·정하린 또는 신규 학습자가 계획하는 흐름으로 진행합니다. 다른 조직에는 기준을 자동 복제하지 않습니다. 과정 학습·평가 내용과 기간은 시험용이며 현장의 직무 기준으로 해석하지 않습니다.

## 관리 대상과 과정 운영

**인증 업무 관리** 상단에서 운영자는 `관리할 Lv1 조직`을 선택합니다. 첫 진입은 미선택이며 이후 같은 탭·계정의 선택과 URL을 유지합니다. 여러 탭은 서로 다른 Lv1을 선택할 수 있습니다. 조직 관리자는 자기 Lv1만 관리합니다. 저장 중 조직·계정 전환을 막으며 미저장 변경이 있으면 저장 후 이동하거나 변경을 버리도록 안내합니다.

과정 상세는 초안의 **초안 삭제**, 게시된 버전의 **운영 종료**, 종료 버전의 **운영 재개**를 제공합니다. 확인창에서 연결된 자격·배정·수료·인증 건수와 처리 사유를 확인합니다. 참조가 있는 초안은 연결을 먼저 정리해야 합니다. 기본 목록은 초안·운영 중이며 `운영 종료` 또는 `전체 상태` 필터로 지난 버전도 찾습니다.

운영 종료 후에도 기존 배정은 계속 진행하고 인증은 유지합니다. 신규 배정 불가 자격은 원인 과정을 표시하며 자격 상세의 **새 버전**에서 구성을 개정합니다. 종료 과정의 새 버전은 운영 종료 정보를 갖지 않는 초안입니다. 학습자·FT·인증·결과 화면에는 종료 상태를 표시하면서 원래 평가 근거를 보존합니다.

## 상태와 오류 복구

[DESIGN.md](../docs/DESIGN.md)가 유일한 스타일 기준입니다. 화면 테마 선택과 다크 초기 적용을 제거하고 따뜻한 바탕·흰 패널의 단일 밝은 스타일을 사용합니다. 일반 화면·개별 편집 최대 1280px, 관리 목록·Excel 표 최대 1760px입니다. 과정의 학습 탭에는 번호·이름만 표시하고 평가 기준은 유형 탭→문항 탭→한 문항 편집으로 연결합니다. 선택지 정답은 라디오로 선택하며, 선택지 삭제 시 정답 인덱스와 Excel 1부터 시작하는 번호 변환을 보존합니다.

신규 계획은 KST 오늘+7일 시작, 시작+21일 완료·+28일 평가로 생성합니다. 기존 미확정 계획은 빈 날짜만 최초 한 번 채웁니다. 지운 날짜나 입력한 값은 이후 자동 변경하지 않습니다. `내 계획`에서 본인 초안을 삭제할 수 있고 요청·읽음 상태·감사 이력은 유지합니다. 다른 탭에서 삭제된 계획은 자동 저장을 멈추고 내 계획 이동을 안내합니다.

- 계정은 서버 세션과 연결됩니다. 새로고침해도 데이터와 세션을 유지하며 서버 재시작 후에는 계정을 다시 선택합니다.
- 답안과 FT 판정은 입력 후 500ms에 저장합니다. 저장 실패 시 입력을 유지하고 `저장 재시도`를 제공합니다. 다른 창과 충돌하면 `다시 불러오기`로 서버 내용을 확인합니다.
- 최종 제출은 저장을 마친 뒤 처리합니다. 응답이 유실되거나 화면 갱신이 실패해도 같은 요청을 다시 실행해 결과를 복구합니다.
- 정답·문항별 점수·타인 기록의 노출 범위는 서버가 결정합니다. 라우트 가드는 화면 이동을 보조합니다.
- FT 변경은 이전 초안을 이력에 보존하고 새 FT에게 빈 입력을 제공합니다. 검증 제외된 과제는 읽기 전용으로 남습니다.
- FT 결과는 `실기 평가를 확정했습니다.`, `김민서 님이 이 과정을 수료했습니다.`처럼 평가자 관점으로 표시합니다. 학습자의 수료 문구는 학습자 화면에서 유지합니다.
- 다른 탭에서 계정을 전환해도 현재 탭의 세션은 유지합니다. 운영자가 소속·역할을 수정한 경우 조회·쓰기 때 최신 권한을 적용하며 탭에 다시 초점을 맞추면 화면도 갱신됩니다.
- 조직·사용자 수정 충돌은 `다시 불러오기`로 확인합니다. 사용 중지 조직에는 신규 소속·배정을 할 수 없으며 기존 기록은 열람할 수 있습니다.

`src/stores/demo.ts`의 파일명은 기존 화면 호환성을 위해 유지했지만 내용은 API 어댑터입니다. 채점·수료·인증 계산은 서버에서 수행합니다. 객관식·실기 입력은 `useAttemptDraft.ts`, 개인 계획·주관식 답안·채점은 `useSavedDraft.ts`가 관리합니다.

과거 `Recipe Management`와 `평가 흐름 체험` 기준·과정은 현재 개발 데이터에서 정리했고 자동화 회귀 시험용 fixture로만 남겼습니다. Inter와 Pretendard는 라이선스에 따라 번들하며 Arcadia는 사용하지 않습니다.

## 기준 일괄 관리의 사용자 중심 편집

`/admin/catalog`은 자격 목록에서 작업할 기준을 먼저 선택합니다. 왼쪽 자격·과정 탐색과 검토 화면의 적용 대상 선택을 분리했습니다. 오른쪽의 과정 정보·학습 항목·객관식·주관식·실기에서 이름과 한글 선택값으로 작성하고, 새 항목은 선택 과정에 연결됩니다. 여러 과정을 함께 편집할 때만 `전체 과정 표 보기`로 전환합니다.

행 선택을 해야 복제·제외할 수 있습니다. 과정 복제는 연결된 항목까지 독립 사본으로 만들며 제외는 건수 확인 후 진행합니다. 오류는 자격·과정·문항·입력칸으로 안내하고 해당 위치로 이동합니다. 기본정보·문항 상세에서도 오류를 입력 근처에 표시합니다.

500ms 브라우저 자동 보관과 서버 초안 저장을 구분합니다. 검토에서 선택한 기준만 저장·사용 등록하며 다른 입력과 편집 위치를 유지합니다. IndexedDB 복구는 계정·Lv1·작업별이고 활성 탭의 복구 기록을 덮어쓰지 않습니다. 미확인 저장 요청은 재시도 버튼으로 결과를 확인합니다. 자세한 v2 Excel/복구 정책은 [사용 안내](../docs/CATALOG_WORKBOOK.md)를 따릅니다.

## 최신 화면 검증

Playwright는 서버를 자동 기동하고 테스트마다 별도 임시 업무·조직 JSON을 만듭니다. 1920×900과 1440·768·390px 화면, 키보드 이동, 조직·사용자 등록부터 다른 Lv1의 기준·배정·평가·인증 조회, 역할 변경, 선택 조직 초기화, 여러 탭, 자동 저장·재시작·충돌·실패 복구를 확인합니다. 캡처는 `test-results/`에 저장하며 기존 `docs/preview/`는 시안 단계의 참고 자료입니다.
