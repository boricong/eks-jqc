# EKS 직무자격인증 프런트엔드 시안

1920×900을 기준으로 홈, 자격 취득, FT 평가, 관리 화면을 검토하는 Vue 3 시안입니다. [UX 설계안](../docs/EKS_프런트엔드_UX_설계안.md)에 화면 구성과 후속 서버 연동 범위를 정리했습니다.

## 실행

Node 24 LTS를 프로젝트 권장 런타임으로 사용합니다. 이번 환경에서는 Node 25.6.1과 npm 11.9.0으로 확인했습니다.

```sh
cd /Users/bori/Workspace/eks-jqc/frontend
npm ci
npm run dev
```

로컬 주소는 `http://127.0.0.1:5186/`입니다. 해당 포트가 사용 중이면 `npm run dev -- --port 5187`처럼 명시적으로 지정합니다.

```sh
npm run typecheck
npm run build
npm run test:e2e
```

브라우저 시험은 개발 서버가 실행 중인 상태에서 수행합니다. 현재 Playwright 설정은 macOS에 설치된 Google Chrome을 사용합니다. 다른 환경에서는 `playwright.config.ts`의 실행 파일 경로를 조정하거나 Playwright Chromium을 설치해 `executablePath`를 제거합니다.

## 화면 확인

상단 접속 계정에서 가상의 사용자를 전환합니다.

| 사용자 | 역할 | 시작 상태 |
| --- | --- | --- |
| 김민서 | 학습자 | 가상 자격 배정, 첫 과정 객관식 통과·실기 미통과 |
| 박준호 | FT | 김민서의 실기 평가 담당 |
| 이서연 | 운영자 | 기준·배정·결과·공지 관리 |
| 정하린 | 학습자 | 미배정, 빈 상태 확인 |

김민서로 `이어서 진행 → 다시 요청`을 실행하고 박준호로 전환하면 FT 평가에 요청이 표시됩니다. 남은 과정의 객관식·실기까지 통과하면 검증용 인증 화면이 연결됩니다. 자료는 각 과정의 `학습자료`에서 확인할 수 있습니다.

Recipe Management는 미완성 초안입니다. 미정인 정답과 선택지, 실기 항목을 임의로 보완하지 않았습니다. `평가 흐름 체험`은 화면 검증만을 위한 별도의 가상 자격입니다.

## 데이터와 구현 경계

- 초기 데이터는 `src/data/demo.json`에 있습니다. DB를 사용하지 않습니다.
- 변경은 Pinia 메모리에만 유지됩니다. 경로 이동과 역할 전환에서는 유지되고 새로고침하면 초기화됩니다.
- 계정 선택과 경로 제한은 화면 시연용이며 인증·인가 서버가 아닙니다.
- 가상 정답도 프런트엔드 예제에 포함되어 있습니다. 실제 평가의 정답은 이후 Fastify 서버로 이동하고 학습자 응답 DTO에서 제외해야 합니다.
- 최종 제출, 채점, 수료·인증 계산은 현재 화면 흐름을 재현하는 모의 동작입니다. 파일 영속 저장, 동시성, 요청 중복 방지, 감사 이력은 아직 연결하지 않았습니다.
- 현재 시안은 학습자료 본문을 대화상자로 표시합니다. 실제 자료 링크 연결은 서버 연동 단계에 포함합니다.
- Inter와 Pretendard는 패키지에서 함께 제공하는 라이선스에 따라 번들됩니다. Arcadia 글꼴은 사용하지 않습니다.

프런트엔드의 `stores/demo.ts`를 API 어댑터로 교체하는 것이 다음 구현 단계입니다. 화면 구성요소는 그 이후에도 사용할 수 있도록 페이지와 공통 컴포넌트로 나눴습니다.
