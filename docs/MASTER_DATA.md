# 설정·기준 보존 초기화와 서버 이전

현재 형식은 업무24·조직4·JSON14다. Auditor 등급·선행 일반 기본자격과 팀 등록 근거를 포함한다. JSON1~13은 원본 검증 후 변환하며, 새 관계를 구형 파일로 위장할 수 없다. `data:migrate-auditor-pool`은 등급 추정 없이 schema·전체 revision·감사만 변경한다. [Auditor 풀 계약](AUDITOR_POOL.md)을 우선한다.

## 현행 조직 필요자격 형식

업무23·조직4·JSON13은 `organizationQualificationRequirements`를 설정·기준 파일과 보존 초기화에 포함한다. 조직별 지정 계보·revision·수정자/시각을 보존하며 요청 스냅샷·종료 이력은 진행 데이터로 제외한다. JSON1~12는 원본 검증 후 새 지정이 빈 목록으로 변환되고 과거 폐지 필수 지정은 되살리지 않는다. 업무22의 명시 이관은 빈 목록·전체 revision·이관 감사만 추가한다. [조직 필요자격 계약과 반영 절차](ORGANIZATION_REQUIREMENTS.md)를 우선한다. 이하 과거 단계의 “현행” 버전 표기는 당시 계약이다.

## 현행 — 주관식 답변 수집 (2026-10-26)

현행 형식은 **업무22·조직4·기본정보 JSON12**다. Auditee 공통 원본·팀 인증Set의 `subjectiveEnabled`와 `subjectiveQuestions`를 내보내며 개인 `subjectiveResponses`는 제외한다. JSON1~11은 원본 체크섬·건수·참조를 먼저 검사하고 주관식 비활성/빈 문항으로 변환한다. 구형 형식에 새 주관식 내용을 넣어 우회하면 거부한다. JSON12도 폐지된 조직 필수 설정·채점 필드를 허용하지 않는다.

- 주관식 문항 수는 기본정보 검사 요약에, 답변 기록 수는 진행 초기화/삭제 보존 검사에 포함한다. 기준 보존 초기화는 문항을 유지하고 답변·관련 영수증은 진행 데이터로 정리한다.
- 파일 최대 크기는64MiB다. 500문항·문항/답변별20,000자 제한을 유지하며 개인 답변을 기본정보 백업으로 옮기지 않는다.
- 업무21은 `data:migrate-subjective`로 명시 이관한다. 기존 원본/사본에 비활성·빈 문항과 업무 상태에 빈 답변 목록만 더하며 기존 완료 근거·공통 기준 해시를 보존한다. 자동 이관하지 않는다.
- 백업·해시·동시성·복구와 API/화면 계약은 [SUBJECTIVE_RESPONSES.md](SUBJECTIVE_RESPONSES.md)를 따른다.

## 조직별 필수자격 종료·선택형 계획 (2026-10-26)

이 단계의 형식은 **업무21·조직4·기본정보 JSON11**이며 현재는 아래 정책을 유지해 업무22·JSON12로 확장했다. 조직별 필수 설정과 충족 판정·통계는 제거한다. 조직 설명·담당 업무·세부 관리자 권한과 Auditee의 관리자 요청 후 선택, 최소1개 계획/추가 대상 없음의 기존 완료 조건을 유지한다. Auditor 자체 학습·일반/메인 인증, 인증Set 내부 필수 항목은 변경하지 않는다.

- 화면은 `/admin/organization-settings`이며 예전 `/admin/policies`는 조직 맥락을 유지해 이동한다. 새 조직 정보 API는 `GET /api/organization-settings`, `PUT /api/organization-settings/:id`와 `/:id/administrators` GET/PUT이다. 조직 정보 입력은 revision·description·duties, 출력은 저장 ID·새 revision이다. 관리자 입력/권한은 기존과 같다. 소속/권한 변경은403, revision 충돌은409, 폐지 필드·잘못된 입력은422로 보류한다. 실패 시 입력을 유지하고 재검토/재시도한다.
- 이전 `/api/organization-policies` 계열과 `/api/me/required-qualifications`는 인증·관리 범위 검사 후410 `FEATURE_REMOVED`로 종료한다. 구형 본문을 파싱하거나 저장 영수증으로 실행하지 않는다. 현황의 폐지 필수 지표·차트·필터·충족률 정렬도410이다. 브라우저의 이전 주소 조건은 정리하고 조직·유형·유효 조건을 유지한다.
- `npm run data:migrate-remove-required-qualifications -- --dry-run`으로 업무20·조직3을 미리본다. 서버 종료→업무·조직·maintenance 및 호환 소스 백업→`--apply --expected-revision=N --expected-sha256=STATE_SHA256 --organization-sha256=ORG_SHA256`→동일 설정 재시작 순서로 반영한다. 일반 서버 시작은 자동 이관하지 않는다.
- 조직 필수 목록은 운영 구조에서 제거하고 원문을 조직 감사에 보존한다. 요청 대상 스냅샷은 선택 목록으로 통합하고 원문/변환 결과를 업무 감사에 보존한다. 미완료 요청은 선택형·새 revision으로 바꾸며 이미 있는 계획의 제외 제한을 유지한다. 완료 근거·계획·배정·학습·평가·수료·인증은 초기화하지 않는다. 과거 정책 수정 번호는 보존 정보다.
- 재실행은 무변경이고 해시/revision 충돌·부분 스키마 쌍은 보류한다. 파일 교체 실패 시 원본 쌍과 maintenance를 복구한다. 복구에는 제거 전 업무20 호환 코드·의존성과 세 원본을 함께 사용한다.
- JSON1~10은 원본 형식·체크섬·건수·참조를 검사한 뒤 호환 변환한다. 파일 검사에는 제외하는 조직 필수 지정 건수를 안내하며 해당 설정을 다시 활성화하지 않는다. JSON11의 폐지 필드는 거부한다. 설정 보존 초기화·JSON 이전에는 현행 조직 정보·관리자·팀 기준과 공통/특화 정보를 보존한다.

이하 날짜별 스키마 설명은 당시의 변경·복구 근거다. 종료 전 조직 필수 및 Excel 사용 설명은 과거 기록이며 위 현행 계약을 우선한다.

2026-10-26 · 업무 스키마 20 · 조직 스키마 3 · 이전 파일 형식 10

현재 운영 형식은 Auditor 자율 학습·일반/메인 인증, 최신 기준 자동 사용과 Auditee Ready 등록을 포함한다. 아래 업무13~18 설명은 해당 단계의 변경 근거이며, 구형 명시적 이관 명령은 최종적으로 업무24까지 연결한다.

## 엑셀·기준 일괄 편집 종료 (2026-10-26)

엑셀/일괄 편집은 제거했고 설정·기준 JSON10 내보내기·가져오기·보존 초기화는 유지한다. 업무20·조직3과 과거 일괄 이력/영수증을 변경하지 않으므로 이번 종료에는 이관이 없다. 아래 이전 형식의 Excel/일괄 설명은 과거 계약의 기록이며 현재 사용 절차가 아니다.

## 공통인증Set 보존 — 업무20·JSON10

시스템 공통 원본·기본자격 기본 목록·팀 사본 분류/출처·등록 당시 허용 범위를 내보내기·가져오기·기준 보존 초기화에 포함한다. JSON1~9 읽기 호환을 유지한다. 기존 팀 자격에는 공통 목록을 추가하지 않으며 기존 인증Set은 특화로 분류한다. 업무19는 정상 시작에서 거부하고 `data:migrate-common-courses`로 명시 이관한다. 서버 중지·업무/조직/maintenance 백업·해시 확인·이관·동일 설정 재시작 순서를 따른다. 상세 계약과 복구는 [공통인증Set 설계·운영](COMMON_COURSES.md)을 따른다.

## Auditee 최초 등록 — 업무19·JSON9

- 번호 부여 이력이 없는 Auditee 계보의 최초 등록은 `version: null`, `lifecycleStatus: Ready`이다. 표시 버전은 `—`, 상태는 `Ready · 대기`이며 조직 필수 지정과 개인 계획 후보에서 제외한다. 기존 미설정 v1을 포함해 이미 번호가 있는 기록은 그대로 보존한다.
- 기간·인증Set 연결·갱신 설정을 실제 변경해 저장하면 같은 ID의 revision을 올리고 v1·Active로 전환한다. 미완성 저장도 허용하며 신규 진행에는 기존 준비 검사를 적용한다. 무변경 저장·공통 명칭/설명 수정은 Ready를 유지한다. 상태 변경/버전 복제로 최초 설정을 우회할 수 없다.
- 개별 최초 저장은 기존 판정을 사용한다. 삭제한 Ready는 보존하고 재등록은 번호를 소비하지 않는다. 번호 이력이 있는 계보의 재등록은 기존 최대 번호 다음을 사용한다. Auditor·인증Set 및 개인 인증 효력의 버전/상태 계약은 유지한다.
- JSON9은 null 버전을 포함한다. JSON1~8은 원본 해시·건수·형식을 검사해 명시적으로 호환 변환하며 구형 형식의 Ready는 거부한다. 기준만 남기는 초기화도 Ready와 사용자 지정을 보존한다.
- `npm run data:migrate-ready-qualifications`로 업무18→19를 미리보기한다. 서버 중지와 업무·조직·maintenance 세 파일 백업/해시 확인 후 `--apply --expected-revision=<revision> --expected-sha256=<업무 SHA256> --organization-sha256=<조직 SHA256>`을 사용한다. 정상 시작은 자동 이관하지 않는다. 실패 시 백업 세 파일과 업무18 호환 코드를 함께 복원한다. 기존 번호·기준·확정 기록은 재작성하지 않는다.

## 최신 기준 자동 사용 — 업무18·조직3

- 자격 설명은 선택 항목이다. 팀에 등록된 계보별 삭제되지 않은 최고 버전을 신규 계획·학습·갱신에 사용한다. 최신 버전이 미완성/Hold/Revoke이면 신규 진행을 보류하며 이전 준비 완료 버전으로 우회하지 않는다. 확정 계획·배정·인증은 당시 근거를 유지한다.
- `qualificationPools`는 운영 저장 구조에서 제거한다. 기존 목록은 조직 이관 감사의 원문과 백업에 남긴다. Auditor 설정은 등급별 `templateId`·`entityId`로 계보만 연결하며 현재 버전은 계산한다.
- 마지막 버전 삭제는 영향 확인 후 현재 조직의 해당 필수 지정도 함께 해제한다. 업무·조직 파일을 동일 대기열에서 저장하고 `.transaction.json`의 원본 쌍으로 실패 및 중단 후 재시작을 복구한다. 응답 유실 재시도에는 최초 삭제 결과를 반환한다. 과거 요청·계획·학습·인증은 보존한다.
- JSON v8은 업무18·조직3을 표현한다. v1~v7의 해시·형식·건수를 먼저 검사한 뒤 명시적으로 호환 변환한다. 설정만 남기는 초기화도 계보와 기준을 보존하며 별도 적용 선택은 만들지 않는다.
- 업무17·조직2는 `npm run data:migrate-automatic-criteria`로 미리보기한다. 서버 중지와 세 파일 백업 후 `--apply --expected-revision=<revision> --expected-sha256=<업무 SHA256> --organization-sha256=<조직 SHA256>`을 사용한다. 정상 기동은 구형 데이터를 자동 이관하지 않는다. 실패 시 세 백업과 호환 코드를 함께 복원한다.

## Auditor 운영 기준 보존 — 업무17

- `auditorPrograms`에 팀별 일반·메인 대표 자격 계보/적용 버전, 설정 revision, 지정 안내문과 revision을 저장한다. 기본자격의 `scope: team`, 소유 Lv1, Auditor 등급은 변경 불가 연결이다. 팀 관리자가 운영 화면에서 기본자격과 자격을 함께 생성한다.
- 사용자 지정 회차와 현재 역할은 설정으로 보존한다. 설정·기준만 남기는 초기화는 팀 운영 기준·안내문·소유 정보도 보존하고 수강·확인·인증·발송 이력을 제거한다. 초기화·이전으로 안내를 자동 발송하지 않는다.
- JSON v7은 업무17·조직2를 표현한다. v1~v6는 기존 유형·진행 초기화 정책에 따라 명시적으로 호환하여 읽는다. 기존 Auditor 인증은 등급을 추정하지 않으며 과거 계획·요청·일정은 업무 파일에서 보존한다.
- 업무16은 `npm run data:migrate-auditor-program -- --dry-run`으로 확인한다. 서버를 중지하고 업무·조직·maintenance 세 파일과 호환 코드를 보관한 후 `--apply --expected-revision=<revision> --expected-sha256=<업무 SHA256> --organization-sha256=<조직 SHA256>`으로 적용한다. 일반 서버 시작은 업무16을 자동 변환하지 않는다.
- 이관은 진행을 초기화하지 않고 스키마·revision·이관 감사만 추가한다. 기존 기본자격은 시스템 소유로, 기존 Auditor 지정은 이관 출처로 표시하며 알림을 보내지 않는다. 백업/원본 교체 실패 시 기존 파일 쌍과 maintenance를 복구하는 공통 유지보수 경로를 사용한다. 최신 실제 실행 결과는 `HANDOVER.md`에 기록한다.

강한 초기화의 현재 설정에는 공통 기본자격 ID·수정 번호·이름·선택 설명·인증 유형, 사용자 역할·소속·세부 관리자 지정·대상자 Hold, 조직 트리·메타정보, 자격의 모든 버전(미완성·삭제 표시 포함)·계보·상태·기간·재인증 정책, 연결되지 않은 인증Set을 포함한 모든 기준·학습 항목·자료·정답이 포함됩니다. 최신 버전은 저장된 계보로 다시 계산합니다. Hold·Revoke·인증Set 운영 종료를 자동 해제하지 않습니다. 기준의 내용·삭제 표시를 보존하고 별도의 변경 이력은 삭제합니다.

평가 기준 검증 기능은 2026-10-24 종료했습니다. 과거 비교 자료는 기존 업무 파일과 백업에 보존하며, 초기화·불러오기 미리보기에는 1건 이상일 때만 `이전 수행 비교 기록(보존 자료)`로 영향 건수를 표시합니다. 기능 종료만으로 자료를 삭제하지 않습니다. 운영자가 별도로 실행하는 기존 초기화/전체 교체의 범위와 백업·복구 절차는 유지합니다.

`보존·삭제 내역 확인` 후 건수를 확인하고 확인창에 **전체 초기화**를 입력합니다. 미리보기는 15분간 유효하며 업무 또는 조직이 바뀌면 다시 확인해야 합니다. 강한 초기화는 업무·조직 파일을 모두 변경하지만 조직 트리와 정책 내용은 유지합니다. 실행 전 영구 백업 쌍을 만들며, 실패 시 원본을 유지하거나 복구합니다.

## 다른 서버로 옮기기

1. 원본 서버에서 `설정·기준 파일 내보내기`를 누릅니다. 원본을 먼저 초기화할 필요는 없습니다.
2. 같은 버전의 앱을 대상 서버에 설치하고 최초 설치일 때만 `npm run data:init`을 실행한 뒤 서버를 시작합니다. 기존 서버에는 초기 설치를 다시 실행하지 않습니다.
3. 대상 서버의 시스템 운영자로 접속해 `설정·기준 JSON 파일`을 선택하고 `파일 검사`를 누릅니다.
4. 현재 서버와 파일의 건수, 삭제할 진행·공지·이력을 확인합니다. 전체 교체 확인창에 **전체 교체**를 입력하고 실행합니다.
5. 완료 후 **파일에 포함된 운영자 계정**을 다시 선택합니다. 팀 자격·조직 정보·관리자 설정을 확인하고 관리자의 새 계획 요청부터 진행합니다.

파일은 `eks-master-YYYY-MM-DD.eksmaster.json`이며 최대 25MB입니다. 형식·스키마·내용 SHA-256·건수·소속·계보·자격/인증Set/조직 정책 참조·운영자 존재 여부를 검사합니다. 미완성 기준도 허용하되 모든 기준에 구조·참조 무결성 검사를 적용합니다. 미지원 형식, 기존 업무 JSON 원본, 진행 데이터가 섞인 파일은 조용히 변환하지 않고 거부합니다. 합치기나 일부 조직만 가져오기는 제공하지 않습니다.

이 파일은 정답과 사용자 정보를 포함하므로 시스템 운영자만 내보내고 불러옵니다. 외부 학습자료의 URL·설명은 보존하지만 EDM·Confluence 계정 권한·외부 본문을 복제하지 않습니다. 서버 코드·환경변수·포트·로그인 세션·브라우저 복구 초안·이전 서버 경로·백업은 포함하지 않습니다. 전체 설정 이전 전용 기능입니다.

## 여러 탭과 응답 유실

완료되면 데이터 세대를 바꾸고 모든 세션을 종료합니다. 이전 탭의 자동 저장·대기 요청은 거부하고 오래된 조회 응답도 적용하지 않습니다. 이 앱의 과거 IndexedDB 복구 초안은 새 세대에서 복원하거나 저장하지 않습니다. 다른 브라우저 설정은 지우지 않습니다.

실행 직후 통신이 끊겨 결과를 받지 못하면 새로고침하고 시스템 운영자 계정을 다시 선택합니다. 같은 탭에 보관한 실행 식별자로 **실제 완료 영수증만 조회**하여 결과를 표시하며 다시 초기화하지 않습니다. 서버 재시작 후에도 영수증과 중복 실행 방지는 유지합니다. 단순 재접속만으로 아직 실행되지 않은 작업을 자동 실행하지 않습니다.

## 저장 위치와 복구

- 영구 사전 백업: `data/backups/state/before-master-reset-*.json` 또는 `before-master-import-*.json`과 `data/backups/organizations/`의 **같은 접미사** 파일.
- 저장소 관리 정보: 업무 JSON 경로 뒤의 `.maintenance.json`. 세대 식별자와 최소 실행 영수증만 저장하며 내보내기·업무 이력에는 포함하지 않습니다. 기존에 없으면 최초 기동 때 만들고, 손상된 파일을 자동 재생성하지 않습니다.
- 중단 표식: 업무 JSON 경로 뒤의 `.replacement.json`. 백업 쌍과 작업 이전 관리 정보 `maintenanceBefore`가 있습니다. 표식이 남으면 일반 기동을 거부합니다.

중간 실패 시 서버가 자동으로 원본 두 파일과 관리 정보를 복구합니다. 복구도 실패한 경우 다음 절차를 따릅니다.

1. 서버를 중지하고 현재 업무·조직·관리 정보·중단 표식을 별도로 보관합니다. 실행 중 파일을 교체하지 않습니다.
2. 종료된 프로세스의 잠금이 남았으면 `npm run data:unlock`을 실행합니다. 실행 중인 서버의 잠금은 해제하지 않습니다.
3. `npm run data:recover-master`를 실행합니다. 별도 저장소는 서버와 동일한 `EKS_DATA_FILE`·`EKS_ORGANIZATIONS_FILE` 환경변수를 지정합니다.
4. 복구 명령은 저장소 두 개를 잠그고 표식의 백업 경로·백업 쌍의 무결성·이전 관리 정보 형식을 검사합니다. 현재 중단된 파일·관리 정보·표식을 `before-master-recovery-*` 사본으로 보관한 뒤 원래 업무·조직과 `maintenanceBefore`를 함께 복원합니다. 모두 성공해야 중단 표식을 제거합니다. 실패하면 표식을 유지하며 원본 백업을 덮어쓰지 않습니다.
5. 서버를 시작하고 세대·사용자·조직·기준과 진행 건수를 확인한 후 새 미리보기부터 실행합니다. 운영자가 파일을 하나씩 임의 복사하는 방법은 사용하지 않습니다.

정상 완료 후 과거 데이터로 되돌릴 때도 같은 백업 쌍을 사용하고 현재 관리 정보를 보관합니다. 복구 뒤 관리 영수증의 세대/데이터 관계를 검토해야 하므로 한 파일만 임의 교체하지 않습니다. 기존 백업은 강한 초기화로 삭제되지 않습니다.

## 업무12 기본자격 호환

기본자격 도입 당시 내보내기는 형식3·업무12·조직2였습니다. 공통 기본자격과 팀 자격 연결을 포함합니다. 삭제된 기준·계보·원래 팀 설명도 유지합니다. 기본자격의 변경 감사는 다른 업무 감사처럼 전체 초기화/서버 이전에는 포함하지 않습니다.

기존 형식1·2/업무10·11은 원본 체크섬·건수·허용 필드를 먼저 검증합니다. 15개 공통 기본자격을 만들고 기존 ID 연결을 검사하며 공통 설명은 임의 승격하지 않습니다. 원래 팀 설명은 기준에 보존합니다. 공통 연결이 누락되거나 같은 팀에서 충돌하면 파일 검사를 중단합니다. 명시적인 연결을 확인한 원본 저장소를 `data:migrate-templates --mapping=...`으로 이관한 후 새 형식으로 내보내세요. 자동 이름 병합은 하지 않습니다. 구형 게시 속성만 제거하며 과거 삭제 표시·ID·정답·내용·상태를 보존합니다.

## 업무13 계획 요청 호환

계획 요청 도입 당시 내보내기는 형식3·업무13·조직2였으며 업무12와 설정·기준 본문 형식은 동일했습니다. 기존 형식3/업무12도 체크섬·건수·참조 검사 후 불러올 수 있습니다. 전체 교체/설정 보존 초기화는 계획 요청과 선택·완료 근거를 다른 진행과 함께 제거하고 조직의 선택적 필수 설정은 보존합니다. 실행 중 업무12 원본의 진행을 보존하려면 초기화/교체가 아닌 `data:migrate-planning`을 사용합니다.

## Auditee·Auditor 유형 보존 이관 (13→14)

인증 유형 원본은 `qualificationTemplates[].qualificationType`이며 값은 `auditee` 또는 `auditor`입니다. 팀 자격과 존재하는 계획/배정/발급 `qualificationMetadata`에 유형을 보존합니다. 역할과는 별개이며 삭제된 팀 등록 이력도 기본자격 유형 변경을 막습니다. 신규 발급 때는 배정 보존 정보를 우선하고, 없는 과거 배정은 연결 자격의 유형을 보존합니다. 타입 불일치·누락·미지원 값은 업무14의 무결성 검사로 차단합니다.

`data:migrate-qualification-types`는 업무13→14 유형 추가 후 아래 인증Set 유형 이관까지 연결해 업무15로 변환하며 현재 업무15는 검사 후 무변경 종료합니다. 기존 기본자격/팀 자격/존재하는 보존 메타데이터에 Auditee를 추가하고 전체 업무 revision과 이관 이력만 늘립니다. 엔티티 ID·버전·개별 revision·계획 일정/목표·답안/점수·발급일/유효기간·조직은 유지합니다. 빈 메타데이터를 새로 만들거나 기준을 추정하지 않습니다. 구형 파일에 예상하지 못한 유형이 있으면 보류합니다. 과거6~12 이관 명령도 기존 단계 후15까지 연결됩니다.

1. 동일 파일의 복사본으로 미리보기와 관련 시험을 수행합니다. 운영 파일 경로를 명시하고 별도 외부 백업에 업무/조직/maintenance 파일을 함께 보관합니다.
2. 개발/API 서버를 정상 종료해 파일 잠금을 해제합니다. 실행 중인 프로세스의 잠금을 강제로 지우지 않습니다.
3. `EKS_DATA_FILE`과 `EKS_ORGANIZATIONS_FILE`을 대상 파일의 절대 경로로 지정합니다. `npm run data:migrate-qualification-types -- --dry-run`으로 대상 건수·업무 revision·업무/조직 SHA256을 확인합니다. 미리보기는 원본을 쓰지 않습니다.
4. 같은 환경에서 `npm run data:migrate-qualification-types -- --apply --expected-revision=N --expected-sha256=STATE_SHA256 --organization-sha256=ORG_SHA256`을 실행합니다. 검토 후 변경·실행 잠금·잘못된 참조는 저장을 보류합니다.
5. CLI가 영구 백업 쌍과 기존 maintenance 백업을 만든 뒤 원자적으로 교체합니다. 교체 실패 시 원본으로 롤백하며 롤백도 실패하면 `.policy-migration.json` 표지를 남겨 혼합 상태 서버 시작을 차단합니다. 표지의 백업 쌍·maintenance를 함께 복구한 뒤 검증해야 합니다.
6. 같은 경로로 서버를 다시 시작하고 health·업무15 읽기·운영자 유형 관리·기존 학습/보유 기록을 확인합니다. 스키마 변경은 데이터 세대를 바꾸므로 브라우저에서 계정을 다시 선택합니다. 유형 이관으로 Auditor 인증을 생성하지 않습니다.

## 인증Set 유형 보존 이관 (14→15)

현재 내보내기는 기본정보 형식5/업무15/조직2, Excel v9입니다. `courses[].qualificationType`은 같은 계보 전체에서 일치해야 하며 연결된 자격과도 같아야 합니다. 과거 형식4는 자격 유형을 유지한 채 인증Set을 연결 근거로 분류합니다. 형식1~3은 기존 자격을 Auditee로 변환한 뒤 동일하게 분류합니다. 형식5의 누락/미지원 유형과 계보·연결 불일치는 거부합니다.

`data:migrate-course-types`는 **업무14→15 명시적 보존 이관**입니다. 자격의 모든 버전(삭제 포함), 계획 일정·정책 보존 정보, 배정의 정책 보존 정보·학습 연결을 입력으로 받아 인증Set 계보별 유형과 대상 ID 목록을 출력합니다. 한 유형에만 사용된 계보는 그 유형, 미사용 계보는 Auditee로 분류합니다. 혼합 유형 계보·누락 참조·기존 유형 충돌은 보류합니다. 이름이나 최신 버전만으로 추정하지 않고 자동 복제·연결 변경을 하지 않습니다.

1. 임시 복사본에서 미리보기/시험을 완료한 뒤 업무·조직·maintenance를 별도 백업합니다.
2. 개발/API 서버를 정상 종료합니다. 대상의 절대 `EKS_DATA_FILE`·`EKS_ORGANIZATIONS_FILE` 환경변수를 지정합니다.
3. `npm run data:migrate-course-types -- --dry-run`의 계보별 분류·수정번호·두 파일 SHA256을 검토합니다. 미리보기/일반 서버 시작은 파일을 바꾸지 않습니다.
4. `npm run data:migrate-course-types -- --apply --expected-revision=N --expected-sha256=STATE_SHA256 --organization-sha256=ORG_SHA256`을 실행합니다. 원본이 바뀌었거나 실행 잠금이 있으면 중단합니다.
5. CLI의 영구 백업 쌍과 maintenance 백업을 보관합니다. ID·계보·자격/인증Set 버전·개별 수정번호·계획/답안/발급 기간·조직은 보존하며 전체 업무 revision과 이관 감사만 증가합니다. 교체 실패 시 원본 복구, 복구 실패 시 `.policy-migration.json`로 시작을 차단하는 기존 보호를 사용합니다. 파일 하나만 교체하지 않습니다.
6. 같은 경로로 재시작해 health·계보/연결 유형·기존 건수를 확인하고 계정을 다시 선택합니다. 재실행은 무변경 종료합니다. 구버전 앱에 업무15/형식5/v9를 강제로 입력하지 않습니다.

인증Set 개별 생성/저장은 `qualificationType`을 받습니다. 기존 생성 호출의 누락은 Auditee, 기존 수정 호출의 누락은 원래 유형입니다. 관리자 workspace는 표시용 `typeEditing: { canChangeType, typeChangeReason }`을 추가로 제공하며 업무 파일에 저장하지 않습니다. 유형 변경 입력은 같은 저장 검토에 전후 값을 표시합니다. 자격 연결(삭제/과거 버전 포함), 계획·배정·평가·수료·과거 비교 참조, 두 번째 버전/부모 버전이 있으면 잠급니다. 검토 후 연결이나 수정이 발생하면 revision 재검사로 보류합니다. 기본자격 등록의 선택적 `qualificationType`은 등록 목록의 기대 유형이며, 검토 이후 기본자격 유형이 바뀌면 등록을 거부합니다. 기존 유형 없는 호출은 이전 등록 동작을 유지합니다.
