# EKS 공통 스타일·테마 보완 정책

확정일: 2026-10-19 · Asia/Seoul

사용자 승인에 따라 [DESIGN.md](DESIGN.md)는 `d6f20b9`의 Mercury Analysis 원문으로 복원한다. 원문을 편집해 EKS 예외를 섞지 않는다. 이 문서가 이전 라이트 전용 `eks-workplace-v1`의 시각 정책을 대체하며 Excel 데이터·개정 정책은 유지한다.

## 공통 형태와 업무 화면 예외

- 본문 400, UI 420, 제목·수치 480, eyebrow 500을 사용한다. Inter Variable·Pretendard Variable을 유지한다. Arcadia 자산은 제공하지 않는다.
- 주요 행동은 40px 높이의 캡슐 버튼, 작은 행동은 32px, 카드 모서리는 12px, 입력·밀집 편집은 8px을 사용한다. 업무 화면의 구분선·입력 경계는 가시성과 오류 위치 구분을 위해 유지한다. 그림자는 약하게 사용한다.
- 역할별 주요 작업/보조 정보 배치, 홈 1440px·관리 1760px, 목록 40/48px·페이지 25/50/100개·고정 열, 사용자 오른쪽 패널, Excel 표 편집을 유지한다. 밀집 표·편집의 12~15px 글자는 업무 화면 예외다.
- 원문의 홈/제품별 색상 분리 대신 사용자가 선택한 팔레트를 앱 전체에 적용한다. 테마에 따라 배치·글자 크기·컴포넌트·저장 상태를 분리하지 않는다.
- 상태 색은 업무 결과에 사용한다. 학습 완료·평가 통과·수료·인증, 채점 대기·실패를 문구와 아이콘으로 구분한다.

`frontend/src/theme.css`가 팔레트의 단일 정의다. `style.css`·`workplace.css`는 의미 토큰을 사용한다. 홈도 같은 토큰을 사용하며 날짜 입력창에는 `color-scheme`을 적용한다. Tabulator의 지연 로딩 CSS보다 구체적인 선택자로 표·선택 범위·셀 편집·선택 목록을 적용한다. 대화상자·알림·오류·토스트도 포함한다.

일반 글자 4.5:1, 큰 글자·필수 조작 경계 3:1 이상을 기준으로 한다. 다크의 링크·초점과 primary 버튼 색을 분리하여 작은 글자와 초점의 대비를 확보한다. 비활성 상태·장식 구분선과 필수 조작 경계를 구분한다. 자동 대비 검사는 전체 접근성 인증을 뜻하지 않는다.

## 선택과 기억

상단 `화면 테마`에서 라이트·다크를 선택한다. 최초 기본값은 라이트이며 OS 자동 모드는 제공하지 않는다.

- 현재 브라우저의 `localStorage` 키 `eks-theme:<사용자 ID>`에 저장한다. 서버 사용자 모델이나 API에는 테마 속성을 추가하지 않는다.
- 계정 전환 시 해당 계정의 설정을 적용한다. `storage` 이벤트는 현재 계정의 키 또는 전체 삭제에만 반응한다. 다른 계정 탭의 설정은 바뀌지 않는다.
- 탭의 `sessionStorage` 키 `eks-theme-actor`는 최초 표시를 위한 마지막 확인 계정 힌트다. 세션 확인 이후 실제 사용자 ID로 다시 적용하며 힌트를 권한으로 사용하지 않는다. 로그인 세션 키는 변경하지 않는다.
- 잘못된 값·저장소 오류는 라이트로 처리한다. 저장할 수 없어도 현재 화면의 전환은 동작한다. 테마 전환은 Workspace 조회·라우트 이동·표 재생성을 일으키지 않는다.

## 일정 편집과 계획 삭제

서버 KST 날짜에 7일을 더해 시작일을 계산하고 시작일부터 21일 후 완료·28일 후 평가로 저장한다. 목표 인증일·목표는 직접 입력한다. 신규 계획의 `scheduleDefaultsAppliedAt`으로 적용 시점을 기록한다.

기존 미확정 계획은 일정 화면 최초 진입 시 `POST /api/plans/:id/schedule-defaults`와 revision으로 빈 날짜만 보완한다. 시작일이 이미 있으면 그 시작일부터 비어 있는 완료·평가일을 계산한다. 입력한 날짜·목표는 유지하며 역전된 날짜는 자동 수정하지 않고 기존 검증에서 안내한다. 적용 후 날짜를 지우거나 시작일을 바꾸면 다시 보완하거나 다른 날짜를 이동하지 않는다.

일정 표는 과정명과 세 날짜를 한 행으로 배치하고 교차 배경·테두리·입력 강조를 사용한다. 태블릿은 제목 아래 세 날짜, 모바일은 세로 입력으로 전환한다. 오류는 입력 아래에 표시하며 첫 오류 초점·앞 단계 검증·500ms 자동 저장을 유지한다.

학습자는 `내 계획`에서 본인 초안만 삭제한다. `DELETE /api/plans/:id`는 최신 역할·Lv1·본인·revision·미확정·배정 미연결을 쓰기 대기열에서 검사한다. 삭제는 `deletedAt`·`deletedBy`와 감사 이력을 보존하고 모든 업무 조회·집계에서 제외한다. 요청과 알림 읽음 상태는 유지하며 같은 자격을 다시 계획할 수 있다. 확정 계획은 삭제할 수 없다.

같은 삭제 요청의 재시도는 최초 결과를 반환한다. 다른 탭의 저장·확정·기본값 적용은 410 `PLAN_DELETED`로 거부하고 자동 저장을 중단한다. 사용자는 삭제 안내에서 `내 계획으로 이동`할 수 있다. 스키마 5의 선택 필드 확장이므로 기존 JSON 일괄 이관·진행 초기화는 하지 않는다.

실제 실행한 검증·백업·서버 적용 결과는 [README](../README.md)와 [handover](../handover.md)에 기록한다.
