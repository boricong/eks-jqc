# Auditor 자격 풀과 지정 안내문 계약

업무24·조직4·기본정보 JSON14. 2026-10-27 변경. 이전 팀 전용 대표 자격 설정은 보존 정보이며 새 운영 자격 선택에는 사용하지 않는다.

## 운영

시스템 운영자가 기본자격 풀에서 Auditor 유형과 일반/메인 등급을 지정한다. 메인은 시스템 일반 기본자격 하나를 선행 조건으로 연결한다. 미완성 저장은 가능하나 팀 등록은 제한된다. 팀 등록 이력 이후 등급·선행 관계는 잠긴다. 등급 없는 이전 기본자격은 연결된 미삭제 팀 자격을 모두 Hold로 만든 뒤 최초 보완한다. 이름으로 등급을 추정하지 않는다.

팀 관리자는 풀에서 자격을 등록하고 공통/특화 인증Set·기간·갱신 기준을 설정한다. 새 자격은 v1·Hold다. 준비 검사를 통과한 자격만 Active로 전환할 수 있다. 현재 계보 기준으로 팀별 Active 일반·메인은 각각 하나다. 교체할 때 기존 자격을 먼저 Hold로 바꾸며 서버는 자동 전환하지 않는다. 이전 버전·기존 학습·인증은 보존된다.

학습자는 계획 요청 없이 실제 운영 자격에서 자율 학습을 시작한다. 메인 최초 시작과 발급에는 지정한 일반 기본자격을 현재 팀에서 취득한 유효 인증이 필요하다. 다른 일반 자격·다른 팀 인증·다른 메인 계보의 취득 이력은 선행 조건을 면제하지 않는다. 일반 인증이 만료·Hold되면 진행과 수료 근거를 보존하고 최초 메인 발급을 보류한다. 조건 회복 후 기존 발급 처리로 이어진다. 같은 팀·자격 계보의 갱신·재취득 및 과거 배정의 당시 선행 계약은 유지한다.

`/admin/auditor`에는 지정 안내문 제목·본문·링크 편집만 제공한다. 저장만으로 발송하지 않는다. 사용자 관리에서 신규 지정할 때 Active 일반 자격의 준비 상태와 안내문을 확인하고 지정·자동 안내를 원자적으로 저장한다. 충돌 시 입력을 유지하고 최신 안내와 비교한다.

## 공개 입력·출력·보류 조건

- 기본자격 생성/수정: `auditorLevel: general | main | null`, `prerequisiteTemplateId: string | null`. 목록은 `auditorCriteriaEditable`, `auditorReadiness`를 반환한다. 유형 불일치·잘못된 선행 참조는422, 등록 후 변경은409다.
- 팀 등록 목록은 등급·선행 ID·보완 사유를 반환한다. 등록은 확인한 기본자격 revision과 공통 원본 revision을 검사한다. 공통 사본 생성과 팀 자격 생성은 기존 단일 트랜잭션을 유지한다.
- 팀 자격의 `auditorCriteria`는 서버가 보존한다. 팀 편집에서 변조할 수 없다. Active 전환은 준비 부족·등급 중복·stale revision을409로 보류한다.
- `GET/PUT /api/auditor-program`: 안내문 중심 `program`과 신규 지정용 `readiness`를 반환한다. PUT은 revision·notice만 받는다. 대표 자격 이름·설명·연결 입력은 허용하지 않는다.
- `/api/auditor-program/qualifications`, `/members`, `/notices/send`는 인증과 팀 관리 권한 확인 후410 `FEATURE_REMOVED`. 이전 영수증을 실행하지 않는다.
- `GET /api/me/auditor`: 자격별 ID·자격/기본자격 revision·이름·등급·선행 이름·시작 가능 여부·보류 사유·학습/인증/갱신을 반환한다.
- `POST /api/me/auditor/starts`: `qualificationId`, `qualificationRevision`, `templateRevision`. `{level}` 시작은410과 새로고침 안내. 쓰기 대기열에서 최신 본인 역할·팀·Hold·revision·선행 조건을 검사하고 같은 팀·계보의 열린 학습 중복을 방지한다.
- 배정에는 등급·선행 기본자격 ID·`criteriaPolicy: pool`을 고정한다. 이전 팀 전용 배정은 기존 계약을 유지한다. 발급은 저장된 배정의 선행 조건을 재검사한다.

## 파일·명시 이관·복구

JSON14는 등급·선행 관계·팀 기준을 포함하고 학습·인증 이력은 제외한다. JSON1~13은 체크섬·원본 형식·참조 검사 후 변환하며 신규 Auditor 관계를 구형 파일로 위장하면 거부한다. 이전 `auditorPrograms.general/main`은 호환 정보로 보존한다.

일반 서버 시작은 업무23을 자동 변경하지 않는다. `npm run data:migrate-auditor-pool -- --dry-run`으로 미리 본 뒤 서버를 정상 종료한다. 최신 업무·조직·maintenance 세 파일과 이전 호환 소스를 함께 백업하고 SHA-256·revision을 기록한다. 명시 이관은 업무 schema24·전체 revision+1·이관 감사 한 건만 추가한다. 기존 ID·개별 revision·진행·인증·등급 없는 기록은 그대로 둔다. 조직 schema4와 바이트는 유지한다. 재실행은 무변경이며 파일 교체 실패는 원본을 복구한다.

보존 대조 후 같은 환경 설정으로 재시작하고 health·화면을 읽기 전용 확인한다. 복구할 때는 서버 중지 후 백업 세 파일과 호환 소스를 함께 복원한다. 이후 새 업무가 생겼다면 이전 백업을 바로 덮어쓰지 말고 추가 보존 검토가 필요하다.

## 검증

서버 테스트는 풀 등록·등급/선행 잠금·Active 충돌·정확한 선행/팀 격리·다른 메인 계보 면제 방지·지정/안내 재시도·학습/발급/갱신·구 API 종료·JSON 왕복·명시 이관/실패/재실행을 다룬다. 브라우저는 안내 편집 충돌·입력 유지·키보드·네 가지 화면 폭과 풀 등록·자율 학습을 검증한다. 실행 결과와 실제 반영 근거는 HANDOVER에 기록한다.
