# 자격별 Excel·웹 표 관리

2026-10-23 · 기본 Excel 양식 `eks-catalog-v7` · v3~v6 읽기 호환 · v1/v2 호환 검사 · 업무 스키마 12

`인증 업무 관리 → 기준 일괄 편집`에서 관리할 Lv1을 선택한다. 조직 관리자는 자기 Lv1에 고정된다. 파일은 자격·인증Set·학습 항목·평가 기준만 포함하며 사용자·조직·개인 진행을 가져오지 않는다.

## v7 구조와 구형 파일

표는 `인증Set / 학습자료 / 학습 항목 / 지식 평가 / 상황 대응 평가`입니다. 인증Set에는 두 평가의 사용 여부와 각각의 합격 기준을 둡니다. 상황 대응 평가를 사용하면 지식 평가도 필수이며 응시 순서는 지식 통과 후 상황 대응입니다. 학습자료 표는 인증Set 연결·자료코드·순서·유형·자료명·본문·URL·설명입니다. 직접 작성은 본문, EDM Link·Confluence·일반 URL은 HTTP(S) 주소를 입력합니다.

지식 표는 문항 분류 없이 질문·선택지·정답·배점, 상황 대응 표는 여기에 상황 설명을 별도로 입력합니다. 두 평가 모두 Excel 정답 번호 1~50과 서버 인덱스 0~49를 변환합니다. 추가 선택지를 손실 없이 보존합니다. 자료·문항의 순서는 표의 순서 열로 관리합니다.

v1/v2 파일의 지식·학습·자료 본문/URL은 변환할 수 있습니다. **주관식 또는 관찰식 실기가 있으면 해당 셀을 안내하고 저장을 차단합니다.** 원본을 보관한 뒤 v7에서 상황 대응 문항을 작성하세요. 폐지된 내용을 조용히 지우거나 자동 추정하지 않습니다. 구형 브라우저 복구 초안도 자동 적용하지 않으며 원본 JSON을 내려받을 수 있습니다.

자격 상단에 `재인증 시작 · 만료 전 개월`을 추가했습니다. 신규 기간제 기준의 기본값은3이며 `재인증 시작 N일 전 알림`(기본7, 0~365일)과 별개입니다. 유효기간별1회이고 0은 시작 당일입니다. `기준 운영 상태 · 참고용`은 내보내기 정보이며 가져오기에서 상태를 변경하지 않습니다. 상태 변경은 자격 관리의 영향 확인·사유 입력으로 처리합니다.

v3~v6는 읽기 호환합니다. 기존 기준을 수정한 파일에 재인증 정책이 없으면 원본의 정책을 유지합니다. 신규 자격의 누락된 사전 알림은7일입니다. 이전 복수 만료 알림은 새 의미로 해석하지 않습니다. 원본과 내용이 같은 파일은 새 버전을 만들지 않습니다. v3의 ‘과정’ 열 이름도 인식하며 v7 출력은 ‘인증Set’으로 표시합니다.

## 공통 정보와 등록 경계

v7은 기본자격 ID·공통 정보 수정 번호를 보존합니다. 이름·영문명·설명은 회색 참고 셀이며 변경하면 해당 위치와 사유를 안내하고 저장을 막습니다. 신규 자격 시트·미등록/타 팀 원본·연결 위조는 거부합니다. 구형 파일도 등록된 팀 자격을 정확히 식별하는 수정만 가능합니다.

공통 정보가 변경되었으면 다시 내보내거나 웹 편집의 `기본정보 수정 → 최신 공통 정보 확인`을 사용합니다. 후자는 작성한 기간·인증Set·문항을 유지합니다. 검토를 다시 수행한 후 저장하며 팀 적용 버전은 바꾸지 않습니다.

## 작성과 적용

1. 자격 목록에서 검색·준비 상태를 확인하고 **작업할 자격을 연다**. 하나를 열면 해당 자격만 불러온다. 여러 자격은 체크한 뒤 함께 편집하거나 내보낸다. 미선택을 전체 선택으로 해석하지 않는다.
2. `팀 자격 설정 → 기본자격에서 등록`을 먼저 수행한다. `Excel 작업 → 선택 자격 내보내기`로 내려받은 파일을 수정한 뒤 `Excel 가져오기`를 사용한다. 파일에는 `작성 안내`, `자격 목록`, 자격별 시트가 만들어진다.
3. 왼쪽에서 자격과 인증Set을 선택하고 오른쪽에서 `인증Set 정보 / 학습자료 / 학습 항목 / 지식 평가 / 상황 대응 평가`를 편집한다. 추가 항목은 선택 인증Set에 자동 연결된다. 자격명·영문명·설명은 읽기 전용 공통 정보이며 인증기간은 `기본정보 수정`에서 작성한다. `취득 후 3년`은 36개월에 대응한다. 정답·합격 기준·상황 설명·알림 시점은 관리자가 직접 결정한다.
4. 여러 인증Set의 내용을 한 번에 다루려면 `전체 인증Set 표 보기`를 연다. 범위 복사·붙여넣기, 실행 취소/다시 실행, 인증Set 필터와 이름 선택을 제공한다. **행 왼쪽 선택 표시**를 해야 복제·제외할 수 있다. 인증Set 복제는 연결된 학습·문항을 독립 사본으로 복사하며, 인증Set 제외는 연결 건수를 확인한 후 함께 제외한다. 취소하면 변경하지 않는다.
5. 입력은 500ms 후 **이 브라우저에만** 자동 보관한다. `변경 검토 후 저장`에서 변경 전후와 저장할 자격을 확인한다. 연결 오류는 저장을 막으며 설명·정답·상황 등 미완성 항목은 위치를 안내한다.
6. `선택 기준 저장`은 선택한 자격·인증Set을 하나의 작업으로 저장한다. 선택하지 않은 자격의 입력은 유지한다. 미완성도 저장하지만 신규 계획·재인증·팀 적용에는 완성된 기준만 사용할 수 있다.
7. 참조된 내용은 새 버전, 참조 없는 내용은 같은 ID의 revision 증가로 보존한다. 무변경은 새 버전을 만들지 않는다. 저장 이후 **팀 적용 버전은 그대로**이며 팀 자격 설정의 팀 적용에서 따로 선택한다. 별도 사용 등록은 없다.
8. 같은 화면에서 계속 편집한다. `변경 이력`에는 저장 결과와 과거 등록 이력을 구분해 표시한다. 서버 반영 전에도 `작업 파일 다운로드`로 내용을 보관할 수 있다.

## 브라우저 자동 보관과 복구

- `이 브라우저에 보관됨`과 `서버 저장됨`은 다르다. 전자는 다른 장치로 공유되지 않으며 브라우저 데이터 삭제 시 사라질 수 있다.
- 다시 방문하면 자격명·작성 시각과 `이어서 작성`·폐기를 제공한다. 사용자·Lv1·작업별 IndexedDB 기록으로 분리하고 여러 탭의 작업을 덮어쓰지 않는다. 다른 탭이 편집 중인 기록을 복원하면 별도 작업 사본으로 다룬다.
- 복원 시 최신 권한·원본 revision을 확인한다. 충돌해도 작성 내용은 보관하며 최신 기준을 다시 확인하거나 작업 파일을 내려받을 수 있다. 저장소 오류는 보관 실패 안내로 표시한다.
- 서버 응답을 받지 못한 저장은 `저장 결과 확인·재시도`로 확인한다. 요청 식별자와 원래 내용을 보관하므로 새로고침 후 재시도해도 버전을 중복 생성하지 않는다. 확인되지 않은 요청이 있으면 다른 내용을 새 저장으로 보내기 전에 결과를 확인한다.
- 계정·조직 이동은 작업별로 분리하며 늦은 응답은 새 화면에 적용하지 않는다. 저장 중에는 전환을 막고, 입력이 남아 있는 이동에서는 보관 상태를 안내한다.

## 시트와 표 규칙

| 영역 | 입력 |
| --- | --- |
| 자격정보 | 신규/개정·한/영 이름·설명·인증기간·개월 수·재인증 시작 개월·재인증 시작 전 알림 일수 |
| 인증Set | 순서·인증Set명·지식/상황 대응 사용 여부·유형별 합격 기준 |
| 학습 항목 | 인증Set명 선택·순서·교육 종류·항목명·필수/선택 |
| 지식 평가 | 인증Set명 선택·순서·문항·선택지·1부터 시작하는 정답 번호·배점 |
| 학습자료 | 인증Set명 선택·순서·유형·자료명·본문·URL·설명 |
| 상황 대응 평가 | 인증Set명 선택·순서·상황 설명·질문·선택지·정답 번호·배점 |

- `EKS_metadata_*`, `EKS_courses_*`, `EKS_learning_*`, `EKS_objective_*`, `EKS_materials_*`, `EKS_practical_*`의 **이름 있는 Excel 표**로 읽는다. 행 번호·시트 이름에 의존하지 않는다. 표의 행을 추가/정렬하고 시트를 복제할 수 있으며, 필수 표와 열 제목은 유지한다.
- 같은 시트의 데이터 표는 폭을 맞췄다. `입력하지 않음` 열은 비워 둔다. 입력 내용이 있으면 무시하지 않고 오류로 안내한다. 연결 정보는 공통 오른쪽의 접힌 관리 열과 접힌 자격 관리 행에 보존한다. 이 열과 원본 정보는 직접 수정하지 않는다.
- 인증Set·문항의 빈 코드는 가져오기 시 생성한다. 새 자격 시트나 독립 자격 복제는 저장할 수 없다. 등록된 팀 자격의 원본 연결과 기본자격 연결을 유지한다. 인증Set·문항 이름이나 순서를 바꿔도 기존 연결 코드는 유지한다.
- 학습·문항의 인증Set명은 선택 목록에서 고른다. 기존 인증Set 이름만 바꾼 경우 원래 연결이 유지된다. 신규 또는 변경한 연결의 인증Set명이 중복되면 대상을 자동 추정하지 않고 오류로 안내한다. 웹에서 번호와 이름으로 인증Set을 지정한 뒤 다시 검사한다.
- 순서·배점·정답·개월 수는 실제 숫자다. 빈 값과 0은 다르다. 입력 셀의 수식은 허용하지 않으며 자격·인증Set·입력칸과 Excel 셀 주소를 안내한다. 단순 재검사로 수식 오류를 없애지 않으므로 해당 입력을 수정해야 한다.
- 두 평가는 기본 선택지 4개를 제공하고 기존 문항에 선택지가 더 있으면 해당 열을 추가한다. 최대 50개까지 보존한다. 중간 빈 선택지를 허용하지 않는다.
- `필수/선택`, `MTC교육/팀 특화 교육/현업 OJT`, `기존 자격 수정`, `미정/기간제/무기한`과 평가별 `사용/미사용`을 한글 드롭다운으로 제공한다. 기존 v1의 영문 값·코드는 읽기 호환한다. 기본 다운로드·수정본·내부 공통 교환 형식은 모두 v7이다.
- 파일 10MB, 자격 100개, 평가 항목 합계 10,000행까지 지원한다. 초과하면 자격별로 나눈다.
- 정답이 포함되므로 해당 Lv1의 관리자만 내보내고 가져올 수 있다.

## 개정과 보존

- 포함한 자격 시트는 완전한 개정안이다. 없어진 인증Set·문항 행은 새 개정안에서 제외한다. 포함하지 않은 자격에는 작업하지 않는다. 필수 표가 사라진 파일은 전체 제외로 취급하지 않는다.
- 인증Set 행을 제외하면서 연결된 학습/평가 행이 남으면 구조 오류다. 웹은 연결 행을 함께 제외할지 확인한다.
- 다른 기준·팀 적용·계획·평가·인증·후속 버전에서 참조한 내용은 변경 시 새 버전으로 보존한다. 미참조 기준은 동일 ID에서 수정한다. 초안/게시 상태는 없다.
- 무변경 재가져오기는 버전을 만들지 않는다. 미완성 저장과 신규 사용 가능 여부는 분리한다.
- 다른 자격의 인증Set을 연결하거나 변경할 때는 독립 사본을 사용한다. 원래 자격의 구성과 과거 근거는 변경하지 않는다.
- 원본 revision 또는 검토 후 업무/조직 revision이 바뀌면 입력을 보존하고 재검토한다. 기존 적용 버전은 자동 변경하지 않는다.
- 저장마다 최신 권한과 Lv1을 쓰기 대기열에서 검사한다. 요청 ID·내용 해시·대상 조직으로 중복을 막고 실행자·파일 해시·결과 ID를 기록한다.
- 적용 전 영구 백업을 생성한다. 백업 실패·검증 실패·저장 실패 시 부분 적용하지 않는다. 조직 마스터는 쓰지 않는다. 진행 초기화도 기준·인증Set 운영 상태·가져오기 배치·기준 변경 이력을 유지한다.

## API

| API | 동작 |
| --- | --- |
| `GET /api/catalog/workbook-template` | 구형 빈 양식 다운로드(새 자격 저장 불가, UI는 선택 내보내기 사용) |
| `POST /api/catalog/workbook-export` | 선택 자격·버전 또는 임시 편집본 XLSX; `view: table`은 같은 교환 형식의 웹 조회 |
| `POST /api/catalog/workbook-preview` | XLSX 바이너리 해석·셀 위치·변경 비교, 업무 저장 없음 |
| `POST /api/catalog/batches/validate` | 웹 교환 데이터 재검증 |
| `POST /api/catalog/batches` | 선택 기준 원자적 저장·최신 workbook 연결/revision 반환 |
| `GET /api/catalog/batches` | 해당 Lv1의 저장·과거 등록 이력 조회 |
| `POST /api/catalog/batches/:id/publish` | 종료: FEATURE_REMOVED(410), 기준 저장 사용 |

관리 요청은 `?lv1OrganizationId=...`를 사용한다. 운영자는 생략할 수 없다. XLSX 업로드는 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` 본문이다. 모든 경로에 기존 탭별 세션을 적용한다. 저장에는 `Idempotency-Key`가 필요하다.

검증 응답은 `rowCode/courseCode/pathLabel`과 업무/조직 revision, 항목별 변경 전후 내용을 제공한다. 새 저장 묶음은 `saved` 상태다. 과거 `draft/partial/published` 배치 이력은 읽을 수 있지만 재등록할 수 없다. 기존 v3~v6 파일은 같은 내부 구조로 정규화하며 누락된 기간 정책은 원본 값을 유지한다.
