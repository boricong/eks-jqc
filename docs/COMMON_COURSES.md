# 공통인증Set 관리와 기본자격 기본 목록

현재 테스트 데이터 로드·전체 초기화는 [테스트 운영 계약](TEST_MANAGEMENT.md)을 따른다. 아래 설정 JSON 이전 형식은 과거 이관/호환 검증 기록이다. 일반 업무·버전·발급 근거와 CLI 백업/복구는 유지한다.

현행 업무28·조직4·JSON15에서 Auditee 공통 내용은 주관식 활성화·문항을 포함한다. 복사 시 문항 ID를 새로 만들고 팀 사본은 독립적으로 수정·버전 보존한다. 비활성/빈 주관식은 기존 내용과 같은 해시로 정규화하므로 이관만으로 `팀 수정`이 생기지 않는다. 답변은 수강별 진행 데이터이며 공통 원본이나 다른 사본에 공유하지 않는다. 주관식 설정 보완 사유는 기존 준비 상태/수료 검사와 별도로 안내한다. [답변 수집 계약](SUBJECTIVE_RESPONSES.md)을 따른다.

2026-10-27 · 업무28 · 조직4 · 기본정보 JSON15

[불변 버전·자동 반영·보류 계약](RELEASE_VERSIONS.md)을 우선 적용한다.

## 관리와 적용 범위

팀 자격의 저장된 조회는 적용된 공통 사본의 정확한 버전만 표시한다. 변경에서는 적용 목록과 추가할 공통/특화 목록을 구분한다. 공통 인증Set 미적용/`자격에서 제거`는 연결만 제외하므로 팀 사본과 과거 근거는 남고 같은 허용 범위에서 다시 적용할 수 있다. 공통 원본 신규 선택·사본 생성은 기존 `commonCourseAdditions`와 자격 저장 트랜잭션을 사용한다. 변경 대화상자의 신규 등록은 **특화인증Set**이며 공통 원본 생성/유형·범위 규칙을 바꾸지 않는다.

시스템 운영자는 **시스템 운영 → 공통인증Set 관리**에서 Auditee/Auditor 유형별 공통 원본을 작성한다. 기본정보·학습 정보·평가 편집을 팀 인증Set과 공유한다. 학습 정보는 교육3종(MTC교육·팀 특화 교육·현업 OJT)과 자료4종(직접 작성·EDM Link·Confluence·일반 URL)의 세로 탭 목록이다. 교육을 먼저 표시하고 구분 안에서 정렬하며 본문을 직접 편집해 인증Set과 함께 저장한다. 미완성 저장은 가능하며 준비 부족을 안내한다.

Auditee는 교육·자료가 없어도 평가 기준이 완성되면 운영할 수 있고 선택 교육만 있는 경우도 허용한다. Auditor도 빈 저장은 가능하지만 신규 운영은 필수 교육1개 이상을 요구하며 본인 확인 수료를 유지한다. 기존 `learningItems`·`materials` 배열과 ID·공통 사본/버전 계약을 유지하므로 학습 정보 UI 통합 자체에는 데이터 이관이 없다. 불변 버전 전환에는 업무25→26 명시 이관이 필요하다.

**기본자격 관리 → 공통인증Set 목록**에서 같은 유형의 운영 중 항목을 선택한다. 0개도 가능하다. 이름·영문명·설명 변경은 연결 팀 자격의 새 마이너를 생성한다. 기본 공통 목록 변경은 이후 새 팀 등록에 적용한다. 완성 원본 내용 변경은 팀 수정 없는 사본에 새 버전으로 전파하며 팀 수정 사본은 비교 후 원본 반영/팀 유지로 처리한다. 원본 유형은 기본자격 연결/팀 등록 이력이 생기면 잠긴다. 운영 종료는 기본 목록 연결 해제 후 가능하고 기존 팀 사본은 영향을 받지 않는다.

팀 자격 등록은 기본자격·공통 원본 수정 번호를 확인한 뒤 자격과 모든 사본을 하나의 트랜잭션으로 생성한다. 각 인증Set·자료·학습항목·문항에는 새 ID를 부여한다. 팀별·자격별 사본은 독립적이다. 기존 팀 자격과 삭제 후 같은 계보 재등록에는 공통 목록을 추가하지 않는다.

## 팀 설정과 개인 화면

팀 자격의 인증Set 선택은 **공통인증Set / 특화인증Set** 구역으로 나뉜다. 기존 팀 사본과 같은 유형의 운영 중 공통 원본을 표시한다. 원본을 선택하고 자격 기준을 저장하면 가장 최근 완성 원본으로 독립 팀 사본을 만들고 연결한다. 기본 목록이 비어 있는 자격도 동일하게 추가할 수 있다. 선택 취소·조회·미리보기는 사본을 만들지 않는다. 완성 버전이 없는 원본은 보완 필요로 표시하며 선택할 수 없다. 다른 자격 사본은 연결할 수 없다. 제외는 자격 연결만 해제하고 다시 선택하면 팀에서 저장한 버전을 사용한다. 원본 반영 보류 목록에서 내용을 비교하고 새 버전 반영 또는 팀 내용 유지를 선택한다.

공통 사본의 내용 수정은 허용하고 수정 후에도 공통 분류를 유지한다. 가져온 당시 내용과 다르면 `팀 수정`을 표시하며 내용을 되돌리면 해제된다. 팀·개인 화면에는 시스템 원본 ID·수정 번호·가져온 시각을 표시하지 않는다. 공통·특화는 이름 접두사가 아닌 배지와 구역으로 구분한다. 학습·평가·수료·발급 역할은 동일하다. 같은 원본에서 생성됐다는 이유로 다른 자격 수료를 인정하지 않는다.

신규 Auditee는 기본 공통 사본이 포함돼도 Ready다. 공통 기본값을 그대로 확정할 때는 **최초 설정 저장 → v1으로 최초 설정 저장**을 명시적으로 선택한다. 인증기간을 지정한 뒤 최초 기준을 저장한다. 미정 또는 유효 개월 누락은 검토/저장에서 거부하고 Ready를 유지한다. 조회는 기준을 변경하지 않는다. 기간/인증Set/갱신 기준을 실제 변경하는 기존 최초 v1 판정도 유지한다. 기간 외 미완성 v1은 저장하되 신규 업무는 준비 검사로 제한한다.

참조된 사본 수정은 새 인증Set 버전, 미참조 수정은 같은 ID의 revision 증가다. 자격 구성 변경은 기존 버전 정책을 사용하고 기존 계획·평가·수료·인증은 당시 근거를 유지한다. 일반 새 버전 생성은 공통 출처를 보존한다.

## 저장 계약

- `State.commonCourses`: 시스템 원본. `CourseContentSchema`의 내용과 ID·revision·운영 상태·작성/수정 근거를 저장한다.
- `QualificationTemplate.defaultCommonCourseIds`: 다음 신규 등록의 기본 원본 목록.
- `Course.category`: `common | specialized`. 공통 사본의 `commonCourseSource`는 원본 ID·revision·기준 내용 SHA256을 내부 보존한다. 해시는 항목 ID·관리 코드를 제외한 이름·유형·학습·평가 내용을 비교한다.
- `Qualification.commonCourseEntityIds`: 해당 자격 버전에 허용된 팀 사본 계보. 직접 추가하면 새 버전에 범위를 누적하며 과거 버전의 범위/연결은 변경하지 않는다. 기존 범위를 제거하거나 다른 자격과 공유할 수 없다.
- 분류·출처·허용 범위는 서버 소유다. 클라이언트는 읽은 값의 유지 외 변경할 수 없다. 같은 팀/유형 검사와 등록 범위 검사를 개별 저장과 기본정보 JSON 검증에 적용한다.

| API                                                    | 입력 / 출력 / 보류                                                                                        |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| `GET /api/system/common-courses`                       | 운영자 전용 원본·준비 상태·사용 개수·감사 조회                                                            |
| `POST /api/system/common-courses`                      | 공통 내용 → 원본·revision·준비 부족 사유. 구조/유형 오류는422                                             |
| `PUT /api/system/common-courses/:id`                   | 내용·revision → 수정 결과. 수정 충돌/운영 종료/유형 잠금은409                                             |
| `GET /api/system/common-courses/:id/usage`             | 연결 기본자격·생성된 팀 버전·유형 잠금 근거                                                               |
| `POST /api/system/common-courses/:id/retire`·`restore` | revision·사유 → 운영 상태. 기본 목록 연결 중 종료는409                                                    |
| 기본자격 저장                                          | 기본 목록·`commonCourseRevisions` 추가. 유형/중복/종료 원본은422, 수정 충돌은409                          |
| 팀 자격 등록                                           | `templateRevisions`·`commonCourseRevisions`로 확인한 기준 검사. 등록과 전체 사본은 원자적 저장            |
| `GET /api/qualifications/:id/common-course-options`    | 팀 관리 권한으로 해당 버전에 허용된 사본의 현재 버전·선택 상태 조회                                       |
| 기존 자격 저장/검토                                    | `confirmInitialConfiguration:true`는 공통 기본값이 있는 Ready의 명시적 최초 확정. 일반 무변경 저장과 구분 |

`GET /api/qualifications/:id/available-common-courses`는 팀 관리 범위 내 자격과 같은 유형의 운영 중 원본 중 아직 해당 자격에 복사하지 않은 항목을 반환한다. 응답은 ID·현재 revision·최신 완성 버전 내용·available이며 원본 편집 권한을 부여하지 않는다.

기존 자격 검토/저장 API에 선택 입력 `commonCourseAdditions: [{id, revision}]`를 추가한다. 최대100개이며 기존 사본을 포함한 범위/연결도100개 이하다. 서버가 원본 유형·운영 상태·중복/이미 등록 여부·revision·완성 버전과 최신 자격/권한을 검사한다. 수정 충돌은409, 불가 원본·범위 위조는422다. 검토는 임시 사본으로 변경 내용/버전 영향을 계산하고, 저장은 사본·자격 새 버전·감사를 원자적으로 반영한다. Ready는 기존 최초 설정, Auditor는 Hold를 유지하는 기존 버전 정책을 따른다. 기본자격 기본 목록과 과거 학습/배정은 변경하지 않는다. 스키마 변경/이관은 없다.

모든 변경은 현재 권한을 쓰기 대기열에서 재확인하고 요청 키·내용 해시·영수증으로 중복 재시도를 보호한다. 미리보기/조회는 변경하지 않는다. 실패 시 부분 적용하지 않으며 입력은 화면에 보존한다.

## 파일과 명시 이관

기본정보 JSON11은 원본·기본 목록·팀 분류/출처·허용 범위를 포함한다. 설정·기준 보존 초기화에서도 유지한다. JSON1~10은 이전 계약의 해시·건수를 검사하고 호환 변환한다.

엑셀과 기준 일괄 편집은 2026-10-26 종료했다. 팀 자격·공통/특화인증Set은 개별 화면에서 편집한다. 현행 업무21·조직4·JSON11에서 과거 일괄 이력·관리 코드는 보존한다.

`npm run data:migrate-common-courses -- --dry-run`은 업무19→20을 미리보기한다. 적용은 서버 중지·업무/조직/maintenance 세 파일과 이전 호환 코드 백업 후 다음 인자를 사용한다.

```sh
npm run data:migrate-common-courses -- --apply --expected-revision=<revision> --expected-sha256=<업무SHA256> --organization-sha256=<조직SHA256>
```

기존 인증Set은 모두 특화로 분류하고 공통 원본·기본 목록·기존 자격의 허용 범위는 비운다. 기존 ID·버전·개인 진행·요청/감사 원문을 재작성하지 않는다. 재실행은 무변경이며 정상 서버 시작은 구형 스키마를 자동 이관하지 않는다. 구형 명시 이관 경로도 업무21까지 연결한다. 실패 복구는 이전 코드와 세 원본을 함께 사용한다.

조직별 필수자격은 종료했으며 공통 기본 목록·공통/특화 분류·인증Set 내부 필수 학습 요건에는 영향을 주지 않는다. 조직 필수 설정의 과거 값은 감사·백업에만 보존한다.
