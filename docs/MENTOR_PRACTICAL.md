# FT 멘토 실기(주관식) 필수 평가

## 적용 범위

일반 자격의 인증Set에 **별도 필수 평가**를 추가한다. 관리자가 개인 수강별 FT 멘토를 지정하고, 학습자가 복수 문항의 수행 답변을 제출하면 지정 멘토가 본인의 `실기 평가` 화면에서 채점한다. 기존 지식·상황 대응 평가와 실기를 모두 통과해야 인증Set을 수료한다. 모든 필수 인증Set 수료 후 기존 규칙에 따라 자격을 발급한다.

- 문항은 1~100개, 문항별 배점은 1~1,000점 정수다. 문항/답변은 각각 최대 20,000자다.
- 실기 합격 기준은 인증Set에 별도로 설정하는 1~100%다. 각 점수는 0~배점 범위에서 소수 둘째 자리까지 입력한다.
- 판정식은 `합산 점수 × 100 >= 총 배점 × 합격 기준`이다. 백분율 표시를 반올림해서 합격시키지 않는다. 예: 총 100점·기준 80%에서 79.99점은 불합격이다.
- 실기만 필수로 설정할 수도 있다. 상황 대응 평가를 함께 쓰는 경우 기존 지식 평가 선행 조건은 유지된다.
- 기존 선택 주관식(`subjectiveEnabled`)은 수료에 영향을 주지 않는다. FT 실기와 별개이며, 과거 선택 주관식 답변을 자동으로 채점 대상으로 전환하지 않는다.
- Auditor, 객관식 재인증 전용 자격, 그룹 실기 전용 인증Set에는 함께 설정할 수 없다. 그룹 공동 판정과 개인 FT 채점은 별도 평가 절차다.

## 화면 사용 순서

1. 팀 사용자 관리 또는 시스템 사용자 관리에서 담당자에게 **FT 멘토** 역할을 부여한다. 학습자·관리자 역할과 겸임할 수 있다. 과거 FT 계정에 자동으로 역할을 복원하지 않는다.
2. 인증Set 설정에서 **실기(주관식) · FT 멘토 평가**를 선택한다. 실기 탭에서 여러 문항, 각 배점, 합격 기준을 저장한다. 문항·배점·합격 기준 개정은 새 메이저 버전이며 기존 수강은 원래 버전을 유지한다.
3. 기존 개인 계획/배정 절차로 수강을 만든다. 관리자는 **인증 업무 관리 → 실기 멘토 배정**에서 개인 수강을 선택해 같은 팀의 활성 FT 멘토를 지정한다. 본인 수강에는 본인을 지정할 수 없다.
4. 학습자는 인증Set 평가의 **실기 답변·평가 결과 보기**에서 시작·답변 저장·제출한다. 모든 문항의 답변이 필요하며 제출 후 수정할 수 없다. 저장 전 이탈은 확인한다.
5. FT 멘토는 헤더 **실기 평가** 또는 FT 멘토 홈에서 본인에게 배정된 수강을 연다. 문항별 점수·피드백·종합 의견을 임시 저장할 수 있다. 학습자의 미제출 답변은 멘토와 관리자에게 공개되지 않는다.
6. **평가 결과 검토**에서 점수 합계, 합격/불합격, 수료·자격 발급 여부를 확인하고 확정한다. 모든 문항을 채점해야 확정할 수 있다. 임시 채점은 학습자/일반 관리자에게 공개하지 않고, 확정 후 답변·점수·피드백을 공개한다.
7. 불합격이면 학습자가 새 차수로 재응시한다. 이전 답변·점수·채점자를 보존한다. 합격한 실기는 재응시하거나 점수를 수정할 수 없다. 다른 필수 평가가 남았으면 그 평가를 계속 진행한다.

멘토 변경은 실기 합격 전까지 가능하다. 변경 사유가 필수이고 이전 담당자 및 임시 채점을 보존한다. 변경 후 새 멘토가 다시 채점한다. 이전 멘토의 채점/확정 권한은 즉시 회수된다. FT 역할 회수·업무 deactive·비활성 소속 등은 진행을 보류하며 관리자가 활성 멘토를 다시 지정해 해결한다. 확정한 과거 결과는 역할 변경 후에도 보존한다.

## 확정 검토 계약

입력: 고정 인증Set 내용 해시·문항/배점/합격 기준, 제출된 문항별 답변, 지정 멘토의 임시 점수, 현재 응시 ID/revision, 최신 멘토 배정·사용자·조직 상태, 검토 토큰.

출력: 실기 합격/불합격과 합산 점수. 합격이고 다른 필수 평가도 충족하면 수료 근거에 실기 응시/채점자/점수/기준을 포함한다. 필요한 자격 발급, 알림, 감사 이력을 같은 저장 트랜잭션에 반영한다.

보류: 미지정/다른 팀/본인 채점/권한 회수, 학습자 또는 멘토의 비활성 상태, 취득 종료/제외/자격 Hold, 답변 또는 점수 누락, 배점 초과, 미제출/확정 완료, 다른 응시 차수/버전, 검토 후 변경. 서버가 현재 상태를 다시 검사하며 화면 표시만 신뢰하지 않는다.

## 데이터·API

- 업무 스키마 **34**, 조직 스키마 **5**, 쓰기 계약 **7**. 업무32/33 읽기를 유지한다. 새 역할·설정·실기 기록은 업무34 명시적 이관 이후만 허용한다.
- `CourseContent.mentorPractical`은 기본값 없는 선택 필드다. 과거 내용에 필드를 자동 삽입하지 않아 기존 해시를 보존한다.
- `mentorAssignments`: 수강당 담당 멘토와 변경 이력. `mentorAttempts`: 차수별 답변, 기준 스냅샷, 임시/확정 채점, 이전 담당자의 임시 채점 이력.
- `Completion.mentorPractical`: 합격 응시 ID, 실제 채점 멘토 ID, 합산 점수, 총 배점, 기준. 기존 선택형 근거와 함께 저장한다.
- `GET /api/mentor-practicals`: FT의 담당 목록. 관리자는 `?management=true&lv1OrganizationId=...`로 팀 수강 및 후보 멘토를 조회한다.
- `GET /api/mentor-practicals/:enrollmentId`: 본인/지정 멘토/팀 관리자/운영자의 상세 조회. 역할별 미제출 답변·미확정 점수 공개 범위를 제한한다.
- `POST .../assign`: `{mentorId, revision, reason}`. revision은 멘토 배정의 버전이며 최초는 0이다.
- `POST .../start`: `{}`. 불합격 후 새 차수를 시작한다.
- `POST .../save`: `{attemptId, revision, answers}`. 전체 답변 초안 저장. 이 경로는 최대 16MiB 본문을 허용한다.
- `POST .../submit`: `{attemptId, revision}`.
- `POST .../grade`: `{attemptId, revision, scores, feedback, comment}`. 점수/피드백의 키는 고정 문항 ID다. 일부 점수만 입력해 임시 저장할 수 있다.
- `POST .../preview`: `{}`. 검토 토큰·보류 사유·점수·판정·수료/발급 예정 여부를 반환한다.
- `POST .../finalize`: `{attemptId, revision, reviewToken}`.
- 모든 쓰기에 `X-EKS-Release-Contract: 7`, 상태 변경에 `Idempotency-Key`가 필요하다. preview는 읽기 검토다. 상태 변경은 기존 직렬 저장·최신 권한 재검사·요청 영수증·파일 교체를 재사용한다. 충돌 시 입력을 보존하고 새 상태를 확인한다. 응답 유실은 동일 키로 재시도해 중복 발급을 막는다.
- 과거 `/assignments/:id/ft`, 기존 수동 채점 API는 계속 폐지 상태다. 새로운 FT 실기 기능에서 재사용하지 않는다.

## 이관 및 배포

프런트엔드와 백엔드는 함께 배포해야 한다. 구형 쓰기 계약6 클라이언트는 새로고침이 필요하다. 코드 구현 과정에서 실제 업무 파일을 이관하거나 실행 서버를 재시작하지 않는다.

1. Node24에서 실행 서버를 중지하고 업무·조직·관리 파일 및 그룹 근거 파일(사용 시)을 백업한다. 코드 버전도 함께 기록한다.
2. 대상 업무 파일을 지정해 dry-run한다. 명령은 원본을 변경하지 않는다.

   ```sh
   EKS_DATA_FILE=/대상/runtime/state.json npm run data:migrate-mentor-practical -- --dry-run
   ```

3. 출력의 `expectedRevision`, `stateHash`, `organizationHash`를 확인하고 동일 파일에 적용한다.

   ```sh
   EKS_DATA_FILE=/대상/runtime/state.json npm run data:migrate-mentor-practical -- \
     --apply --expected-revision=<expectedRevision> \
     --expected-sha256=<stateHash> --organization-sha256=<organizationHash>
   ```

4. 이관은 기존 조건부 이관·사전 백업·실패 복구를 재사용한다. 업무32 또는33을34로 올리고 새 빈 컬렉션과 감사 이력을 추가한다. 과거 과목/동결 기준/수료/인증 및 사용자 역할을 바꾸지 않는다. 재실행은 이미 적용됨으로 보고한다.
5. 그룹 시험환경의 `groupPracticalEnvironment: trial` 표시를 보존한다. 그룹 사용 시 기존 환경 설정도 유지한다. 업무34 그룹 백업 묶음은 업무/조직/관리 JSON과 참조 파일의 해시를 포함하고 기존 `data:restore-group`으로 복구할 수 있다.
6. 시작 후 역할 지정 → 새 인증Set 기준 저장 → 개인 멘토 배정 → 제출/채점/수료를 확인한다. 되돌릴 때는 이관 전 코드와 관련 백업 파일을 함께 복구하며, 이후 생성한 평가 이력이 사라지는 영향을 먼저 확인한다.

현재 계정 선택 기반 신원 확인과 단일 JSON 저장소 구조는 기존 시스템과 같다. 이 기능은 실제 실기 수행의 진위를 자동 검증하거나 외부 통계 분석을 실행하지 않는다. 문항별 수행 내용의 적절성은 지정 FT 멘토가 판단한다. 확정 결과의 사후 정정/무효화는 이번 기능 범위에 포함하지 않는다.
