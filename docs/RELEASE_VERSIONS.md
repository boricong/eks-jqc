현재 테스트 데이터 로드·전체 초기화는 [테스트 운영 계약](TEST_MANAGEMENT.md)을 따른다. 아래 설정 JSON 이전 형식은 과거 이관/호환 검증 기록이다. 일반 업무·버전·발급 근거와 CLI 백업/복구는 유지한다.

현행 업무 스키마는28이다. 상속 예외의 저장·명시 이관은 [조직 필요자격 계약](ORGANIZATION_REQUIREMENTS.md)을 따른다. 이 문서의 업무26은 버전 기능 도입 당시 형식이며 버전 쓰기 계약1은 유지한다. 설정 파일 이전은 종료 상태다.

## 팀 인증Set 목록과 과거 조회 (2026-10-28)

- 인증 업무 관리 → 인증Set 설정 목록은 관리 팀 안에서 계보별 최신 비삭제 내부 순번(version) 한 개만 표시한다. 공통 사본·특화 모두 같은 규칙이며, 최신 선택 후 유형·구분·운영 상태·이름 검색·정렬·페이지를 적용한다. 과거 이름이나 과거 운영 상태가 검색에 맞더라도 대신 표시하지 않는다.
- 최신 삭제 시 남은 최신 비삭제 버전을 표시하고 계보 전체가 삭제되면 목록에서 제외한다. 워크스페이스의 전체 버전·과거 자격/계획/평가/발급 참조는 유지한다.
- 인증Set 상세의 조회 버전 드롭다운은 같은 계보의 저장된 버전을 내부 순번 내림차순으로 보여준다. 각 항목에 표시 버전·저장 당시 이름·최신/과거/삭제 여부를 표기한다. 이전 형식의 삭제 표시 버전이 남아 있으면 읽기 전용 조회할 수 있다. 현재 DELETE로 제거한 미참조 버전은 감사/백업에만 남으며 이번 변경에서 복원하지 않는다.
- 과거 버전을 선택하면 이름/버전을 명시한 과거 버전 조회 확인창에서 조회를 눌러 이동한다. 미저장 입력이 있으면 폐기 안내를 같은 창에 포함하고 한 번만 확인한다. 취소는 현재 선택·내용·입력을 보존하고 선택창으로 초점을 돌린다. 최신 복귀는 추가 과거 확인 없이 이동한다.
- 과거/삭제된 내용은 저장·삭제·운영 상태 변경을 제공하지 않는다. 최신 비삭제 버전은 기존 편집 방식을 유지한다. 저장/검토/선택 중에는 중복 버전 선택을 막고 계정·관리 팀·현재 경로가 달라지면 대기 중 선택을 적용하지 않는다.
- API·저장 스키마·자격 상세 이력·시스템 공통 원본 관리·학습자 화면은 변경하지 않는다. 기존 직접 주소의 과거 읽기 전용과 일반 화면 이탈 보호를 유지한다.

## 버전 규칙

팀 자격 목록은 버전이 있는 자격의 **조회**와 최신 비삭제 자격의 **변경**을 구분한다. `/admin/qualifications/:id`는 저장된 값과 연결된 정확한 인증Set 버전만 표시하며 후보·체크박스·입력을 제공하지 않는다. Active/Hold/Revoke 모두 같은 규칙이다. 버전 없는 Ready는 `/admin/qualifications/:id/edit`의 최초 설정으로 이동한다. 과거·삭제 버전의 편집 주소는 해당 조회로 돌아간다. 변경 저장/무변경 확인은 결과 버전의 조회로 돌아가고 취소·계정/조직 이동·브라우저 종료는 미저장 입력을 보호한다.

변경 화면에서 체크 해제 또는 `자격에서 제거`는 자격의 연결만 제외한다. 인증Set·팀 공통 사본·과거 연결과 학습/인증 근거는 보존하고 후보에서 다시 적용할 수 있다. 연결 계보의 추가·제외는 메이저, 같은 계보의 버전 교체·운영 기준 변경은 기존 마이너 규칙을 따른다.

`POST /api/courses?lv1OrganizationId=...`는 선택 입력 `content: CourseContent`를 받아 전체 내용을 원자적으로 특화인증Set으로 생성한다. 준비 완료 내용은 v1.0, 보완 필요 내용과 이름/유형만 전달하는 생성은 v0.1이다. `content`에 관리 ID·범위·분류를 주입할 수 없고, 바깥 유형을 함께 보내면 내용의 유형과 일치해야 한다. 팀 관리 권한·유형·문항/정답 구조를 검사하며 Auditor의 평가 입력은 거부한다. 저장 실패는 부분 생성하지 않고 동일 요청 키 재시도는 같은 결과를 반환한다.

자격 변경 내 `새 특화인증Set 등록`은 유형을 고정한 기존 내용 편집기를 연다. 재인증은 객관식만 허용한다. 생성 성공 후 새 ID를 부모의 미저장 변경안에 추가하며 자격 저장 전에는 연결하지 않는다. 부모 변경을 취소해도 생성한 인증Set은 팀 목록에 남는다. 응답 유실/최신 조회 실패는 입력을 고정하고 같은 요청으로 결과 확인·재시도한 뒤 이동할 수 있다. 새 리뷰 API/스키마/이관은 추가하지 않으며 자격 저장 검토의 revision·보류·충돌 계약을 유지한다.

자격의 최초 내용은 v1.0이다. 인증Set은 최초 보완 필요 저장을 v0.1로 시작하고 초안 변경마다 v0.2처럼 마이너를 증가시킨다. 처음 준비 완료가 되는 저장은 초안 번호나 문항 변경 여부와 관계없이 v1.0이다. 이후 변경 전 또는 변경 후에 보완 필요이면 문항 변경도 모두 마이너다. 준비 완료끼리의 변경만 아래 문항 기준으로 메이저/마이너를 판정한다. 준비 완료 여부는 기존 공통 운영 검사(courseUseErrors)로 계산한다. Auditor는 필수 교육이 있어야 준비 완료이며 Auditee의 학습 정보는 선택이다.

내용이 달라진 저장마다 새 ID를 만들며 계보 entityId와 내부 양의 정수 순번 version을 유지한다. releaseVersion이 표시 번호이고 revision은 충돌 검사 전용이다. ReleaseVersionSchema는 인증Set 초안의 major=0을 허용하며 저장 스키마28·쓰기 계약1·API 경로/요청 형식을 유지한다. 자격 생성 규칙은 바꾸지 않는다. 기존 저장 버전(이전 정책에서 보완 필요에 부여한 vN.x 포함)과 확정/발급 근거는 재번호하지 않으며 새 내용 저장에 새 정책을 적용한다. 기존 양의 메이저 이력은 v0.x로 되돌리지 않는다. 무변경·실패·동일 요청 키 재시도는 번호를 올리지 않는다. 이전 버전은 읽기 전용이며 상태 변경은 기존 상태 이력으로 구분한다.

| 대상    | 메이저                                                          | 마이너                                                   |
| ------- | --------------------------------------------------------------- | -------------------------------------------------------- |
| 인증Set | 지식·상황 대응 문항의 추가·삭제·순서·상황·질문·선택지·정답·배점 | 이름·교육·자료·주관식·평가 사용 여부·합격 기준 등 나머지 |
| 자격    | 연결 인증Set 계보의 추가·제외·교체                              | 같은 계보의 버전 교체·이름·정책 등 나머지                |

준비 완료끼리의 변경은 비활성 채점 문항도 비교하고 메이저가 있으면 우선한다. 초안/보완 필요는 위 준비 상태 규칙을 먼저 적용한다. 자격에서 선택 순서만 바꾼 저장은 무변경이다. 동일 계보의 여러 버전을 동시에 선택하지 않는다. 교육·자료의 저장 구조와 기존 수료 기록은 유지한다.

취득용 팀 자격의 직접 검토/저장은 인증기간을 필수로 검사한다. `unknown` 또는 기간제의 개월 누락은 `422 QUALIFICATION_VALIDITY_REQUIRED`이며 무변경 저장도 동일하다. 기간제(1~1200개월) 또는 무기한을 지정해야 저장할 수 있다. 화면은 저장을 비활성화하고 사유를 표시하며 API도 같은 검사를 적용한다. 풀 등록 단계의 Ready/Hold와 기존 기록은 유지하고, 재인증 전용 자격은 별도 기간 입력 없이 기존 보유 인증의 정책을 사용한다. 다른 미완성 항목의 보관/신규 사용 검사는 기존 계약을 따른다. 데이터 스키마/이관은 없다.

## 자동 반영과 보류

완성된 팀 인증Set 저장은 연결한 자격 계보의 최신 버전에만 새 인증Set을 연결한 마이너를 생성한다. 미완성 저장은 자체 버전만 보관하고 이전 완성 연결을 유지한다. 이후 완성되면 중간 미완성 버전을 건너뛴다. 자격의 다른 준비 부족·Hold·Revoke를 해제하지 않는다. Ready는 버전 없는 미설정 상태를 유지하고 명시 최초 설정을 기다린다.

시스템 공통 원본 ID는 유지하며 commonCourseReleases에 불변 내용을 저장한다. 공통 사본은 원본 버전 ID·표시 번호·기준 해시를 보존한다. 완성 원본은 팀 수정 없는 최신 사본과 연결 자격에 한 번의 트랜잭션으로 반영한다. 팀 수정은 commonUpdates의 보류 항목으로 남기고 관리 화면에서 원본과 팀 내용을 비교한다. 원본 반영은 새 팀 버전·자격 버전을 만들고, 팀 내용 유지는 현재 내용과 버전을 유지한다. 새 원본이 나오면 다시 검사한다. 제외한 사본을 자격에 재추가하지 않는다. 미완성 원본은 전파하지 않으며 신규 사본은 가장 최근 완성 원본을 사용한다.

기본자격 이름·영문명·설명 변경도 최신 연결 자격의 마이너를 만든다. 기본 공통 목록 변경은 이후 신규 팀 등록에 적용한다. 과거 자격과 확정 업무에는 최신 메타데이터를 덮어씌우지 않는다.

## 검토 API와 오류

- 팀 자격/인증Set의 기존 save-preview와 저장 응답: releaseChange(종류·이전/다음 표시·사유), propagation(자동 반영/보류), stateRevision, organizationRevision. 번호는 서버가 정한다.
- GET /api/courses/:id/versions, /api/qualifications/:id/versions: 관리 팀 범위 안의 계보 버전 목록. 반환 ID를 기존 상세 조회에 사용한다.
- GET /api/system/common-courses/:id/versions: 공통 불변 버전 목록과 내용. 과거 내용은 저장할 수 없다.
- POST /api/system/common-courses/save-preview 및 qualification-templates/save-preview: 입력 id(신규 생략), content. 출력 검토 revision·저장 결과·자동 생성 자격 목록. 실제 저장은 review: {stateRevision, organizationRevision}을 보낸다.
- GET /api/common-course-updates: 선택 팀의 보류 항목과 원본/팀 내용. POST /:id/resolve 입력은 decision(apply/keep), courseId, revision, sourceReleaseId. 출력은 처리 ID·전파 결과다.
- 쓰기 요청은 현재 계약 헤더와 요청 키를 사용한다. 과거 버전 편집, 검토 이후 변경, 권한 변경, 잘못된 참조는 저장을 보류한다. 동시 변경409는 입력을 유지하고 재검토한다. 저장 오류는 부분 전파 없이 롤백한다. 종료한 수동 versions 생성 API는410이다.

## 계획·수료·발급 근거

GET /api/plans/:id/criteria는 이전/현재 자격·인증Set 기준과 criteriaToken을 반환한다. 변경이 있으면 일정·목표를 저장한 채 차이를 보여주고 사용자가 최신 기준 확인·적용을 선택한다. POST /review-criteria는 revision·qualificationId·criteriaToken을 검사한다. POST /complete는 revision·criteriaToken을 쓰기 트랜잭션에서 다시 검사하며 한 번 더 변경되면409다.

확정 시 계획·배정·수강과 frozenCriteria를 함께 저장한다. 고정 묶음에는 자격 ID·표시 번호·내용 해시, 인증Set별 ID·계보·표시 번호·해시, 확정자·시각·적용 경로가 있다. 이름·영문명·설명·정책은 불변 자격과 기존 메타데이터/정책 스냅샷에 보존한다. Auditor 시작과 재인증 시작도 같은 근거를 고정한다. 최신 변경만으로 시작된 절차를 막지 않는다. 명시적 운영 통제와 권한 검사는 유지한다.

학습·문항·채점은 고정 ID를 사용하고 인증서와 수료증은 발급 근거를 표시한다. 상세 내용 좌하단과 인쇄에도 v메이저.마이너를 보조 텍스트로 출력한다. 기존 기록은 당시 보존된 스냅샷을 우선하며 새 기록과 구분되는 migration 출처를 보존한다. 확보하지 못한 과거 원본을 복원했다고 주장하지 않는다.

## 이관·복구

일반 시작은 업무25를 자동 변환하지 않는다. 기존 자격/인증Set vN은 vN.0으로 매핑하며 Ready는 null이다. 공통 현재 원본은 v1.0 기준점으로 추가하고 과거 사본 출처 revision·기준 해시는 유지한다. 기존 스냅샷 차이를 현재 내용으로 합치지 않는다. 연결 누락·상충은 이관을 보류한다. 이관 감사·전체 revision+1 외 기존 업무·ID·연결은 보존하며 재실행은 무변경이다.

JSON15는 모든 내용 버전·공통 이력·출처·보류를 포함한다. 진행 기록은 기존 정책대로 내보내지 않는다. JSON1~14는 원본 체크섬·건수·참조를 검사하고 명시 호환 변환한다. 내보내기/복원 후 같은 버전·연결을 유지한다.

1. 임시 데이터의 서버·브라우저·타입·빌드·포맷 검증.
2. 실제 서버 종료, 업무·조직·maintenance 세 파일과 업무25 호환 코드 백업 및 SHA256 기록.
3. npm run data:migrate-releases -- --dry-run 실행·허용 변경 검토.
4. npm run data:migrate-releases -- --apply --expected-revision=N --expected-sha256=STATE_HASH --organization-sha256=ORG_HASH 실행.
5. 동일 절대 경로/포트 재시작 후 읽기 전용 확인과 세 파일 해시 비교.

실패 시 서버를 중지하고 이전 코드와 세 원본을 함께 복원한다. 진행 초기화는 사용하지 않는다.

## 팀 자격 저장 후 이동 (2026-10-28)

팀 자격 최초 설정·새 내용 버전 저장·무변경 저장 확인을 마치면 선택 팀과 인증 유형을 유지한 팀 자격 설정 목록으로 돌아간다. 저장 실패·충돌은 작성 화면과 입력을 유지한다. 조회/변경 경로 분리와 과거 버전 읽기 전용 정책은 유지한다.
