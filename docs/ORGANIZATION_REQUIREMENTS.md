# 조직 필요자격 상속과 계획 요청

2026-10-27 · 현행 업무27 · 조직4 · 설정 파일 이전 종료

현행 서버는 업무27을 요구한다. 업무26은 아래 상속 예외 명시 이관을 적용한다. 업무25 이전은 기존 공식 이관 명령의 후속 단계를 통해 업무27까지 이관한다. 설정 JSON·Excel 이전은 종료 상태를 유지하며, 아래 업무22→23·JSON13 절차는 최초 도입 당시 기록이다.

## 운영 흐름

1. 팀 관리자가 자격 풀에서 Auditee 자격을 등록하고 인증Set·기간 등 기준을 완성해 Active 상태로 운영한다.
2. `조직 필요자격`에서 조직 트리를 선택해 매핑한다. 팀 자격 상세의 `필요 조직 설정`은 해당 자격을 선택한 매핑 화면으로 이동한다. 팀 관리자는 자기 팀 전체, 시스템 운영자는 선택한 팀, 세부 조직 관리자는 실제 소속 조직 한 곳만 수정한다.
3. 조직에 적용되는 목록은 팀부터 해당 조직까지 순서대로 계산한다. 직접 지정은 추가하고, 상속 제외는 해당 지점까지 누적된 지정 출처 전체를 차단한다. 제외는 모든 하위 조직에 이어지며 더 아래에서 직접 지정하면 그 지점부터 다시 상속한다. 같은 조직·계보에 직접 지정과 제외를 함께 둘 수 없다.
4. 관리자는 `계획 요청·진행`에서 인원을 선택하고 조직별 필요자격·운영 불가 사유·이미 충족한 자격·이전 미완료 요청을 확인한다. 필요자격이 없으면 발송에서 제외한다. 하나라도 운영할 수 없으면 해당 인원 전체를 보류하며, 문제 자격만 자동으로 제외하지 않는다.
5. 새 요청은 발송 당시 소속 경로·필요자격 목록·지정 출처와 경로별 직접/제외 규칙을 고정한다. 제외 사유는 개인 화면·워크스페이스에 노출하지 않는다. 학습자는 목록의 자격별 계획을 수립하며 임의 제외나 목록 밖 추가는 할 수 없다. 이미 유효한 인증·확정 계획·진행 중 배정으로 충족하는 경우 중복 계획을 만들지 않는다. 필요한 계획을 모두 확정해야 요청을 완료한다. 전체가 이미 충족되면 `추가 계획 대상 없음`으로 확인한다.

Auditor의 일반·메인 인증과 학습 확인은 변경하지 않는다. 공통/특화인증Set, 주관식 답변 수집, 기존 평가·수료·인증 계약도 유지한다. 과거 폐지한 필수 충족률·통계나 이전 API를 복구하지 않는다.

## 트리 매핑 화면

- 경로: `/admin/organization-requirements`. `lv1OrganizationId`는 관리 팀, `organizationId`는 선택 조직, `view=organization|qualification`은 보기, `entityId`는 자격별 보기의 선택 계보다. 권한 밖 조직·자격 URL은 허용 범위의 기본 선택으로 처리한다.
- 조직별 보기: 트리의 적용 개수·변경 표시를 보며 조직을 선택한다. 오른쪽에는 적용 자격만 표시하고 `자격 추가`에서 검색·복수 선택한다. 직접 지정과 상속이 겹치면 배지를 함께 표시하며 적용 개수는 중복 없이 센다.
- 자격별 보기: 팀 관리자·선택 팀 시스템 운영자는 자격 하나를 선택하고 조직별 `상위 설정 따름 / 직접 지정 / 상속 제외`를 선택한다. 세부 관리자는 실제 소속 조직의 조직별 보기만 사용한다.
- 상속 배지를 펼치면 지정 출처를 확인한다. 편집 가능한 상위 조직으로 이동할 수 있다. 직접 지정 해제 후 남아 있는 상속 또는 상위 제외를 즉시 표시한다.
- 적용 목록과 `상속 제외` 목록을 나눈다. 제외 목록은 이 조직/상위 조직에서 제외했는지, 현재 상속이 없어 대기 중인지 표시한다. 근거를 펼쳐 지정 출처·제외 조직·사유를 확인한다. 상위 제외를 이 조직에서 없앨 수는 없으며 직접 지정으로 재포함할 수 있다.
- 예외 생성·해제(직접 지정으로 전환 포함)에 사유 1~500자를 받는다. 직접 지정에서 상위 설정 따름으로 바꾸는 일반 해제는 사유 없이 처리한다. 저장한 제외 사유의 수정도 검토·감사 대상이다.
- 보기·조직·검색을 바꿔도 여러 조직의 미저장 변경을 유지한다. `변경 확인` 후 모든 변경을 한 번에 저장한다. 다른 페이지·팀·계정 이동과 새로고침은 미저장 보호를 적용한다. 데이터 교체 시 이전 초안을 폐기한다.
- 검토는 직접 지정의 추가/해제, 실제 적용 목록의 추가/해제, 목록은 같고 지정 출처만 달라진 경우와 제외 근거만 달라진 경우를 구분한다. 구성원 수는 적용 목록이 달라지는 활성 조직의 고유 사용자 수다. 출처·예외 근거만 바뀐 조직은 인원 집계에서 제외하며, 신규 계획 대상자 수를 뜻하지 않는다. 세부 관리자에게는 자기 조직의 검토 결과만 공개한다.
- 저장 충돌 시 조직·계보별 변경 의도를 최신 기준과 대조한다. 서로 다른 항목은 합치고, 같은 항목의 상태·사유가 다르면 `내 변경 / 최신 설정`을 명시적으로 선택한 뒤 재검토한다. 최신 예외를 내 변경으로 해제할 때도 해제 사유가 필요하다. 다른 관리자가 추가한 무관한 지정은 유지한다. 응답 유실은 같은 요청 키로 재시도하고, 저장 성공 후 조회만 실패하면 조회만 재시도한다.
- Hold·준비 미완성으로 바뀐 기존 지정은 남겨 두고 요청 보류 사유를 펼쳐 확인한다. 신규 추가는 운영 가능한 Active Auditee만 허용한다.
- `조직 정보·관리자`는 조직 설명·업무·관리자만 관리하며 선택 조직의 매핑 화면으로 연결한다.

## 변경·종료·보존

- 자격 지정은 버전 ID가 아닌 계보 ID를 사용한다. 새 계획은 기존 최신 운영 버전 규칙을 따르고, 확정된 계획·배정은 당시 기준을 유지한다.
- 준비 미완성·Ready·Hold 자격은 새로 지정할 수 없다. 지정 후 Hold 또는 준비 미완성이 되면 지정은 유지하되 새 요청을 보류한다. 참조된 자격 삭제는 직접 지정과 모든 예외를 먼저 해제해야 한다. 상속이 사라진 예외도 삭제 참조에 포함한다.
- 새 제외는 현재 상위에서 적용받는 자격에만 만들 수 있고 팀 루트에는 만들 수 없다. 기존 Hold·준비 부족 상속을 제외하거나 복원할 수 있으나 복원 이후 새 요청은 기존 준비 검사를 통과해야 한다.
- 상위 지정이 없어져도 예외를 삭제하지 않는다. 같은 계보가 다시 상속되면 자동으로 제외한다. 조직 이동·자격 버전 교체에도 예외는 유지하고 새 경로에서 계산한다. 팀이 달라지는 잘못된 참조는 거부한다.
- 조직 설정·소속 변경은 기존 요청에 소급하지 않는다. 다른 소속으로 이동한 기존 요청은 기존 계획 권한 규칙에 따라 보존한다. 새 소속 기준을 적용하려면 다시 검토해 새 요청을 보낸다.
- 미완료 요청의 교체 종료는 새 요청 발송 검토에서 명시적으로 선택한다. 신규 요청과 이전 요청 종료·알림 정리는 한 트랜잭션이다. 새 요청을 보낼 수 없을 때에도 사유를 입력해 기존 요청만 종료할 수 있다.
- 종료된 요청은 미완료·기한 경과 집계에서 제외한다. 해당 요청의 미확정 초안은 읽기 전용이며 새 요청에 자동 복사하지 않는다. 확정 계획·배정·학습·평가·인증은 계속 보존한다.
- 업무22까지 만들어진 선택형 요청은 그대로 유지한다. 이전 요청을 새 고정 목록 방식으로 강제 변환하지 않는다.

`summary`는 `affectedOrganizations`, `membershipChangedOrganizations`, `sourceOnlyOrganizations`, `exceptionOnlyOrganizations`, `affectedMembers`를 반환한다. 저장 입력은 계약 버전·revision과 changes만 받는다. 새 예외는 다조직 변경을 모두 적용한 최종 상위 규칙으로 검증하며 입력 순서에 영향받지 않는다. 빈 배열도 명시하며 중복·직접/제외 중첩·사유 누락은422, 더 이상 상속받지 않는 새 제외는409다. 구형 계약은 인증·권한 확인 후 이전 영수증 조회 전에409 `REQUIREMENT_CONTRACT_CHANGED`로 거부한다. 미리보기 표시 필드를 그대로 제출하면 거부하며 서버가 최신 자료로 검토 결과를 다시 계산한다. 화면과 서버는 같은 순수 상속 계산 함수를 사용한다.

현황 구성원 상세 응답은 요청에 `closedOn`, `closeReason`을 선택적으로 반환한다. 종료 이력은 보존하고 미완료 집계에 포함하지 않는다.

## 업무26→27 상속 예외 이관

- 조직별 규칙에 `exclusions[{entityId,reason,updatedBy,updatedAt}]`를 추가한다. 명시 이관은 기존 규칙에 빈 배열만 더하고 업무 스키마·전체 revision·이관 감사 한 건만 변경한다. 기존 규칙 revision·수정 근거, 요청·계획·진행·인증·조직 원본은 유지한다.
- 새 요청의 `requirementSnapshot.ruleVersion`은2다. `rules`에는 경로 순서대로 조직 ID·규칙 revision·직접 계보·제외 계보를 보존한다. 제외 사유는 설정/감사에만 보존한다. 이전 요청은 변환하지 않는다.
- 내장 테스트 데이터 생성·전체 초기화는 업무27을 생성한다. 설정 파일 이전과 Excel은 계속 제공하지 않는다.
- 일반 서버 시작은 업무26을 거부한다. 서버 정상 종료 후 업무·조직·maintenance 세 파일과 업무26 호환 소스를 백업하고 해시/revision을 기록한다.
- 같은 절대 경로에서 `npm run data:migrate-requirement-exceptions -- --dry-run` 후 `npm run data:migrate-requirement-exceptions -- --apply --expected-revision=N --expected-sha256=STATE_SHA256 --organization-sha256=ORG_SHA256`으로 적용한다. 위 허용 변경 외 업무 필드와 조직 바이트를 대조한다.
- 충돌·잘못된 참조·파일 교체 실패는 원본을 보존한다. 재실행은 세 파일 모두 무변경이다. 같은 Node24·경로·포트로 재시작해 읽기 전용으로 확인한다. 복구는 서버를 종료하고 업무26 호환 소스와 세 백업을 함께 사용한다.

## 최초 도입 당시 저장·파일·명시 이관

- `State.organizationQualificationRequirements`는 조직별 `entityIds`, revision, 수정자/시각을 저장한다. 조직 스키마는4를 유지한다.
- 새 `PlanningRequest.mode`는 `organization_required`다. `requirementSnapshot`에 확인한 업무/조직 revision과 계보별 지정 조직 경로를 기록한다. 종료는 `closed`에 시각·처리자·사유·선택적 대체 요청 ID를 기록한다.
- 기본정보 JSON13은 조직 필요자격 지정을 설정으로 포함한다. 계획 요청·종료 이력은 개인 진행 데이터이므로 포함하지 않는다. 설정 보존 초기화는 지정을 남기고 요청·진행을 제거한다.
- JSON1~12는 원래 형식·체크섬·건수·참조 검사를 거쳐 새 지정을 빈 목록으로 변환한다. 구형 파일에 새 지정이 있으면 거부한다. 폐지된 조직 필수 설정은 다시 활성화하지 않는다.
- 일반 서버 시작에서는 자동 이관하지 않는다. 업무22의 기존 모든 업무 기록을 유지하고 빈 지정 목록·업무23·전체 revision 증가·이관 감사 한 건만 추가한다. 조직 원본은 바꾸지 않는다. 재실행은 무변경이다.

## 최초 도입 당시 운영 반영과 복구

1. 전체 검증 후 서버를 정상 종료하고 업무·조직·maintenance 세 파일과 업무22 호환 소스를 백업한다. SHA256·revision·실행 설정을 기록한다.
2. 같은 절대 데이터 경로에서 `npm run data:migrate-organization-needs -- --dry-run`으로 검사한다.
3. `npm run data:migrate-organization-needs -- --apply --expected-revision=N --expected-sha256=STATE_SHA256 --organization-sha256=ORG_SHA256`으로 적용한다.
4. 허용된 신규 필드·revision·감사 외 모든 업무 필드 및 조직 바이트를 대조한다. 재실행 시 세 파일의 해시가 같아야 한다.
5. 같은 Node24·경로·포트로 재시작하고 health와 실제 화면을 조회한다. 조회 전후 세 파일 해시를 확인한다.

해시/revision 충돌·유효하지 않은 참조·파일 교체 실패는 적용을 보류한다. 복구 시 서버 종료 후 업무22 호환 소스와 해당 의존성, 백업한 세 원본을 함께 복원한다. 새 지정은 이관 직후 비어 있으므로 관리자가 실제 필요 조직을 선택한 뒤 새 요청을 보낸다.
