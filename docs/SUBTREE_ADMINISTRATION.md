# 세부조직관리자 관리 범위

2026-10-28부터 세부조직관리자는 지정된 본인 조직과 모든 깊이의 하위 조직에 같은 기존 기능 권한을 가진다. 지정은 계속 사용자 한 명의 실제 소속 조직에 기록한다. 하위 조직에 관리자 지정 레코드를 복제하지 않는다.

## 허용과 제한

- 조직 설명·담당 업무 수정, 지정 관리자 조회, 조직 필요자격 지정·해제·상속 제외·복원, 인증 대상자 Hold·해제와 현황·차트·명세·구성원 요약 조회를 허용한다.
- 상위·형제·다른 팀은 대상에서 제외한다. 관리자 지정/해제, 계정 변경, 팀 자격·인증Set 편집, 계획 요청 발송과 개인 보유 인증 효력 변경 권한은 추가하지 않는다.
- Lv1에 직접 소속된 세부관리자의 조직 범위는 그 Lv1 전체지만 기능 권한은 세부관리자 그대로다. 중첩 지정된 관리자는 각자 자기 조직 아래만 관리한다. 운영자/팀 관리자 역할을 함께 가진 사용자는 기존 상위 역할 권한을 유지한다.
- 사용 중지 조직의 신규 필요자격 지정 등 기존 제한을 유지한다. 상속 예외는 관리 조직 안에서만 변경하며 상위 규칙은 읽기 전용 근거로 사용한다.

## 공개 응답과 저장 계약

- API 경로·요청 형식·저장 스키마는 유지하며 데이터 이관은 없다. `Workspace.management.editableOrganizationIds`, 조직 설정·필요자격 entries, 대상자 목록은 본인 조직 및 모든 하위 조직을 반환한다. 워크스페이스의 상위 조직 경로는 탐색을 위해 남기며 편집 가능한 ID에 넣지 않는다.
- 필요자격 미리보기 입력은 기존 `contractVersion:2`·업무/조직 revision·changes다. 출력 affected·summary는 권한 내 하위 조직의 적용/출처/예외 변경과 영향 인원을 포함한다. 권한 밖 조직이 섞이면403, 확인 이후 기준 변경은409이며 부분 저장하지 않는다.
- 대시보드의 기본 organizationId는 본인 조직, includeDescendants는 true다. 명시적 false는 선택한 조직의 직접 인원만 조회한다. options는 관리 가능한 조직만 제공하며 `directOnly:false`, `fullManager:false`를 반환한다. fullManager는 기존 전체 기능 권한 표시로 유지한다. Auditor 현황에도 같은 범위를 적용한다.
- 조직 ID 경로는 매 요청의 최신 조직 문서에서 계산한다. 저장 큐 안에서도 최신 사용자 지정·소속·조직 계층으로 확인하며 이전 요청 영수증 재사용 전에도 범위를 검사한다. 조직 이동·권한 회수·구성원 이동으로 범위를 벗어난 요청은403으로 거부한다. 기존 revision 충돌·입력 보존·백업·감사를 유지한다.

## 검증·배포

본인·자식·손자, 같은 이름의 조직, 상위·형제·타팀, 중첩 관리자, Lv1 관리자, 비활성 조직, 조직/구성원 이동과 권한 회수, 다조직/다인원 원자 거부를 검증한다. 홈과 현황의 하위 포함 기본값, 조직 선택·직접 소속 필터, 네 화면 폭·키보드 탐색을 확인한다.

임시 저장소에서 시험한 뒤 실제 업무·조직·관리 정보와 호환 소스를 백업하고 같은 경로·포트로 재시작한다. 배포에서는 업무 저장을 수행하지 않고 읽기 전용 확인 전후 세 파일 해시를 비교한다.
